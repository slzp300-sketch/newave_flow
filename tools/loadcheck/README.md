# 로컬 100명 동시 접속 검수

운영 앱을 건드리지 않고 현재 서버 코드의 HTTP API를 점검한다. 실행 때마다 **전용 합성 DB의 자료를 재생성**한다. 다른 검수나 개발 실행과 동시에 실행하지 않는다.

## 실행

필요: Node 24, JDK 21, PostgreSQL 18 실행 도구. DB 주소는 `127.0.0.1:55443/newave_loadcheck`, HTTP 주소는 `127.0.0.1:18083`으로 고정되어 있으며 임의 원격 주소 옵션은 없다.

저장소 루트 PowerShell:

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-21.0.10'
./tools/loadcheck/run.ps1 -PostgresBin './backend/.verification/postgresql18/pgsql/bin' -HeapMiB 512
./tools/loadcheck/run.ps1 -PostgresBin './backend/.verification/postgresql18/pgsql/bin' -HeapMiB 1024
```

PC별 JDK와 PostgreSQL 경로는 조정한다. 의존성은 기존 Gradle 캐시/공식 Maven 저장소를 사용한다. 이 도구는 main 애플리케이션 소스나 배포 JAR에 포함되지 않는다.

## 범위

- 합성 교사 100명, 50개 반(반마다 담임·부담임), 학생 500명, 과거 13주 TTS 1,300건과 답변 9,100건을 생성한다. 지난 분기 자료도 포함한 부하용 데이터이며 실제 이관 대상이나 운영 보관 정책을 뜻하지 않는다.
- 매번 임시 가상 암호를 생성하고 인증 토큰은 메모리에서만 보관한다. 실제 명단, 운영 비밀값, 계정 정보는 읽지 않는다.
- 워밍업 후 100명 동시 비밀번호 로그인, 각 사용자 8회 혼합 동작(홈·일정·TTS 참여/요일 체크·반 출석 저장/제출·행사 교사/학생 체크·연간 통계).
- 반별 두 교사가 동일한 출석 최종값을 함께 제출한다. 모든 사용자의 TTS/행사 최종값, 반 출석 수, 행사 학생 수를 조회하여 확인한다. 반 외부 쓰기 403, 비로그인 조회 401도 검사한다.
- 저장 결과 검증은 동일한 값을 반복 저장하는 경우를 확인한다. 서로 다른 충돌 값의 우선순위, 장시간 재접속, 모바일 화면 렌더링·네트워크 장애는 별도 검수다.

## 결과와 해석

`backend/.verification/loadcheck/run-<heap>-<timestamp>/`에 결과 JSON, 요청별 지연/상태, 메모리·DB 연결 대기 수, 서버 로그를 보관한다. Git 제외 대상이다.

`passed`는 요청 결과와 저장값 일치 성공이다. 응답 속도 기준 통과를 뜻하지 않는다. 요청 그룹별 p50/p95/p99/max를 따로 읽는다. 정상적으로 거절되어야 하는 401/403은 오류 수에 포함하지 않는다.

힙 512/1024 MiB와 JVM에 보이는 CPU 2개 조건이다. **1GB/2GB Railway 서비스의 실제 메모리 제한을 재현하지 않는다.** Windows 프로세스 최고 메모리에는 JVM 힙 이외의 메모리도 포함된다. 다른 프로세스·디스크 캐시·JIT의 영향이 있어 한 번의 차이를 메모리 증가 효과로 단정하지 않는다. 운영 네트워크·리눅스 컨테이너에서 같은 결과가 나온다는 보장도 없다.

현재 JPA 엔티티로 DB 구조를 생성한다. V001~V007 마이그레이션 자체 검수는 기존 PostgreSQL 전용 자동 검사에서 따로 수행한다. 기존 운영/백업 DB 폴더는 사용하지 않는다.
