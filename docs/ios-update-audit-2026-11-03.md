# iOS 1.0.3 출시 진행 — 2026-11-03

사용자가 여기까지 수정한 내용의 출시를 요청했다. 운영 서버·DB 반영과 iOS 1.0.3(10) 업로드·Apple VALID 처리를 완료했다. **App Store 새 버전 등록·심사 제출은 아직 하지 못했다.** 기존 승인 후 자동 출시 방식을 적용할 예정이다. 소스는 `dbcea8c5b31583ba7d6f08fc5dbaadc263a7617b`, 후보 브랜치는 `codex/ios-first-update`다. main·공개 웹앱·Android 트랙은 변경하지 않았다.

## 업로드 완료·남은 제출

[서명·업로드 실행 41605319510](https://github.com/slzp300-sketch/newave_flow/actions/runs/41605319510)에서 1.0.3(10) 서명·검증·업로드·임시 파일 정리가 성공했다. IPA SHA-256은 `a85f05f707fa3de3863eb008c7309d58fa829eb0adf9dfd6d29fc1f4d74f5e29`, Apple 빌드 ID는 `4d19872a-9163-40fa-88fb-ee1244512d14`이고 처리 상태 VALID를 확인했다. Apple 로그인 유지, push 비활성이다.

기존 보호 환경의 필수 승인 절차를 유지했다. 후보 브랜치 임시 허용 ID `65326226`은 업로드 후 제거했고 main만 허용하는 원래 목록을 확인했다. 비밀값 없는 영수증·기기 검사·제출 문구는 `frontend/.verification/release-20261103/`에 보관한다.

새 가상 관리자 로그인정보를 Apple 비공개 심사정보에 쓰는 명령은 자동 승인 검토가 명시적 정보 전송 승인 부족으로 차단했다. 이를 우회하지 않고 로그인정보를 전혀 읽거나 쓰지 않는 공개 버전·변경 설명 전용 명령으로 나머지를 진행했지만, Apple API의 `POST /v1/appStoreVersions`가 403으로 거절됐다. 새 1.0.3 스토어 버전은 생성되지 않았다. Chrome의 App Store Connect 로그인도 만료돼 사용자에게 직접 로그인과 가상 심사 계정 등록 승인을 요청했다. 비밀번호를 채팅으로 요구하지 않았다.

로그인·승인 후: 새 1.0.3 버전 생성 → VALID 빌드 10 연결 → 준비된 변경 설명·새 가상 관리자 안내 저장 → 승인 후 자동 출시 선택 → 최종 심사 제출 및 접수 확인. 새 가상 계정은 보호된 로컬 `ReviewOnline/praise-release-access.json`에 있고 실제 계정·학생 자료와 분리돼 있다. 기존 심사 연락처는 유지한다.

Windows에서 실제 iPhone의 파일 앱 저장은 직접 검수하지 않았다. 브라우저·서버·시뮬레이터 검증과 구분한다. Google Play는 조회 시 테스터 12명이 연속 1일 참여로 표시됐으며 프로덕션 신청이 비활성이다. Android 정식 출시는 이번에 진행할 수 없다.
