# 교회 제출용 주간 보고서 — 구성 계획안

작성일: 2026-10-29. 범위: 첨부 HWPX 분석과 입력·검토 화면 시안. 실제 앱 기능·DB·배포·외부 제출은 변경하지 않는다.

확정한 운영 방식: **예배 회차를 합산한 주일 통합 보고서 1건을 작성하고, 한글/PDF 파일로 교회에 전달한다.** 화면은 단계별 작성을 기본안으로 제안한다.

추가 설계 방향: **교사들이 제출한 데이터를 기반으로 주간 보고서 초안을 자동 작성한다.** 관리자는 출석을 재입력하지 않고 제출 현황·집계 오류·누락을 확인하며, 부서 공통 내용만 보완한다. 시안도 이 흐름으로 변경했다.

## 1. 원본에서 확인한 구성

검토한 파일은 ‘청소년부 주간보고서 (250622-25주차).hwpx’이다. 미리보기뿐 아니라 `Contents/section0.xml`의 94행·42열 병합 표 전체를 확인했다. 재적 내 반별 현황은 59개 반이다. 문서 안의 작성 메모는 원본 양식의 설명 자료로만 해석했다.

| 원본 영역 | 입력·출력해야 할 내용 |
|---|---|
| 제목·결재 | 부서명, 기준 주일·주차/보고서 표기, 담당자, 교육부총괄, 담임목사 |
| 예배 현황 | 찬양 담당, 기도 담당, 성경 본문, 설교 제목, 설교자 |
| 출석 현황 | 남·여·계, 학생 재적/결석/출석, 재적 외 새가족·금주 새인원·장기결석자 출석, 총출석, 총출석 중 등반수, 교사 재적/출석/결석 |
| 금주 새로 온 인원 | 번호, 이름, 성별, 학년, 학교, 주소, 연락처, 전도자. 원본은 11명 입력 공간 |
| 재적 내 반별 현황 | 학년·반, 담임, 재적 남/여/합계, 금주 출석 남/여/합계, 등반 남/여/합계·이름 |
| 재적 외 현황 | 장기결석자(새가족), 새가족, 금주 새로 온 인원, 각 성별 및 합계 |
| 헌금·부서 내용 | 금주 헌금, 부서 특이사항, 당월·차월 계획 |

### 집계에서 발견한 확인 사항

- 파일 안의 `Preview/PrvText.txt`는 중간에서 끝나며, 출석·결석 헤더 순서가 실제 본문과 다르다. 미리보기만 읽어 매핑하면 출석과 결석을 뒤집을 수 있다.
- 본문과 59개 반 합계를 대조하면 재적 남 143/여 134=277, 출석 남 107/여 102=209, 결석 68이다. 재적 외 출석은 새가족 8+금주 새인원 2+장기결석자 1=11이며 총출석 220과 맞는다.
- 상단 ‘총출석 중 등반수’는 0인데 반별 등반 합계는 1이고 특이사항에도 등반 기록이 있다. 실제 제출 때 자동으로 덮어쓰지 말고 불일치를 확인하도록 해야 한다.
- 원본의 ‘총출석 중 등반수’라는 헤더와 일부 작성 메모의 계산 설명은 중복 집계 가능성이 있다. 기본 제안은 등반을 출석자의 부분집합으로 표시하고 총출석에 다시 더하지 않는 것이다. 교회 기준 확인 후 확정한다.
- 양식 메모에는 10시와 12시 30분 예배를 따로 작성한다고 되어 있지만, 사용자가 현재 운영은 **한 보고서로 합산**한다고 확인했다. 이번 설계에서는 사용자 답변을 기준으로 예배 회차 선택을 없앤다.

## 2. 권장 구조: 출석 관리를 ‘주간 보고서’로 연결

관리자 ‘출석 관리’에 들어가면 해당 주일의 자동 집계 보고서 홈이 먼저 열린다. 기존 학생 출석 조회는 ‘자동 집계 확인’에서 계속 이용하고, 토요 교사회의 메뉴는 별도로 유지한다. 교사의 제출 시 보고서 초안의 해당 부분이 자동 갱신되며, 주차를 열 때도 최신 제출본을 다시 확인한다.

공통 상단에 **부서·기준 주일·주일 통합 보고서 표시·작성 상태**를 항상 표시한다. 다른 주차로 옮기면 해당 주일의 보고서를 연다. 예배별 보고서를 따로 만들지 않는다. 작은 목록형을 기본으로 하고 입력한 내용에 따라 행 높이가 늘어나도록 한다.

| 화면 | 주요 구성 | 다음 행동 |
|---|---|---|
| 주간 요약 | 반별 제출률, 교사 본인 출석 확인률, 자동 집계된 학생·교사 합계, 미제출·필수 항목 누락 | 미제출 또는 보완할 항목만 확인 |
| 자동 집계 확인 | 학생은 제출한 반별 최신 제출본과 명단, 교사는 본인이 기록한 주일 출석. 출처·제출 상태·집계 기준 표시 | 상세 확인. 보완이 필요하면 원본 기록으로 이동하거나 사유를 남겨 정정 |
| 새가족·등반 | 담당 교사가 제출한 금주 첫 방문 명단·새가족 과정·장기결석 후 출석·등반 내역을 자동 반영 | 누락·중복만 확인. 동일한 정보를 다시 입력하지 않음 |
| 공통 내용 보완 | 예배 순서·설교, 헌금, 부서 특이사항, 당월/차월 계획, 결재자 | 공통 항목만 입력·확인 → 검토 |
| 검토·파일 전달 | 원본 순서의 미리보기, 인원·누락 검증, 한글/PDF 파일 만들기, 전달 이력 | 파일 내려받기 → 교회에 직접 전달 → 완료 기록 |

시안은 **단계별 작성**과 **한 화면 작성** 두 안을 비교한다. 휴대폰에서는 단계별 작성이 우선 추천이다. 한 화면 안은 사무실에서 전체를 빠르게 검토할 때의 대안이다.

교사의 보고 대상 여부는 앱 권한만으로 정하지 않는다. 관리자·목사님도 교사 재적에 포함할지는 실제 명부 기준으로 정해야 한다.

### 현재 코드에서 재사용할 수 있는 범위와 보완점

- `AttendancePage`는 교사가 학생별 출석을 저장한 뒤 반 출석을 제출한다. `AttendanceService`는 출석 저장 시 `DailyReport`의 인원 수를 자동 계산한다. 따라서 학생 출석의 재입력 없이 보고서 집계로 연결할 기반이 있다.
- 현재 `DailyReport.totalStudents`는 저장된 출석 레코드 수다. 교회 보고서의 **재적수는 보고 주일의 대상 명부**에서 가져와야 하며, 일부 입력된 레코드 수를 재적으로 쓰면 안 된다.
- 현재 관리자 반별 요약에는 임시 저장 자료도 포함된다. 제출본만 집계하려면 상태를 구분해야 한다. 보고서가 없는 반도 명부에서 찾아 ‘미제출’로 표시해야 한다.
- 현재 저장 로직은 기존 제출 상태를 유지한 채 출석 수를 갱신할 수 있고, 과거 제출 당시의 학생별 자료를 별도 버전으로 보관하지 않는다. 단순히 `SUBMITTED`만 필터링해서는 ‘최신 제출본’을 보장하지 못한다. **수정 중 자료와 확정 제출본을 구분하는 버전 저장**이 필요하다.
- `ReportSummaryResponse`의 교사 제출률은 담당 반이 모두 제출되었는지를 나타낸다. 부서 보고서의 완성도는 **대상 반 수·개별 출석 누락**으로 판단하고, 교사 예배 출석은 별도 본인 기록으로 판단한다.
- TTS의 기본 ‘본예배’ 문구만으로 청소년부 예배 출석이라고 단정할 수 없다. 이름 문자열로 항목을 자동 추정하지 않고, 확정한 항목 식별자와 주차·날짜 규칙을 연결한다. 체크 여부만으로 ‘미확인’과 ‘결석’을 구분할 수 없다면 명시적 상태 입력을 보완한다.
- 반별 메모는 공통 특이사항 작성의 참고로 모을 수 있다. 개인 사정 등 내부 메모를 제출 파일에 모두 복사하지 않고, 담당자가 선택한 내용만 부서 특이사항에 반영한다.

## 4. 입력 및 집계 규칙 제안

1. 학생을 **재적 / 새가족 과정 / 금주 첫 방문 / 장기결석 후 출석** 가운데 그 주일의 주 분류 하나로 집계한다. 한 사람을 여러 구분에 중복으로 더하지 않는다.
2. **등반은 별도 사건/표시**로 관리한다. 재적 내 출석에 포함된 등반자를 총출석에 또 더하지 않는 안을 기본으로 둔다. 등반 후 명부 변경 시점도 기록한다.
3. 보고서에 지각 칸이 없으므로 **출석+지각을 보고서 출석으로 합산하는 안**을 제안한다. 현재 앱의 `presentCount`는 PRESENT만 세므로, 이 변환 규칙을 별도로 적용해야 한다. 교회 기준 확인 전 확정하지 않는다.
4. 미확인은 0이나 결석으로 바꾸지 않는다. 출석 대상 명부와 미확인 수를 함께 표시하고 제출 전 확인한다. 실제 0명은 0으로 출력한다.
5. 남+여=합계, 재적=출석+결석(미확인 해소 후), 반별 합계=부서 합계, 재적 내 출석+재적 외 구분 합계=총출석, 반별 등반 합계=상단 등반수를 검증한다. 성별 미확인도 별도로 표시한다.
6. 새 방문자의 학교·주소·연락처·전도자 등이 빠지면 해당 사람과 필드를 바로 찾도록 표시한다. 알 수 없는 정보를 임의로 만들지 않는다. 예외를 허용하려면 사유를 기록한다.
7. 제출본은 당시 명부·집계·본문을 함께 보관한다. 이후 교적부나 반 배정이 바뀌어도 과거 제출본은 바뀌지 않는다. 수정 제출은 새 버전으로 남긴다.
8. 예배를 한 보고서로 합산하되, 같은 사람이 여러 예배에 참석했을 때는 주일 출석 인원을 한 번만 세는 안을 제안한다. ‘한 보고서로 합산’ 답변만으로 중복 참석의 집계 정책까지 확정하지는 않는다. 현재 시안은 한 사람당 주일 출석 1건을 사용한다.
9. 반+보고 주일+제출 버전으로 원천 자료를 식별한다. 같은 반의 공동 담당 교사나 재전송 때문에 두 번 집계하지 않는다. 학생·교사는 식별자로 중복을 제거하며, 이름이 같다는 이유로 합치지 않는다.
10. 자동 집계는 최신 확정 제출본을 사용한다. 재수정 중이면 기존 제출본을 유지하면서 ‘수정 중’임을 표시하고, 재제출되면 초안에 반영한다. 관리자가 공통 내용에 작성한 문장은 자동 집계 갱신으로 덮어쓰지 않는다.
11. 파일 생성 시 사용한 원천 제출 버전과 명부·집계를 고정하여 보관한다. 이후 원천 자료가 바뀌면 새 초안에 변경 표시를 하고 파일을 다시 생성하게 한다. 이미 전달한 파일과 전달 이력은 자동으로 바뀌지 않는다.
12. 재적 외 구분·등반은 자유 메모에서 임의 추론하지 않고 담당자의 구조화된 제출 항목으로 받는다. 미제출·미확인·성별 누락이 남은 동안 최종 파일 생성을 제한하고 원인으로 바로 이동할 수 있게 한다.

## 5. 제출 흐름

**교사 입력·제출 → 부서 보고서 자동 집계 → 관리자 누락 확인·공통 내용 보완 → 원본 양식 미리보기 → 한글/PDF 생성·내려받기 → 교회에 직접 전달 → 전달 완료 기록**으로 구성한다.

- 사용자가 한글/PDF 파일 전달 방식을 확인했다. 마지막 화면에서 파일을 내려받고, 실제 전달을 마친 뒤 완료를 기록한다. 파일 생성만으로 전달 완료 상태가 되지 않는다.
- 한글 편집용 HWPX와 최종 확인·출력용 PDF를 제공하는 안으로 설계한다. 생성한 버전, 전달 완료 시각·기록자·간단한 전달 메모를 보관한다. 교회 측의 수신 확인과 담당자의 전달 완료 기록은 구분한다. 실제 파일 생성과 이력 저장은 이후 구현 범위다.
- 출력은 원본의 병합 표, 용지 설정, 글꼴·행 구조와 결재란을 보존한다. 새 방문자가 11명이나 반이 59개를 넘을 때도 잘라내지 않도록 행·쪽 확장을 설계한다.
- 원본 결재란은 파일에 유지한다. 앱 안의 승인 요청·반려 절차와 교회 사이트 업로드는 이번 계획 범위에 넣지 않는다. 추후 필요할 때 별도 설계한다.
- 교회 제출용 연락처 포함 출력은 권한을 가진 제출 담당자에게 제공한다. 일반 공유가 필요하면 연락처를 가린 사본을 선택할 수 있도록 한다.

## 6. 구현 순서

1. **집계 정의 확정:** 파일 전달·주일 통합 보고서는 확정. 지각 포함 기준, 등반·재적 외 및 여러 예배 참석의 중복 방지, 교사 재적 범위를 정한다.
2. **교사 원천 자료 보완:** 명부 성별, 교사 본인 출석 연결 기준, 교사·새가족 담당자 화면의 보고 구분·최초 방문·전도자·등반 이력.
3. **제출본·자동 집계 연결:** 반별 수정 중 자료와 제출 버전을 구분하고, 확정 제출본으로 성별·학년·반별·전체 합계를 자동 계산. 누락과 제출 현황을 관리자에게 표시.
4. **주간 보고서 저장/검증:** 부서+기준 주일을 보고서 단위로 두고 공통 내용, 원천 제출 버전, 출력본과 수정 이력을 보관.
5. **원본 출력과 전달 기록:** 실제 양식으로 HWPX/PDF 출력 검증, 파일 내려받기와 수동 전달 완료 기록 연결.

완료 기준은 원본 항목 누락 없음, 남녀/반별/전체 합계 일치, 미기록과 0 구분, 등반 중복 없음, 주차별 자료 섞임 없음, 합산 정책에 맞는 통합 출석, 과거 제출본 보존, 원본 양식과 실제 출력의 비교 확인이다.

## 7. 확정 사항과 남은 집계 선택

- 확정: 한글/PDF 파일로 전달한다. 예배는 한 보고서로 합산한다.
- 구현 전 집계 기준 확인: 지각의 출석 포함 여부, 등반자와 장기결석 후 출석자의 집계 구분, 여러 예배 참석자의 중복 제거 여부, 관리자·목사님을 포함한 교사 재적 범위.
- 교사 본인 출석의 원천 선택: TTS ‘본예배’가 보고서와 같은 대상 예배인지 확인한다. 일치하면 연결하고, 다르면 청소년부 예배 출석 체크를 별도로 받는다. 현재 시안은 본인 출석 연동 후의 제안 동작을 가상 자료로 보여준다.

시안은 가상 인물과 가상 숫자만 사용한다. 입력·검토·전달 완료 표시는 로컬 시뮬레이션이며 실제 학생 기록, 파일 생성·전달, 교회 시스템 전송은 발생하지 않는다.

## 8. 시안 확인 범위

- 현재 시안은 관리자 직접 출석 입력을 읽기 중심의 자동 집계 확인으로 변경했다. 교사·새가족 담당자가 구조화한 자료를 제출하는 후속 기능까지 연결됐을 때의 제안 화면이며, 현재 운영 앱에 이미 모두 구현되어 있다는 뜻은 아니다.
- 가상 자료의 초기 상태는 반 출석 4/5개 반, 교사 본인 출석 3/4명 확인이다. ‘가상 교사 제출 도착’으로 새 제출이 들어오는 상황을 체험하도록 구성했다. 이 단계에서 실제 교사에게 제출 요청이나 알림을 보내지 않는다.

- 단계별 작성과 한 화면 작성의 두 대안을 준비했다. 두 안 모두 주일 통합 보고서와 한글/PDF 파일 전달 흐름을 반영했다.
- 두 작성 방식에서 가상 제출 도착 → 반 출석 4/5→5/5개 반, 교사 본인 출석 3/4→4/4명 확인, 학생 출석 6→7명, 교사 출석 2→3명, 확인 항목 2→0개로 자동 갱신되는 것을 확인했다.
- 집계와 새가족 확인 화면에 관리자용 재입력 칸이 없고, 공통 내용에 작성한 문장이 새 제출 반영 후에도 유지되는 것을 확인했다.
- 원본 항목의 미리보기에서 학생/교사 남녀 합계, 재적 외 세부 집계, 반별 남녀·등반자 이름, 새 방문자 정보, 헌금·특이사항·월별 계획·결재란을 확인했다. 이는 항목 구조 시안이며 원본 HWPX와 동일한 출력 파일은 아직 생성하지 않는다.
- 주차별 제출 현황·공통 입력·완료 상태 보존, 미제출 상태의 파일 만들기 제한, 파일 준비 및 전달 완료 기록을 확인했다. 예배 회차 선택은 제공하지 않는다.
- 320px에서 새가족 확인·한 화면 집계, 375px에서 검토·보고서 미리보기의 가로 넘침이 없고, 브라우저 오류 로그는 0건이다. 시안 스크립트 구문 검사를 통과했다.
- 실제 학생·교사 자료 변경, 앱 코드 구현, 배포, 결재 요청, 파일 전달·외부 제출은 하지 않았다.
