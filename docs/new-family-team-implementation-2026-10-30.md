# 새가족팀 관리 구현 — 2026-10-30

## 범위와 상태

첫 방문 기록·출결 → 등록 결정 → 과정 참여 기록 → 새가족팀 판단 → 관리자 반 배정 → 담당 교사 출결과 주간보고서 연결을 구현했다. 로컬 가상 자료로 검증했으며 배포, 운영 DB 변경, push, PR은 하지 않았다.

기존 계획의 ‘추후 새가족 기능’은 이 구현으로 대체한다. 운영 적용 시 V015/V016 다음 V017 DB 변경과 앱 반영이 필요하지만 이번 작업에서는 실행하지 않는다.

## 확정한 집계 기준

- 첫 방문 주에는 등록 여부와 관계없이 금주 새 인원(FIRST)으로 한 번만 집계한다.
- 첫 방문 이후 등록을 결정하지 않은 재방문은 등록 미정 재방문(FOLLOWUP)으로 별도 기록한다. 총 출석에는 포함하고 새 인원·새가족에는 중복 포함하지 않는다. 원본 양식에는 별도 칸을 추가하지 않고 특이사항에 인원을 표시한다.
- 등록 결정일부터 새가족(FAMILY)으로 집계한다. 첫 방문 주 규칙이 우선한다.
- 출결과 과정 참여일 네 개를 따로 기록한다. 4회 참여가 자동 등반 조건은 아니다. 팀이 계속 참여 또는 등반 가능 판단과 사유를 남긴다.
- 팀이 배정을 요청하면 관리자/목사님이 같은 학년의 반, 적용일, 인계 메모를 확정한다. 적용일 전에는 팀, 적용일부터는 담당 반이 출결을 맡는다. 학생 ID를 그대로 유지한다.
- 등반자 표시는 반 적용일 이후 첫 주일 보고에 한 번 반영한다.
- 일반 반의 드문 첫 방문 참여는 참고 기록을 팀의 실제 학생에 명시적으로 연결한다. 보고서는 팀 출결 원본만 집계하여 이중 계수를 막는다.
- 입력 저장과 제출을 구분한다. 미확인 출결·미연결 참고 기록은 제출을 막고, 제출 후 변경은 보고서 재제출 안내와 최종 출력 차단으로 연결한다. 이미 만든 출력본은 당시 자료를 보존한다.

## 화면과 권한

`/new-family`에 이번 주, 학생·과정, 등반·배정 탭을 제공한다. 관리자/목사님에게는 팀원 관리도 제공한다.

- 관리자/목사님: 팀원 지정, 모든 팀 업무, 최종 반 배정.
- 지정된 새가족팀 교사/임원: 학생 등록, 출결 제출, 과정·판단 기록, 배정 요청.
- 일반 교사: 자신의 배정 반만 출결 처리. 적용일 이후 학생 상세에서 인계 내용을 확인한다.
- 메뉴 숨김과 별개로 서버에서 현재 계정의 담당 여부를 매번 확인한다. 담당 해제는 즉시 접근에 반영한다.

이름·학년·첫 방문일을 중심으로 등록하며, 학교·성별·연락처 등은 선택 입력한다. 성별 등 보고서 필수 정보가 빠지면 관리자의 누락 보완 안내에 표시된다. 동명이인 등록에는 명시적인 확인이 필요하다.

## 저장 구조와 변경 충돌

`new_family_members`는 기존 `students`와 1:1로 연결한다. 미배정 학생은 반이 비어 있으며, 배정 시 `class_effective_date`가 교사 명단 공개와 출결 시작을 제어한다. 별도 테이블에 날짜별 출결, 제출 스냅샷, 반 참고 기록 연결을 저장한다.

학생 수정에는 버전, 출결 저장·제출에는 원본 해시를 사용한다. 팀 업무 변경은 레지스트리 잠금으로 직렬화한다. 다른 담당자의 변경을 덮어쓰려 하면 409와 최신 자료 확인 안내를 반환한다. 팀 판단의 사유·담당자·시각은 현재 판단에 보관하며, 모든 과거 판단의 별도 감사 로그는 이번 범위에 포함하지 않았다.

## 반 배정 확정부터 교사 제출까지 추가 확인

사용자 요청에 따라 5196 미리보기에서 가상서아(학생 ID 10)를 가상 중1반/가상담임에게 2026-11-01 적용으로 확정했다. 이전 주일인 2026-10-25의 교사 명단은 기존 학생 1명으로 유지되고, 보고서에서 서아는 새가족 1명으로 남는다.

아직 오지 않은 적용일을 검증하기 위해 같은 가상 자료를 별도 H2 메모리 DB로 복사했다. 검증용 실행기와 프런트 진입점에서만 날짜를 2026-11-01로 설정했으며, PC 시간과 운영 앱의 날짜 처리는 바꾸지 않았다. 실제 서비스·컨트롤러·React 화면을 그대로 사용한다. 검증 실행기와 날짜 대체 코드는 `.verification` 안에만 있다.

- 담임 출석 화면에서 기존 학생 + 가상서아 2명이 표시되었고, 교사 본인 예배 출석과 반 출석·주간자료 제출을 UI에서 완료했다.
- 서아는 학생 ID 10을 유지하고 REGULAR/PRESENT/등반으로 한 번만 집계된다. 그 주의 새가족팀 출결 명단에서 빠지고, 담임에게 인계 메모가 전달된다.
- 전체 가상 보고서는 재적 출석 8명 + 등록 미정 재방문 2명 = 총 출석 10명이다. 등반자는 서아와 앞서 배정한 은별 2명이며, 새 인원·새가족 출석에는 중복 포함하지 않는다. 보완 항목은 0개다.
- HWPX 합계 셀과 PDF 텍스트에서 인원 및 서아 이름 1회 표시를 확인했다. 10월 25일 보고서는 원래 새가족 분류를 유지한다.
- 날짜 경계 회귀검사를 추가했다. 교사가 미래 날짜를 직접 지정해 조회해도 실제 적용일 전에는 미리 학생 정보를 볼 수 없도록 명단 조회 조건을 보완했다.
- 새가족 6개, 출석·이력 4개, 보안 회귀 10개로 총 20개 백엔드 테스트 통과.
