# 첫 방문·새가족 출결 책임 정리 — 2026-10-30

> 후속 상태: 아래 내용은 전용 팀 기능 도입 전 단계의 기록이다. 이후 사용자 승인을 받아 새가족팀 전용 기능과 자동 집계를 구현했다. 현재 기준과 검증은 [새가족팀 관리 구현](new-family-team-implementation-2026-10-30.md)을 따른다. 등록 미정 재방문은 별도 기록하고 총 출석에 포함한다.

## 사용자에게 확인한 기준
- 교회에 처음 온 주에는 모두 금주 새 인원이다.
- 예배 후 등록을 결정하면 새가족에 배정되어 계수된다. 첫 방문 주에는 금주 새 인원으로 한 번 집계한다.
- 새가족팀이 첫 방문 학생과 새가족 모두를 관리·감독하고 출결을 보고한다.
- 새가족은 4주 과정을 거쳐 등반한 뒤 일반 반에 배정된다.
- 친구를 따라 일반 반에 하루 참여하는 것은 드문 예외이다. 이 경우에도 새가족팀이 출결 보고를 책임진다.
- 새가족 전용 기능은 추후 개발하며, 이번 작업에서 자동 등록·4주 과정·등반 처리를 만들지 않는다.

## 현재 반영
- 일반 교사 화면은 배정 학생의 출석과 선택 특이사항만 기본으로 제공한다.
- 교사의 새가족·금주 새 인원·등반 분류 선택을 제거했다. 서버에서도 관리자가 확인한 기존 분류를 보존하며 교사가 변경하지 못하도록 한다.
- 예외 상황은 접힌 영역의 '친구와 우리 반에 참여한 첫 방문 학생'에 참고 기록을 남긴다. 이름과 함께 온 친구가 중심이며, 알고 있는 추가 정보만 선택 입력한다.
- 참고 기록은 새가족팀 확인 대기 상태로 저장한다. 학생 명단이나 반 배정을 생성하지 않고 다음 주로 자동 복사하지 않는다.
- 확인 대기 기록은 보고서 새 인원·전체 출석 합계에서 제외하고, 누락 안내를 표시하여 미확인 상태의 최종 다운로드를 막는다.
- 새가족 전용 기능 도입 전에는 관리자가 팀에 출결·중복을 확인한 후 기존 반 자료 보완 화면에서 확인 완료로 표시한다. 보완 사유는 기존 방식으로 남긴다.
- 확인 후 금주 새 인원에 한 번만 집계하며, 새가족·재적에 중복 계수하지 않는다.
- 팀에서 확인한 기록은 일반 교사에게 읽기 전용이다. 수정·삭제는 관리자 보완에서 처리하며, 오래된 교사 입력으로 확정된 정보가 덮어써지거나 삭제되지 않도록 보존한다.
- 이전 제출/출력 자료는 유지한다. 새 확인 상태가 없는 과거 JSON은 기존 집계 의미를 보존한다. 신규 교사 입력은 누락·위조된 확인 상태와 관계없이 확인 대기로 생성한다.

## 추후 새가족 기능의 연결 기준
- 새가족팀의 전용 명단·출결 제출이 공식 원본이 되어야 한다. 일반 반의 예외 참여 기록은 이 원본에 연결하여 중복 보고를 방지한다.
- 첫 방문일, 등록 결정일, 4주 과정 이력, 등반일과 반 배정일을 구분하고 과거 보고서를 소급 변경하지 않는다.
- 현재 관리자의 확인 작업은 전용 팀 기능 도입 전의 보완 경로이다.

배포·운영 자료 변경·PR·push는 하지 않는다.

## 검증 결과
- 프런트엔드 191개 테스트 통과 및 최종 로컬 빌드 성공.
- 백엔드 전체 build 성공. 첫 방문 확인 대기/확정 후 집계, 일반 교사의 분류 위조 차단, 확정 기록의 변경·삭제·오래된 입력 보호, 다음 주 자동 이월 방지, 기존 JSON 호환성을 검증했다.
- 원본 HWPX 셀 값에서 확인 전 새 인원 0명/전체 1명, 확인 후 새 인원 1명/새가족 0명/재적 1명/전체 2명으로 중복 없는 집계를 검증했다.
- 375px 실제 가상 서버 화면에서 첫 방문 이름·함께 온 친구 제출, 관리자 확인 대기 안내와 다운로드 차단, 팀 확인 완료 보완 후 해당 누락 안내 해제를 확인했다.
- 일반 교사 화면의 분류 선택 0개, 화면 가로 넘침 없음.
- 운영 배포 및 운영 데이터 변경 없음. 새가족 전용 명단·4주 과정 기능은 추후 개발 범위이다.
