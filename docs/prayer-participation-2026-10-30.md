# 기도모임 관리 — 투표 기준 통계 (2026-10-30)

## 2026-11-02 — 개인 투표 완료 화면 개선 (로컬, 미배포)

- 기도모임과 교사회의에 공통 `VoteReceipt`를 적용했다. ‘내 투표’와 ‘투표 완료’를 구분하고, 선택한 요일/참석 여부를 큰 글씨·아이콘·상태 색상으로 표시한다.
- 참석은 초록색, 불참은 붉은색이며 텍스트도 함께 표시한다. 기도모임은 선택한 날짜와 온라인 모임을, 교사회의는 해당 토요일 날짜를 명시한다.
- 불참 사유, 마이크 가능 여부와 사유, 마이크 순서, 마지막 저장 시각은 보조 정보로 정리했다. 사유의 줄바꿈을 보존하며 ‘투표 수정’ 버튼으로 다시 편집할 수 있다.
- 저장 성공 응답을 해당 주의 조회 캐시에 반영한다. 교사회의 완료 카드는 편집 중 임시값 대신 서버에서 받은 기록을 표시한다. 저장/재조회 중에는 중복 수정을 막는다. API·서버·DB 변경은 없다.
- 가상 자료로 화→목 변경, 수정 취소, 미응답 주 전환, 교사회의 첫 제출·새로고침·불참 수정, 저장 실패 후 기존 참석 보존을 확인했다. 375px 및 320px/120% 글씨에서 가로 넘침 없이 요일·날짜·긴 사유가 표시된다.
- 프런트엔드 기존 테스트 233개 통과. native 모드 로컬 빌드 성공(기존 번들 크기 및 혼합 import 경고 유지).
- 실제 페이지를 사용하는 가상 미리보기: `http://127.0.0.1:5198/.verification/vote-receipt-app.html` 및 `?page=meeting`. `.verification`의 Axios 어댑터가 모든 요청을 가상 자료로 처리하며 실제 API로 전달하지 않는다.
- 배포, 스토어 심사 제출, 운영 투표 수정은 진행하지 않았다. 앞서 진행한 앱 새 버전 안내 관련 미커밋 수정은 보존했다.

## 반영 내용

- 사용자 확인: 실제 출석을 새로 받지 않고 기존 `TUE` / `THU` / `ABSENT` 투표로 집계한다.
- 관리자 화면을 작은 목록으로 통일했다. 불참 / 미응답 / 참석 / 전체 필터, 이름·학년 검색, 불참 사유를 제공한다.
- 주간 참석률 = (화 참석 + 목 참석) / (화 참석 + 목 참석 + 불참). 미응답은 분모와 불참에서 제외한다.
- 응답이 없는 주는 `—`로 표시한다. 최근 8주 추이와 합산 참석률을 제공하며, 합산은 응답 수에 따른 가중 집계다.
- 추이의 주를 누르면 해당 주 명단을 조회한다. 명단 필터는 전체 통계를 바꾸지 않는다.
- 교사·관리자 화면의 필사 제출 항목과 안내를 제거했다. 기존 투표 입력과 TTS 연결은 유지한다.
- 기존 앱의 공통 버튼, 펼침 메뉴, 색상과 글씨를 사용한다. 작은 화면의 큰 글씨 모드에서는 요약 수치를 2열로 배치한다.

## 데이터와 호환성

- 새 조회 API: `GET /api/prayer-votes/participation?week=YYYY-MM-DD` (ADMIN / PASTOR / EXECUTIVE).
- 과거 응답 수는 저장된 투표 기준이다. 현재 이용 정지·비활성 상태가 과거 응답을 지우지 않는다.
- 미응답 후보는 현재 활성·이용 가능한 교사/임원/관리자이며, 해당 주 이후 가입자는 제외한다. 과거 재직 명단 스냅샷은 없으므로 화면에 ‘현재 교사 명단·가입일 기준’을 명시했다.
- 여러 반에 배정된 교사의 투표는 한 번만 집계한다. 개인 학년이 없으면 주담임 반부터 학년을 확인한다.
- 기존 필사 데이터는 삭제하지 않는다. 폐지된 PATCH `/prayer-votes/{id}/scripture`는 410 응답으로 변경을 막는다. 기존 조회 응답은 호환성을 위해 유지했다.
- 이 변경 자체에는 DB 마이그레이션이 없다. 추후 배포 시 새 통계 API와 화면을 함께 반영해야 한다. 다른 미배포 변경의 마이그레이션과는 별개다.

## 검증

- 프런트엔드 테스트 198개 통과: 참석률, 무응답 주, 가중 합산, 필터, 연말·주차 이동 포함.
- 백엔드 관련 테스트 14개 통과: `PrayerParticipationHttpTest` 5개, `AdminParticipationHttpTest` 3개, `TtsWeekStatsTest` 6개.
- 실제 HTTP 경로에서 교사가 화 참석을 불참으로 수정하면 관리자 요약·사유·주간 추이가 함께 변경됨을 확인했다.
- 접근 권한, 미래 주 차단, 과거 가입일, 다중 반 중복 방지, 폐지된 필사 API의 기록 보존을 확인했다.
- 프런트엔드 빌드 성공. 기존 번들 크기/혼합 import 경고만 남아 있다.
- 실제 React 화면에 가상 응답을 연결한 브라우저 확인: 375px, 320px + 120% 글씨, 이름·학년 검색, 미응답 분리, 빈 주 선택, 8주 추이, 조회 오류 안내, 교사 화면 필사 제거. 정상 화면 콘솔 오류 없음.
- 가상 화면: `http://127.0.0.1:5197/.verification/prayer-participation-app.html`.
- 브라우저 시연 자료는 가상 데이터이며 운영 자료를 조회·수정하지 않았다. 배포·푸시·검토 요청 없음.

## 후속 반영: 기도모임·교사회의 학년별 명단

- 두 화면 모두 기본값을 전체 교사로 두고 학년별로 묶었다. 학년 내에서는 이름순으로 표시한다.
- 접힌 행에는 이름과 참석 / 불참 / 미응답만 표시한다. 이름 또는 행을 누르면 상세가 펼쳐진다.
- 기도모임 상세는 응답 요일, 불참·마이크 사유, 수정 일시를 표시한다. 교사회의 상세는 불참 사유, 회의록 확인 상태, 수정 일시를 표시한다.
- 교사회의의 보기 방식 선택을 없애고 목록으로 통일했으며, 기존 미제출 표기를 미응답으로 맞췄다. 저장된 출결 값과 회의록 확인 자료는 변경하지 않았다.
- 공통 `GradeAttendanceList`로 두 화면의 행 크기와 펼침 디자인을 맞췄다. 주차가 바뀌면 펼친 상세는 닫힌다. 학년·상태·이름 필터는 전체 요약을 바꾸지 않는다.
- 프런트엔드 테스트 198개와 별도 로컬 빌드 통과. 가상 자료로 두 페이지의 이름 클릭, 불참 사유, 참석 요일, 회의록 확인, 미응답 구분, 필터, 주차 변경을 확인했다. 375px 및 320px 큰 글씨 모드에서도 확인했다.
- 교사회의 미리보기: `http://127.0.0.1:5197/.verification/prayer-participation-app.html?page=meeting`.
- 배포하지 않았으며 이번 후속 수정에는 서버·DB 변경이 없다.
- 추가 요청으로 학년 영역을 2열로 배치했다: 중1·중2 / 중3·고1 / 고2·고3. 작은 화면에서도 두 칸을 유지하며 긴 이름·상세는 줄바꿈한다. 두 화면에서 상세 열기와 320px 큰 글씨 모드의 가로 넘침 없음, 로컬 빌드 성공을 확인했다.
- 주간 참석률 카드를 축소했다. 제목 옆에 참석률을 두고 수치 영역의 여백·글씨를 줄였으며, 8주 추이는 얇은 펼침 줄로 정리했다. 일반 미리보기에서 요약 카드 높이 157px, 접힌 추이 46px로 확인했다. 320px 큰 글씨 모드, 추이 펼침, 로컬 빌드 확인 완료. 집계 기준이나 데이터는 변경하지 않았고 배포하지 않았다.
