# Apple 로그인 개인정보 안내 반영 기록

갱신: 2026-10-16. Apple 로그인 신규 가입을 비밀번호 없이 진행하고 검증된 Apple 이메일을 보존하는 구현에 맞춰 `frontend/src/content/privacyPolicy.js`에 안내를 반영했다. 공개 방침 소스·생성 HTML 반영과 실제 공개 URL 배포, 운영 서버의 Apple 로그인·알림 활성화를 확인했다. Apple 로그인 지원 TestFlight 1.0.0(2)는 서명·업로드·Apple 처리 및 기존 운영자 iPhone 검수 그룹 배포까지 완료했다. 사용자 보고로 실제 iPhone의 Apple 인증 후 가입/기존 회원 선택 화면 표시와 본인의 기존 앱 계정 연결·로그아웃·Apple 재로그인 성공을 확인했다. 신규 가입·이메일 가리기·인증 취소·실제 동의 철회 알림·계정 삭제는 별도 미검수다. 상세 배포 증거와 이후 검수 결과는 해당 배포 작업로그에서 별도로 확인한다.

## 공개 방침에 반영한 처리

### 가입·기존 계정 연결

- Apple 계정의 개발자별 식별자를 인증 및 계정 연결에 사용한다.
- 신규 가입 이메일은 서버가 Apple 신원 확인 토큰의 서명과 이메일 확인 결과를 검증한 값만 사용한다. 이용자가 ‘나의 이메일 가리기’를 선택하면 Apple이 제공한 중계 주소를 그대로 보존한다. 클라이언트가 임의의 이메일로 교체하거나 다른 이메일을 추가로 요구하지 않는다. 검증된 이메일이 없으면 신규 가입을 완료하지 않는다.
- Apple이 최초 승인 때 제공한 이름은 가입 화면의 제안값이다. 사용자가 확인·수정한 이름과 선택 전화번호를 계정에 저장한다. Apple이 이름을 다시 주지 않으면 직접 입력한다. 이름은 계정 소유권을 판단하거나 기존 계정을 합치는 근거로 쓰지 않는다.
- 신규 Apple 가입에는 앱 비밀번호를 요구하거나 임의로 생성하지 않는다. 관리자의 교사 가입 승인 절차는 그대로 적용한다.
- 기존 앱 계정에 연결할 때는 현재 비밀번호로 확인한다. 기존 이름·이메일·업무 기록은 자동 변경하지 않으며 이메일 일치만으로 계정을 병합하지 않는다.
- Apple 프로필 사진과 연락처 목록을 가져오지 않으며 학생·보호자 자료나 공동 업무 자료를 Apple 인증 요청에 보내지 않는다.

### 인증·보관·철회·삭제

- 인증 코드와 신원 확인 토큰은 검증 중 일시 처리한다. 연결 관리·철회를 위한 갱신 토큰은 서버에서 암호화해 보관한다. 원문 토큰과 인증 응답은 운영 로그에 남기지 않는다.
- 인증 흐름은 300초 유효하며 상태·nonce 해시·PKCE 확인값·만료시각 및 신규 가입에 사용할 검증된 이메일을 보관한다. 만료 흐름 정리는 60초 간격으로 실행된다. ‘5분이 되는 순간 모든 사본이 완전 삭제된다’고 표현하지 않는다.
- 기기의 Apple 인증 응답, 가입 초안과 삭제 재인증 증명은 메모리에서만 처리한다. 앱을 재시작하면 새 인증이 필요하며, 이를 Keychain에 영구 보관하거나 기기 간 동기화하지 않는다.
- 앱 비밀번호 없이 Apple로 가입한 계정은 삭제 요청 때 Apple 시스템 인증을 새로 진행한다. 서버는 해당 계정·세션에 묶인 일회용 증명을 확인하고 Apple 권한을 철회한 뒤 삭제 요청을 접수한다. 기존 비밀번호 계정의 재확인 경로는 유지한다.
- 삭제 요청에서 권한을 철회한 뒤 갱신 토큰을 제거한다. 식별자 등 연결 자료는 실제 앱 계정 삭제 시 제거한다. 신규 가입 후 저장한 이름·이메일은 교사 계정의 보관 기준을 따른다.
- Apple 알림은 앱 범위의 식별자 해시·알림 ID 해시·본문 해시·수신/철회/처리 시각을 저장하고 원문은 별도로 보관하지 않는다. 접수 해시는 수신 후 30일, 계정 연결이 없는 상태 기록은 마지막 갱신 후 30일을 기준으로 매시간 정리한다. 계정에 연결된 상태 기록은 해당 계정 관리 기간 동안 보관하며, 실제 계정 삭제 시 연결 상태·접수 해시도 제거한다.
- Apple 연결 해제·Apple 계정 삭제 알림에 따라 로그인 세션을 종료할 수 있다. 이 알림을 앱 계정·공동 업무 자료의 즉시 삭제 요청과 동일하게 처리하지 않는다.

## 외부 처리·국외 처리의 표현 범위

공개 방침에는 Apple 인증의 자체 처리 안내와 공식 개인정보 문의 경로를 연결했다. Apple의 일반 정책은 수집한 개인정보를 일반적으로 미국 Apple Inc.에 저장하고 담당 법인이 거주지·서비스에 따라 달라질 수 있다고 설명한다. 이를 Apple 인증의 모든 처리 국가가 미국 한 곳이라는 보증으로 사용하지 않았다.

Apple Korea 또는 Apple Services Pte. Ltd.의 자체 국외 이전 표에 적힌 수령자·위탁 근거를 우리 앱의 법적 근거로 복사하지 않았다. 이번 문구 반영만으로 우리 앱의 모든 국외 이전 법적 요건이나 Apple 인증의 전체 처리 국가가 확인됐다고 주장하지 않는다. Apple 인증을 선택하지 않을 때의 일반 이메일 가입·로그인, Apple 계정 설정에서의 연결 해제, 앱 계정 자료 삭제 요청을 구분해 안내한다. 기존 학생·보호자 자료의 별도 동의·국외 이전 절차는 그대로 유지한다.

공식 근거(2026-10-16 확인):

- [Apple로 로그인 및 개인정보 보호](https://www.apple.com/kr/legal/privacy/data/ko/sign-in-with-apple/): 개발자별 식별자, 최초 이름·이메일 제공, 이메일 가리기, 연결 해제와 개발자 보관 자료의 구분, Apple 자체 보관 기준.
- [Apple 개인정보 처리방침](https://www.apple.com/kr/legal/privacy/kr/): 국가·서비스에 따른 담당 법인, 일반적인 미국 보관 및 자체 국외 처리 안내.
- [Apple 개인정보 문의](https://www.apple.com/kr/privacy/contact/): 확인된 공식 연락 경로. 확인하지 않은 개인정보 담당 이메일이나 처리 국가 목록을 만들지 않는다.

## 반영·최종 검증 기준

1. 방침 시행일은 `2026-10-16`이며 9절에 변경 내용을 안내한다. 앱의 `PrivacyDocument`와 공개 HTML은 같은 원본을 사용한다. `node frontend/tools/build-privacy-policy.mjs`로 HTML을 재생성한다.
2. 최종 코드에서 검증된 이메일·중계 주소 보존, 이름 제안·수정, 비밀번호 없는 신규 가입, 기존 계정 연결, Apple 재인증 삭제의 동작이 위 문구와 일치하는지 확인한다.
3. Name·Email Address·User ID 및 상태 처리의 Other Data Types에 Apple 경로를 포함해 App Privacy를 대조한다. 목적은 App Functionality, 사용자 연결은 예, 추적은 아니오로 유지할 수 있는지 실제 최종 구성을 기준으로 확인한다. 해시를 저장한다는 이유만으로 비연결 데이터라고 답하지 않는다.
4. 공개 정책 반영, 서버 설정, Apple 알림 주소, 서명된 앱과 심사 노트의 기능 상태를 맞춘다. 이 문서나 자동 검사만으로 실제 Apple 승인·알림 전달·최종 iPhone 검수가 끝났다고 기록하지 않는다.

코드 근거: `AppleAuthService`, `AppleClient`, `AppleTransport`, `AppleNotificationService`, `AppleNotificationStateStore`, `AppleAccount`, `AppleAuthFlow`, `NewaveAppleSignInPlugin`, `appleFlow.js` 및 계정 삭제 처리. 실제 Apple 인증 정보·운영 계정 자료는 문서 검토를 위해 읽지 않았다.
