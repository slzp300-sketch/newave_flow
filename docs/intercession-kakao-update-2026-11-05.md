## 기도제목 접수 화면 개선

- 접수 목록은 15초마다 갱신하며 새 요청 배지와 함께 최신 요청을 반영한다. 상세 화면의 뒤로가기는 들어왔던 접수·공유·내 기도제목 목록으로 돌아간다.

## 공유 결정·기도 상태 (후속 변경)

- 최종 피드백: 접수 시점에 기도 종료까지 묻는 흐름이 어색하여 단계별 행동으로 분리했다. 새 요청은 원문을 읽고 `전체에 공유 / 팀에서만 기도` 중 하나를 누르면 처리되고 `기도 중` 목록으로 이동한다. 팀만 전달된 요청은 `확인하고 기도하기`만 표시한다.
- 기도 중 요청은 `기도 마치기`, 마친 요청은 `다시 기도하기`만 주요 행동으로 보여주고 처리 후 해당 목록으로 이동한다. 두 가지 상태 선택과 공통 저장 버튼을 제거했다. 공유본은 기존 정리본 또는 원문으로 채우며, 내용·공유 범위 수정은 별도로 펼쳐서 저장한다.
- 팀만 전달된 요청은 전체 공유할 수 없고, 익명 동의도 완화할 수 없다. 기존 팀 관리 권한·동시 수정 검사를 새 결정 API에도 적용했다.
- 팀만 보는 요청도 기도를 마치거나 다시 이어갈 수 있다. 공유를 중단해도 완료 상태는 보존하며 완료 상태를 바꿔도 공유 범위가 임의로 바뀌지 않는다.
- 공개된 기도 마침 요청은 전체 공유의 `마친 기도` 목록에 남고, 모임 자료의 진행 중 기도제목에서는 제외된다. 준비한 공유본도 변경됨으로 처리해 끝난 요청이 다시 표시되지 않게 한다. 공유본을 다시 만들면 마친 요청을 자동으로 빼고 남은 요청만 준비한다. 다시 계속 기도로 변경하면 모임 자료에 다시 선택할 수 있다.
- V024는 `prayer_completed` 열을 추가하고 기존 ANSWERED만 완료 상태로 옮긴다. 기존 원문·공유본·권한·상태·수정 이력 값은 보존한다. 구버전 API의 공유 내용 수정으로 완료 상태가 풀리지 않는다.
- 검증: 프런트 241개 성공 및 최종 빌드 통과. 서버 전체 최종 build 성공, 중보기도 HTTP의 공유/팀만 보기 독립 전환·마침/재개·권한/익명/동시수정 보호·모임 자료 자동 제외 검사를 포함한다. 별도 PostgreSQL에서 V022→V024 전환·실패 롤백·재실행 차단·기존 자료 보존·JPA validate와 개인정보 삭제 회귀 검사 2개도 성공했다.
- 실제 로컬 화면에서는 가상 비공개 요청의 마침·재개와 공개 범위 유지, 새 요청의 원문 재입력 없는 공유 저장, 마친 요청의 일반 교사 공유 목록 노출, 마친 요청을 제외한 모임 자료 재생성·발표 화면을 확인했다. 375px에서 가로 넘침 없고 선택 버튼 높이 44px 유지. 검사 DB 서버는 종료했고 가상 앱 미리보기만 유지한다.
- 단계별 흐름 검증: 가상 요청의 접수→기도 중, 마치기→마친 기도, 다시 기도하기→기도 중 자동 이동 및 팀만 보기 유지 확인. 새 가상 요청의 `전체에 공유`도 별도 저장 단계 없이 처리됨을 확인했다. 프런트 241개 검사 성공, `.verification/intercession-flow-build` 빌드 및 375px 화면 버튼·가로 넘침 확인. 이번 단계별 흐름 변경은 기존 서버 API를 사용한다.

- 별도 제목 선택·순서 조정·자료 생성·발표 화면을 제거했다. 현재 전체 공유 중이며 기도 중인 제목을 청소년부·학생·교사·가정·기타 순서로 자동 묶는다. 비어 있는 분류는 표시하지 않는다.
- 분류 선택·제목/내용 검색을 제공하고 공유 본문을 바로 읽을 수 있다. 전체/현재 목록 또는 분류별로 복사해 PPT에 옮길 수 있다. 복사 결과에도 분류 제목을 유지한다.

- 상세 확인 후 모아보기로 돌아온다. 예전 materials/present 주소도 모아보기로 연결한다. 기존 모임 자료 API와 저장 자료는 이전 앱 호환을 위해 보존하며, 이번 변경은 프런트에 한정한다. 위의 모임 자료 생성·발표 검증은 이전 단계 기록이다.
- 검증: 프런트 244개 검사 성공, `.verification/intercession-collection-build` 빌드 성공. 페이지 이어 읽기·중복 제거·조회 실패·공유/완료 필터·복사 개인정보 제외 검사를 추가했다. 실제 가상 화면에서 청소년부 3건/교사 1건 분류, 전체·분류별 복사 결과, 검색 빈 결과, 상세 왕복을 확인했다. 375px 화면 가로 넘침 없음, 브라우저 오류 없음. `git diff --check` 통과.

## 기도제목 용어 정리 (후속 변경)

- `기도 마치기`를 `보관하기`, `마친 기도` 목록을 `보관함`, 완료 상태 표시를 `보관 중`으로 변경했다. 응답 여부를 단정하지 않고, 현재 함께 기도할 목록에서 정리한다는 뜻으로 사용한다. 보관 시 기존 공유 범위와 기록은 유지된다.
- 보관된 제목에는 `다시 기도하기`를 표시하며 실행하면 기도 중 목록으로 돌아간다. 완료 여부를 저장하는 기존 API·데이터 구조는 유지한다.
- `기도제목 철회 / 철회됨`을 `기도제목 삭제 / 삭제됨`으로 변경했다. 확인창은 목록과 공유 화면에서 사라진다는 결과를 짧게 알린다. 삭제 후 원래 목록으로 돌아가며 기존 삭제 방식·접근 권한은 유지한다. 서버 오류 문구도 삭제로 통일했다.
- 저장 알림도 `보관함으로 옮겼습니다 / 기도 중 목록으로 옮겼습니다 / 기도제목을 공유했습니다`로 정리했다.
- 검증: 프런트 244개 검사 및 `.verification/intercession-labels-build` 빌드 성공, 서버 전체 `build` 성공. 가상 기도제목 보관→보관함 이동→다시 기도하기→기도 중 복귀, 공유 범위 유지, 삭제 확인창과 취소를 확인했다. 375px 가로 넘침·브라우저 오류 없음. 실제 자료 삭제는 하지 않았다.

## 최종 용어 확정: 현재·지난 기도제목

- 사용자는 응답 여부를 단정하는 표현 대신 `현재 기도제목 / 지난 기도제목`을 확정했다. 위의 보관 관련 용어는 이 변경으로 대체한다.
- 접수 탭은 `새 요청 / 현재 기도제목 / 지난 기도제목`, 공유 탭은 `현재 기도제목 / 지난 기도제목`으로 통일했다. 목록 상태·상세 제목·이동 알림도 같은 표현을 사용한다.
- 주요 버튼은 `지난 기도제목으로 이동 / 다시 기도하기`이며, 별도의 삭제 버튼은 `기도제목 삭제`를 유지한다. 이동 아이콘도 지난 기록을 뜻하는 모양으로 맞췄다.
- 기존 상태 저장·공유 범위·원문·기록 보존 동작은 변경하지 않았다. 모아보기에는 현재 공유 중인 기도제목만 표시한다.
- 검증: 프런트 244개 검사 및 `.verification/intercession-current-past-build` 빌드 성공. 375px에서 3개 탭·상태 표시·긴 이동 버튼·지난 제목의 다시 기도하기를 확인했고 가로 넘침과 브라우저 오류가 없었다. 서버 변경은 없다.

## 기도제목 화면 통합 (최신 변경)

- 사용자 요청에 따라 접수·정리·모아보기·함께 기도해요를 `기도제목` 한 화면으로 합쳤다. 홈에는 기도제목 메뉴 하나와 팀원 명단만 남기고 중복 공유 목록·별도 모아보기 메뉴를 제거했다.
- 팀은 새 요청(빨간 건수)·현재 기도제목·지난 기도제목을 전환하고 청소년부·학생·교사·가정·기타 분류, 검색, 공유 범위(전체 보기·전체 공유·팀만 보기)를 같은 화면에서 사용한다. 제목을 누르면 상세·공유 결정·내용 수정·현재/지난 이동을 창으로 처리한다.
- 본인 등록과 대신 등록도 같은 화면의 등록창으로 연결했다. 등록·공유·현재/지난 이동 후 창을 닫고 해당 목록을 보여준다. `내가 보낸 요청`은 본인 접수 상태 확인용으로 유지한다.
- 일반 교사는 같은 기도제목 화면에서 현재/지난 공유 내용·분류·검색·복사·본인 제출을 이용한다. 새 요청 관리, 대리 등록, 팀만 보기, 관리 버튼은 제공하지 않는다. 기존 서버 권한을 그대로 사용한다.
- 공유 내용 복사는 전체 또는 분류별로 가능하며 항상 최신 공개 API를 다시 읽는다. 팀 원문·비공개 요청·익명 이름·지난 요청은 복사하지 않는다. 페이지가 여러 개인 목록도 모두 조회한 후 분류·검색한다.
- 기존 inbox/board/collection/materials/present 주소는 통합 화면으로 연결한다. 예전 발표 주소 때문에 하단 메뉴가 사라지던 레이아웃 예외도 제거했다. 서버·DB 변경은 없다.
- 검증: 프런트 249개 검사 성공. 새 테스트로 역할별 조회 범위, 기존 주소 연결, 새/현재/지난/삭제 상태 분리, 분류·검색, 익명 원문 검색 제외, 최신 공유본만 복사, 두 번째 페이지 검색을 확인했다. 가상 대리 등록→새 요청 1→2→공유 후 1, 현재→지난→현재 이동을 같은 화면에서 확인했다. 일반 교사 공개 목록·상세·본인 제출창에는 관리 기능과 비공개 내용이 노출되지 않았다. 전체 복사 결과에는 분류 제목과 최신 공개 내용만 포함되며 익명 이름·팀만 보기·지난 요청은 제외되었다. 공유 범위·분류·검색 빈 결과·홈 메뉴 통합을 확인했다.
- 최종 `.verification/intercession-unified-build` 빌드 성공. 375px에서 목록·등록창·공유 결정창의 가로 넘침이 없고 팀장·교사 브라우저 오류도 없었다. 수정된 통합 화면 미리보기를 열어 두었다.

## 화·목 모임과 참석 통계 묶음

- 홈 하단의 작은 `기도모임 참석 통계` 텍스트 링크를 제거하고, 화·목 모임 카드 바로 아래에 통계 아이콘·제목·화살표가 있는 카드형 버튼으로 배치했다.
- 화·목 제목·두 모임 카드·통계 버튼을 같은 연보라색 배경과 테두리 안에 묶었다. 통계 버튼은 높이를 작게 유지하면서 누를 영역을 넓혔다.
- 기존 통계 화면과 접근 권한은 유지한다. 투표 자료·집계 방식·서버는 변경하지 않는다.
- 검증: 프런트 249개 검사와 `.verification/intercession-meeting-card-build` 빌드 성공. 375px 가로 넘침 없음, 통계 버튼에서 기존 참석률·교사별 응답 화면으로 이동 및 뒤로 복귀 확인, 브라우저 오류 없음. 수정한 홈 미리보기를 열어 두었다.

## 세 가지 후속 개선: 주차 연결·짧은 목록·수정과 근황

- 통계 버튼에 선택한 주차를 전달한다. 지난주 통계를 보고 돌아와도 중보기도팀 홈의 주차가 유지된다. 통계 화면은 잘못된 날짜와 미래 날짜를 이번 주로 정규화하며, 홈의 미래 주차 통계는 `집계 전`으로 표시한다. 집계 기준과 권한은 유지한다.
- 기도제목 목록 본문을 최대 세 줄로 줄였다. 상세에는 전체 본문을 표시하고 분류별·전체 복사에도 전체 공개 본문을 유지한다.
- 제출자는 본인 상세에서 `내용 수정·근황 전달`을 펼쳐 제목·내용을 수정하거나 최근 상황을 보낼 수 있다. 입력은 기존 제출 내용으로 채우며, 새 전달 내용은 팀의 `새 요청`과 본인 목록의 확인 대기 표시로 연결한다.
- 팀은 `공유 내용 유지` 또는 `공유 내용에 반영`을 선택한다. 공유할 제목·본문을 직접 정리할 수 있고, 팀만 전달에 동의한 요청에는 공유 버튼/API를 허용하지 않는다. 초기 새 요청의 수정도 같은 화면에서 한 번에 확인한다.
- 팀 확인 전에는 기존 원문·공유 본문을 변경하지 않는다. 확인 시 원문을 반영하고 수정·근황 이력을 남기며, 공개 여부·익명 여부·현재/지난 상태를 보존한다. 검토 대기 중 원문은 접어 두어 새 내용부터 확인할 수 있게 했다.
- 제출자 본인만 수정·근황을 전달할 수 있고 팀만 검토할 수 있다. 공개 조회·검색·복사에는 확인 전 내용과 비공개 수정 이력을 포함하지 않는다. 동일 요청의 동시 수정은 버전 충돌로 차단하며, 삭제된 요청에는 추가 전달/검토를 허용하지 않는다. 계정 삭제 시 해당 요청에 담긴 근황·수정 이력도 함께 삭제된다.
- 다른 기기에서 변경한 결과를 빨리 확인하도록 목록 전환·상세 열기 때 최신 자료를 조회하고, 목록은 15초 간격으로 갱신한다.

검증:
- 프런트 252개 검사 통과 및 `.verification/intercession-updates-build` 최종 빌드 성공. 주차 연결·날짜 정규화, 검토 대기 분류, 공개 검색/복사의 비공개 정보 제외를 추가 검사했다.
- 백엔드 `gradlew build` 성공. 실제 API 경로의 본인 권한·팀 권한·공유 동의·익명성·검토 전 비공개·검토 후 반영·공유 내용 유지·지난 상태 유지·버전 충돌·입력 검증·삭제 후 차단을 확인했다.
- 격리 PostgreSQL에서 V022–V025 전환, 실패 시 롤백, 기존 기록 보존, 재실행 차단, 최종 스키마 검증 및 개인정보 삭제 검사를 통과했다. 검사 서버는 종료했다.
- 가상 자료 브라우저 검수: 지난주 통계 날짜·뒤로 복귀, 미래 주차 집계 전, 교사 수정·근황 전달→팀 새 요청→기존 공유 유지→추가 수정→팀 공유 반영, 비공개 요청의 팀 확인, 수정 이력 2건, 세 줄 목록과 상세 전체 본문·전체 복사 확인. 375px 입력·목록·검토 화면에 가로 넘침이 없으며 브라우저 오류가 없었다.

## 기도제목 사분할 보기 (최신 화면 변경)

- 기도제목의 새 요청·현재·지난 목록을 분류별 2열 사분할 카드로 통일했다. 위의 세 줄 본문 미리보기는 이 변경으로 대체하며, 카드에서는 본문을 표시하지 않는다.
- 작은 카드에는 제목(최대 두 줄), 제출자 이름, 등록일을 표시한다. 수정·근황 대기 표시는 유지하고 공유 범위는 작은 아이콘으로 정리했다. 등록일은 원래 생성일을 사용하므로 수정·근황 전달 시 바뀌지 않는다.
- 일반 교사 화면에서는 이름 비공개 요청을 `익명`으로 표시한다. 팀에는 기존 권한 범위의 제출자 이름이 보인다. 본문과 상세 수정·공유 기능은 카드를 눌러 사용한다.
- 분류·검색·공유 범위 필터와 전체/분류별 복사를 유지했다. 서버·저장 구조 변경은 없다.
- 검증: 프런트 252개 검사 및 `.verification/intercession-grid-build` 빌드 성공. 가상 요청으로 375px에서 2×2 카드 배치·본문 미리보기 제거·상세 열기·새 요청/현재/지난 전환·등록일 표시를 확인했다. 일반 교사에게 익명 이름과 비공개 요청이 노출되지 않으며, 모바일 가로 넘침과 브라우저 오류가 없었다.

## 기도제목 상세의 펼침·스크롤 디자인 통일

- 사용자 이미지의 네모난 기본 펼침 영역을 공통 버튼 규격에 맞춘 둥근 아이콘형 패널로 교체했다. 기존 앱의 파란 닫힘 상태·초록 열린 상태, 화살표 회전, 테두리·간격·입력란 여백을 적용했다.
- 내용·공유 설정, 현재 공유 본문, 기존 제출 내용, 내용 수정·근황 전달, 팀 검토의 공유할 내용, 지난 수정·근황을 같은 `PrayerDisclosure`로 통일했다. 펼침과 접힘에 짧은 높이 애니메이션을 적용하고 동작 줄이기 설정을 따른다.
- 접어도 입력 요소를 유지하여 초안이 사라지지 않는다. 접힌 내용은 접근성 트리와 키보드 이동에서 제외하고, Enter/Space로 버튼을 조작할 수 있다. 펼칠 때 강제로 페이지 아래로 이동시키지 않는다.
- 중보기도 상세창은 일정한 높이 안에서 본문만 스크롤하며 제목·닫기 버튼을 고정한다. 작은 화면/키보드 높이에 맞춰 줄어들고, 바깥 페이지로 스크롤이 넘어가지 않게 했다. 스크롤바와 입력란 스크롤도 얇고 둥글게 정리했다. 삭제 확인창은 내용에 맞는 작은 높이를 사용한다.
- 삭제 버튼은 본문 펼침 버튼과 구분되는 작은 테두리 버튼으로 정리했다. 실제 삭제 전 확인 절차는 유지한다.
- 공통 MotionDialog에는 선택적인 className만 추가하고 새 상세창 스타일은 중보기도 화면으로 한정했다. 서버·권한·저장 구조 변경은 없다.
- 검증: 기존 252개 검사 및 최종 `.verification/intercession-disclosure-build` 빌드 성공. 375px/320px에서 가로 넘침 없음, 펼침 전후 헤더 위치 유지, 공유 제목과 근황 초안의 접기/펼치기 유지, Enter/Space 조작, 접힌 입력란을 건너뛰는 Tab 이동, 모든 펼침 영역, 공유 설정 저장, 삭제 확인 취소, 닫기 후 원래 카드로 초점 복귀를 확인했다. 브라우저 오류 없음. 삭제·배포는 수행하지 않았다.

다음 출시 준비 시 V023·V024에 이어 `V025__intercession_request_updates.sql` 적용이 필요하다. 기존 운영 V022는 반복 적용하지 않는다. 가상 미리보기 서버(8094)만 새 코드로 재시작했으며 실제 데이터는 변경하지 않았다.

사용자는 추가 개발 후 출시하기로 했다. 이번 변경은 로컬 작업이며 배포·스토어 제출·커밋·푸시는 하지 않았다. iOS 1.0.4(11)에 이번 변경은 포함되지 않았으므로 다음 출시 시 새 빌드가 필요하다.
