# iOS 업데이트 안내 지연 확인·수정 — 2026-11-06

사용자는 설치 버전이 1.0.3인데 새 버전 안내가 나오지 않는다고 보고했다. 안내 기능은 1.0.3 소스 dbcea8c에 포함돼 있다. 이번 수정은 로컬 검증까지 완료했으며 새 배포·스토어 제출은 하지 않았다. 이미 출시된 1.0.3·1.0.4에 소급 적용되지 않는다.

## 원인과 실제 조회

11월 6일 08:39 KST 확인:

- App Store Connect의 1.0.4(12)는 READY_FOR_SALE, 자동 출시 AFTER_APPROVAL, 빌드 VALID.
- 앱이 쓰는 고정 Apple 조회 주소 `https://itunes.apple.com/lookup?id=6823391707&country=kr`는 1.0.3을 반환했다. Cache-Control의 남은 시간은 약 9,550초였다.
- 같은 주소에 no-cache 요청 헤더를 보내도 1.0.3이었다.
- 조회 시각 매개변수 t를 추가한 새 주소는 1.0.4와 공개 시각 2026-11-05T19:17:02Z(11월 6일 04:17:02 KST)를 반환했다. 응답의 cache max-age는 86,400초였다.
- 따라서 앱의 숫자 버전 비교가 아니라, 고정 조회 주소에 남은 Apple 캐시가 새 버전 발견을 늦추는 사례를 재현했다. 이 결과는 조사 PC에서 관찰했으며 사용자의 기기 내부 응답이나 캐시를 직접 읽은 것은 아니다.

## 수정

- Apple의 조회 도메인·앱 ID·한국 스토어 조건을 유지하고, 기존 1시간 확인 간격마다 바뀌는 t 값을 주소에 붙인다.
- 같은 시간대에는 공통 주소를 사용하며 기기·계정 식별자를 전송하지 않는다. 저장된 조회 결과의 1시간 재사용, 실패 후 15분 재시도, 나중에 24시간 숨김은 유지한다.
- 매번 최신 버전이 즉시 보인다고 보장하지 않는다. 다음 확인 기회는 앱 실행·다시 활성화·온라인 복구이며 기존 확인 간격과 Apple 원본 정보 반영 시간이 적용된다.
- 이미 설치된 앱 코드를 원격으로 수정하지 않는다. 지금 업데이트하려면 App Store 상세 페이지에서 직접 1.0.4로 업데이트할 수 있다. 기존 앱도 고정 주소와 기기 캐시가 갱신된 뒤 안내할 수 있다.

## 검증

- URL마다 하루 동안 이전 응답을 유지하는 Apple 캐시를 재현한 테스트 추가. 출시가 바뀐 후 다음 확인에서는 새 버전을 찾고, 확인 간격 내 중복 요청은 보내지 않음을 확인했다.
- 안내 관련 16개, 전체 프런트 253개 테스트 성공. native 모드 빌드 성공. 기존 500 kB 청크 경고만 남았다.
- 서버 build 성공(변경 없음, 기존 검사 결과 UP-TO-DATE).
- 08:41 KST 수정된 실제 조회 주소에서 1.0.4 확인. 설치 1.0.3에는 1.0.4 안내, 설치 1.0.4에는 안내 없음 확인.
- 실제 iPhone 설치 검수·서명·스토어 제출은 이번 작업에서 하지 않았다.
