# iOS 1.0.4 최신 수정분 출시 준비 — 2026-11-05

사용자가 “이어서 진행하고, 다 마무리 되면 출시까지 진행해줘”라고 승인했다. 이전 출시 보류를 해제하고 기존 iOS 출시 후보 브랜치에서 진행한다. 승인 후 자동 출시를 유지한다.

## 출시 범위

- 미제출 빌드 1.0.4(11)를 그대로 제출하지 않는다. 최신 변경을 담은 1.0.4(12)를 준비한다.
- 중보기도 화·목 21:30 고정, 모임 없음 표시, 카카오톡 Zoom 공유 방식, 통합 기도제목 목록·공유 결정·현재/지난 기록·수정과 근황 검토, 통계 주차 연결과 모바일 상세 디자인.
- 찬양팀 상세·선택·스크롤 디자인, 기존 학년 색상 적용.
- 모든 임원의 팀 조회, 일반 교사의 소속 팀 메뉴, 담당자 지정과 기존 수정 권한 분리.
- 운영 V022는 이미 적용됐으므로 재실행하지 않는다. V023·V024·V025를 최신 암호화 백업 복원본에서 확인한 뒤 순서대로 반영한다.
- main·공개 웹앱·Android 배포 트랙은 기존 출시 방식대로 분리한다.

## 로컬 확인

- 프런트 252개 검사 및 최종 빌드 성공.
- 서버 301개 중 283개 성공, 별도 환경용 18개 제외, 실패 0.
- iOS 출시 도구 80개 성공. 제한된 실행 환경의 Windows 보호 저장소 검사 1건은 실제 사용자 환경에서 재실행해 통과했다.
- 백업·개인정보 도구 7개 성공, 별도 PostgreSQL 환경용 1개 제외.
- 가상 자료로 팀 지정 화면·학년 색상·임원/소속 교사/비소속 교사의 메뉴와 조회 전용 화면을 확인했다.

출시 진행 시점 Apple 조회: 공개 1.0.3(10), 1.0.4(11) VALID, 1.0.4 버전 레코드 아직 없음. App Store Connect 브라우저 로그인은 유효하다.

원격 동일 소스 검사, 백업 복원·자료 전환, 운영/가상 심사 서버 반영, 빌드 12 업로드 및 심사 접수 결과는 완료 후 추가한다. 현재 문서는 심사 접수나 출시 완료를 뜻하지 않는다.

## 출시 중 확인 및 추가 수정

- 85ba2e3 후보의 프런트·서버·Android·PostgreSQL 17/18 회귀 검사와 iOS 검사가 성공했다.
- 17:55 KST 암호화 백업: 70개 표·2,829행. 복원본 해시·계정 삭제 이력 확인, V023~V025 실패 롤백·재실행 차단·기존 필드 보존·JPA validate 기동 통과.
- 18:03 KST 운영 V023~V025 반영 완료. 지정한 21:30 전환 외 기존 필드·기록을 보존했고 운영 배포 5657188c-8bec-4eb0-8f44-3dfda5bc5ba8 성공·단독 활성·공개 health 200을 확인했다.
- 가상 심사 서버의 기존 H2 데이터에서 새 NOT NULL 열의 기본값이 없어 자동 추가가 실패하는 문제를 발견했다. canceled·cancellationReason·prayerCompleted의 DB 기본값을 지정하고, review 전용 기존 자료 전환에서 모임 시각·지난 기도제목 상태를 맞췄다. 새 테스트는 기존 본문·수정 번호와 재시작 후 팀의 상태 변경 보존을 확인한다. 운영 PostgreSQL 전환은 재실행하지 않는다.
- 수정 후 서버 전체 build·bootReviewJar 성공. 심사 묶음에서 실제 명단과 개인 키가 제외됨을 확인했다. 이 추가 수정도 새 커밋에서 원격 검사를 다시 진행한다.
- App Store Connect에 1.0.4 버전 레코드를 만들고 변경사항·설명·심사 안내를 저장했다. 기존 5개 iPhone 스크린샷과 비공개 가상 심사 계정을 유지했고 승인 후 자동 출시를 선택했다. 아직 빌드 12 업로드·연결·심사 제출은 하지 않았다.
- 서명 환경에 codex/ios-first-update를 임시 허용하는 요청은 자동 승인 검토에서 거절됐다. 현재 환경은 main만 허용하고 필수 승인자를 유지한다. 사용자에게 이 구체적인 임시 허용의 승인을 받은 후 진행해야 하며 다른 경로로 우회하지 않는다.
