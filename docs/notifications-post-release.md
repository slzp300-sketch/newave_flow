# 출시 후 알림 사전 구현 — 운영 미적용

이번 변경은 별도 worktree에서 준비한 소스다. APNs/FCM 전송 소스는 사용자 승인 후 준비했으며, 가짜 HTTP 응답으로 검사한다. 운영 V015 마이그레이션, 서버 배포, 공급자 키 발급·설정 및 외부 발송은 수행하지 않았다.

## 알림 규칙

정기 알림은 서버 기준 Asia/Seoul 오전 09:00에 생성한다. 알림일은 입력 잠금일이 아니다.

| 항목 | 생성 조건 | 제외 대상 |
|---|---|---|
| 새 일정 | 단건·일괄 생성 시 기존 활성 사용자 | 비활성·이용 중지 |
| 행사 출석 | 행사 마감 3일 전·당일 | 필요한 교사 응답/담당 반 학생 응답을 모두 제출한 사용자, 접수 시작 전 |
| TTS | 수·토요일, 이번 주 현재 분기에 속한 지난 날짜의 일일 체크 누락 | 오늘·미래 날짜, 마감된 분기, 시트 확정 기간, 이미 체크 완료 |
| 주일 출석·공동 보고 | 주일 안내·화요일 미제출 독려 | 담당 반이 모두 제출 완료된 교사. 같은 반 다른 교사의 제출도 완료로 인정 |
| 교사회의 투표 | 금요일, 이번 주 토요일 응답 없음 | 참석·불참 중 하나라도 응답 완료 |
| 회의록 | 최초 공개 시 해당 날짜 회의에 불참으로 응답한 활성 사용자 | 참석자·미응답자. 본문 편집/재공개는 재전송 안 함 |
| 전도 로테이션 | 월·금요일, 이번 주 남은 일정에 배정된 교사 | 취소 일정·다음 주 이후·지난 일정·비활성 사용자 |

요일별 개인 체크는 기존 월~토를 유지한다. TTS 기한 변경과 알림은 별도 정책이다. 참석/주간 단일 항목은 토요일 귀속이며, 토요일 오전 알림에서 당일 미체크를 독려하지 않는다.

## 앱 API

- `GET /api/notifications`: 본인 알림에 `targetPath` 추가. 클라이언트는 수신된 `notificationId`를 본인 알림 목록과 대조한 후 저장된 경로로 이동한다.
- `GET /api/notifications/preferences?platform=IOS|ANDROID`: `{pushEnabled, available}`. 기본 동의는 false. 해당 플랫폼의 전송 설정이 비활성이면 available=false. `available`은 서버 설정 준비 여부이며 실제 공급자 연결 성공이나 휴대폰 권한을 보장하지 않는다.
- `PUT /api/notifications/preferences?platform=IOS|ANDROID`: `{pushEnabled: true|false}`. 본인 설정만 저장. 플랫폼은 선택 인자이나 모바일 앱은 자신의 플랫폼을 보낸다.
- `PUT /api/notifications/devices/{UUID}`: `{platform: "IOS"|"ANDROID", token, appVersion}`. 토큰은 응답·로그에 노출하지 않는다.
- `DELETE /api/notifications/devices/{UUID}`: 본인 기기만 해제. 다른 소유자의 기기를 삭제하지 않는다. 로그아웃 전에 호출한다.
- 동일 설치/토큰이 다른 계정으로 등록되면 이전 소유자의 대기 전송을 제거한다. 한 토큰을 여러 설치 행에 중복 등록하지 않는다.
- 앱은 등록·토큰 갱신·해제를 한 순서로 처리하며, 해제 중에는 토큰 갱신을 받지 않는다. 서버는 사용자 잠금 후 현재 인증 버전과 이용 상태를 다시 읽어 로그아웃 전에 인증된 늦은 등록을 거절한다. 등록 결과가 불명확하면 해제 확인 전까지 새 등록을 보류한다.
- 서버 해제 대기는 최대 60초, OS 정리는 최대 5초로 제한하며 미완료 요청을 뒤의 등록이 앞지르지 않게 한다. 오프라인 로그아웃과 앱 강제 종료 때는 서버 해제를 확정할 수 없다. 잠금 화면 문구는 일반 안내만 사용하고 알림을 열 때 본인 소유를 다시 검사한다. 실제 연결 검수에는 느린 응답·오프라인·계정 전환을 포함한다.

## 전송·중복 방지

`NOTIFICATIONS_ENABLED`, `PUSH_ENABLED`, `PUSH_IOS_ENABLED`, `PUSH_ANDROID_ENABLED`는 모두 기본 false다. 기존 주일 08시/월요일 10시 전체 독려 작업을 09시 대상별 작업으로 대체한다. 정기 생성은 해당 시각 서버가 실행 중이어야 하며, 중단 시간의 정기 알림을 자동 소급 생성하지 않는다.

업무 종류·대상·주차/날짜·발송 회차로 만든 키와 수신자 조합에 DB 유일성 제약을 둔다. 기기별 전송 행도 알림+설치 조합으로 유일하다. 수신 거부, 계정 전환, 이용 중지, 삭제, 만료 기기는 전송 전에 재확인한다. 이미 제출했거나 일정 취소·삭제·배정 변경·회의록 비공개 전환 등으로 대상에서 벗어났으면 전송 직전 취소한다. 당일 독려는 다음 날 보내지 않는다. 일시 DB 조회 오류는 취소로 오인하지 않고 대기 행을 보존한다.

전송 행은 잠금으로 병렬 작업자가 같은 행을 동시에 발송하지 못하게 한다. 공급자 일시 실패는 최대 5회, 24시간 안에서 재시도한다. 공급자가 토큰 무효를 확인하면 기기 토큰과 해당 기기의 전송 행을 즉시 제거하고 앱 내 알림은 보존한다. 임의의 토큰 보관 기간은 도입하지 않았다.

발송 작업은 소유자 ID를 먼저 읽고 사용자→전송 행 순서로 잠근 뒤 전송 행을 새로 읽는다. 다른 작업자가 이미 완료한 행을 이전 캐시 상태로 재전송하지 않는다. 한 플랫폼이 꺼져 있으면 그 플랫폼의 미만료 행을 100건 조회 한도에서 제외해 다른 플랫폼을 막지 않게 한다. 조회 이후 비활성화된 경우에는 횟수 소진 없이 최대 5분 뒤(만료 시각 이내)로 미룬다.

네트워크 전송 성공 직후 DB 저장 전에 프로세스가 중단되는 경우까지 외부 푸시의 정확히 1회 전달을 보장할 수는 없다. 어댑터는 알림 ID 기반 APNs collapse / Android tag를 사용한다. 앱의 ID 확인과 함께 중복 영향을 줄이지만 정확히 1회 전달을 보장하지는 않는다.

`ProviderPushTransport`는 APNs HTTP/2 및 FCM HTTP v1용 소스다. 모든 전송 플래그가 꺼진 상태에서는 공급자 호출이 일어나지 않는다. HTTP 경계에 가짜 응답을 주입한 검사만 수행하며, 실제 휴대폰 수신이 확인됐다고 보고하지 않는다. 잠금화면에는 개인 이름·기록·종교 활동 상세 없이 ‘새 알림이 있습니다. 앱에서 확인해주세요.’와 앱 이름만 표시한다. 데이터에는 알림 ID만 포함하고 화면 경로는 본인 알림 API에서 검증한다. 현재 경로는 해당 기능의 첫 화면이며 특정 과거 주차로 바로 이동하는 기능은 포함하지 않는다.

공급자 설정은 환경변수로만 읽는다. iOS는 `PUSH_APNS_TEAM_ID`, `PUSH_APNS_KEY_ID`, `PUSH_APNS_PRIVATE_KEY`, `PUSH_APNS_TOPIC`(앱 ID 고정), `PUSH_APNS_SANDBOX`를 사용한다. Android는 `PUSH_FCM_PROJECT_ID`, `PUSH_FCM_CLIENT_EMAIL`, `PUSH_FCM_PRIVATE_KEY`를 사용한다. 키·토큰·공급자 응답 원문을 로그에 쓰지 않는다. 허용된 HTTPS 공급자 호스트만 호출하고 리다이렉트를 따라가지 않으며 연결·요청·응답 시간 제한을 둔다. APNs 인증 JWT는 50분, FCM 액세스 토큰은 최대 55분 동안 메모리에만 캐시한다.

계정 삭제 SQL은 알림 동의, 기기 토큰, 전송 대기/결과와 TTS 연동 스냅샷을 제거한다. 운영 적용 전 새 마이그레이션을 포함한 가상 PostgreSQL 및 복원본 검증이 필요하다. 운영 DB나 실제 계정으로 검증하지 않는다.

## 후속 배포 전 확인

1. V015(알림), V016(TTS) 적용 순서와 백업 복원 검증. 새 스키마 없이 새 서버를 배포하지 않는다.
2. 공급자 설정·키·권한을 별도 승인/준비하고 실제 연결을 검증. 소스·가짜 응답 검사는 실제 전달 검사와 구분한다.
3. iOS entitlement·서명 프로파일, Android Firebase 설정 및 Android 알림 권한. 이후 새 앱 빌드 필요.
4. 개인정보 안내에 기기 식별자·푸시 토큰과 수신 동의/철회 반영.
5. 별도 가상 계정·검수 기기에서 실제 수신·탭 이동·로그아웃·계정 전환 검수 후 활성화.

공식 참고: [Apple APNs 요청](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns), [Firebase HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api).
