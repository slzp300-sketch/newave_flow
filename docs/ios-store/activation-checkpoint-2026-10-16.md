- 공개 제출 자료 `metadata.ko-KR.json`과 콘솔 저작권 칸에 `2026 김재현`을 반영·저장했다.

- 사용자 승인에 따라 대한민국 공개 연락용 이메일을 인증했고 대한민국 연락처를 최종 저장했다. App Store Connect 비즈니스 규정 준수 표에서 대한민국 전자상거래법 상태 **활성화됨**, 마지막 갱신일 **2026-10-16**을 확인했다.

- 권리자 확인과 개인 멤버십 활성화는 Apple 심사 지침상 서비스 제공 주체·제출 명의 적합성의 확인을 대신하지 않는다. 제출 전 [권리·제출 주체 준비 자료](../ios-enrollment-dossier.md)를 최종 대조한다.

## API 접근과 서명 자료

App Store Connect API 접근 신청은 사용자 명시적 승인 후 진행했고 즉시 승인됐다. 이후 Developer 역할의 팀 API 키를 발급했으나 앱 내 브라우저의 일회성 다운로드에서 키 파일을 확보하지 못했다. 사용자의 승인으로 해당 미사용 키를 무효화했다. 이어 Chrome에서 같은 Developer 역할의 팀 API 키를 다시 발급하고 정상 다운로드했다.

다운로드한 키는 P-256 형식 검증과 Windows CurrentUser DPAPI 암호화·복원 왕복 검사를 통과했다. GitHub 보호 환경 설정을 다시 확인한 뒤 업로드용 App Store Connect 비밀값 **3개를 저장했고 서명용 4개를 포함한 총 7개 비밀값 목록을 확인했다.** 다운로드 폴더의 평문 키는 암호화 보관·등록 확인 후 삭제했다. **새 키로 Apple API의 해당 앱 레코드 조회에 성공했고, 아래 실제 빌드 검증·업로드 실행도 성공했다.** Apple 로그인 서버용 키와 업로드 키는 별도로 관리한다.

Apple Distribution 인증서는 사용자 명시적 승인 후 발급했다. 개인 키는 Windows CurrentUser DPAPI로 보호했고 암호화 p12와 별도로 DPAPI 보호한 p12 비밀번호를 준비했다. 다음 로컬 검증은 통과했다.

- 인증서와 개인 키의 공개키 일치
- 개발자 팀 일치, 인증서 유효기간과 코드 서명 용도
- 암호화 p12의 복원 및 비밀번호 보호 왕복
- 앱 전용 App Store Connect 배포 프로파일 발급, 팀·Bundle ID·배포 형식과 포함 인증서 일치
- 프로파일의 CMS 서명 무결성 검사. `-noverify`를 사용한 수학적 서명 일치 확인이며 Apple 신뢰체인·취소 상태를 검증한 것은 아님

GitHub `ios-testflight` 보호 환경은 필수 검토자 `slzp300-sketch`, `main` 브랜치만 허용, 관리자 우회 금지 설정을 확인했다. 서명용 비밀값 **4개**와 저장소 변수 `IOS_RELEASE_CONFIGURED=true`를 저장했다. 실제 값·인증서/프로파일/키 식별자는 이 문서에 기록하지 않는다.

**실제 macOS runner에서 유효한 Apple Distribution 서명 identity 확인, 아카이브 서명 검증, 최종 권한·프로파일 대조와 IPA 내보내기를 완료했고 Apple 바이너리 검증·업로드도 통과했다.** 로컬 CMS 검사는 여전히 신뢰체인 검사와 구분하며, 별도의 인증서 취소 상태 검사를 완료했다고 기록하지 않는다. 이후 Apple 처리와 실제 설치 결과는 [서명·TestFlight 절차](../ios-testflight-runbook.md)에 따라 확인한다.

최초 자료 준비 도구는 저장 위치 제한, OneDrive·네트워크·경로 재지정 거부, 덮어쓰기 방지, 민감한 오류·키·비밀번호의 출력 방지를 포함한다. 최초 가상 자료 검사에서 신규 **16개**와 기존 검사를 포함한 iOS 도구 검사 **58개**가 통과했다. 이후 아래 entitlement XML 수정과 안전한 파싱 검사를 추가한 **전체 60개 검사도 통과했다.** 테스트의 실제 DPAPI 왕복 검사는 공개 가상 문자열만 사용했다. 독립적인 읽기 전용 검토에서 수정이 필요한 사항은 발견되지 않았다.

## 최초 실제 서명 실패와 수정 이력

첫 [서명 전용 실행 38825661452](https://github.com/slzp300-sketch/newave_flow/actions/runs/38825661452)은 `upload=false`로 진행했다. `codesign`에서 읽은 entitlement 출력을 plist로 해석하는 단계에서 `Invalid file` 오류로 실패했다. 업로드와 내보내기 완료로 기록하지 않는다.

entitlement 출력을 명시적인 XML로 받도록 `--xml` 옵션을 추가했고, 잘못된 출력을 안전하게 거절하는 파싱 처리도 보완했다. 관련 전체 **60개 검사 통과**를 확인했다. 수정 후 실제 서명 재실행과 업로드 성공은 아래 후속 실행 기록으로 확인했다.

## 재발급 후 추가 확인

새 Developer 역할 키로 Apple API의 이 앱 레코드를 조회해 인증과 Bundle ID 일치를 확인했다. 가상 데이터로 촬영한 iPhone 스크린샷 5장은 체크섬·크기·RGB 형식·촬영 영수증을 대조해 제출 묶음을 만들고 콘솔에 업로드했다. 콘솔에 5개 파일이 순서대로 표시됨을 확인했으며 최종 기능과의 대조는 제출 전에 다시 한다.

`97ace10`의 macOS 검사에서는 Windows용 보관 도구의 합성 테스트가 macOS 임시 폴더의 심볼릭 링크 경로를 거부했다. 테스트 기준 경로만 `resolve()`로 정규화했고 실제 보관 경로의 링크 거부 규칙은 유지했다. 관련 16개 검사를 통과했으며 후속 `feb43c4`의 회귀 검사와 iOS 네이티브 검사도 모두 통과했다.

App Store Connect TestFlight 목록에 `1.0.0(1)`이 생성 시각 **오전 9:25(KST)**, 상태 **처리 중**으로 표시됐고, 후속 확인에서 **제출 준비 완료** 상태와 90일 만료 표시로 전환됐다. Apple 빌드 처리는 완료했으며 내부 테스트 그룹 배정·초대 후 실제 기기 설치 확인이 필요하다. 이번 빌드는 Apple 로그인이 비활성화된 초기 검수용이며, 최종 기능 활성화와 실제 iPhone 검수·정식 심사를 대신하지 않는다. CI 영수증의 `appleProcessingVerified=false`는 업로드 시점의 기록으로 보존하고 후속 콘솔 결과를 별도로 기록한다.

내부 그룹 `운영자 iPhone 검수`를 생성하고 자동 배포를 껐다. 처리 완료한 `1.0.0(1)`을 수동으로 연결했으며 그룹에 **0명의 테스터·1개의 빌드**, 빌드 상태 **테스트 준비 완료**를 확인했다. 테스터 초대는 아직 발송하지 않았다.

## 제출 정보의 현재 저장 상태

- 앱 개인정보 **15개 데이터 유형의 초안**을 사용자 승인 후 저장했다. **게시하지 않았으며** 최종 기능·서버 동작과 대조한 뒤 게시해야 한다.
- 연령 등급 설문은 사용자가 나중에 검토하기로 하여 **저장하지 않았다**. 실제 콘텐츠 빈도와 기능에 대한 최종 확인이 남아 있다.
- 제3자 콘텐츠 권리 확인은 저장했다. 저작권·대한민국 무료 배포·연락처 규정 준수와 기존 스토어 정보의 최종 대조는 심사 제출 전에 수행한다.

## 이어서 완료할 작업

1. `1.0.0(1)`이 연결된 내부 테스트 그룹의 초대 발송 후 실제 iPhone에서 가상 계정으로 설치·검수.
2. Apple 로그인 capability, 서버용 키·알림 수신 주소, V011 적용과 서버 설정·개인정보 문구 활성화. 실제 계정으로 로그인·연결 해제·계정 삭제·알림 연동을 검증.
3. 실제 기기 검수에서 발견한 문제를 수정하고 최종 기능을 포함한 빌드에 대해 검사·서명·업로드·설치를 다시 확인. 초기 검수용 빌드와 최종 심사 빌드를 구분.
4. 저장된 개인정보 15개 유형 초안을 최종 기능과 대조해 게시하고, 미저장 연령 등급 설문을 사용자 검토 후 완료. 심사 접근 정보·무료 가격·국가·저작권·대한민국 규정 준수 상태와 스토어 화면도 최종 확인.
5. 사용자 승인 범위에 따라 정식 앱 심사 제출. 심사 승인 후 저장한 수동 공개 방식으로 대한민국 무료 출시.

이 기록에는 실제 Apple 키·프로파일·비밀번호·심사 계정·비공개 전화번호·주소가 포함되어 있지 않다. 현재 자료 준비 상태를 정식 심사 통과나 출시 완료로 표시하지 않는다.
