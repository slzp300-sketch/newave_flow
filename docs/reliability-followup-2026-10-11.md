# 운영 점검 후 개선 결과 — 2026-10-11

디자인을 보류하고 조회 실패로 인한 기록 오입력 방지, 행사 오류 표시, 마감 안내, 앱 업데이트 안내, 실행 문서를 순서대로 개선했습니다. 운영 DB·명단·기존 기록을 바꾸는 작업은 포함하지 않았습니다.

## 1. 출석·TTS 조회 실패 시 입력 보호 — 완료

- 출석의 담당 반·학생·출석 기록·반 공동 제출 상태를 모두 읽은 뒤에만 입력·제출을 허용합니다.
- TTS 질문과 주간 기록 중 하나라도 실패하면 체크·점수를 숨기고 오류와 재시도를 표시합니다. 실제 0점과 조회 실패를 구분합니다.
- 처음 읽는 중, 재조회 중, 오프라인으로 요청이 멈춘 경우도 입력을 잠급니다.
- 출석 입력은 반·날짜별 초안으로 관리합니다. 주차를 바꾸면 이전 주 초안을 새 주에 제출할 수 없습니다. 같은 주의 재조회는 작성 내용을 유지합니다.
- 출석 제출 중에는 주 이동·입력을 잠급니다. TTS 저장 중에는 주 이동을 잠그고, 저장·실패 복원은 요청 당시 주차에 적용합니다.
- TTS 통계 조회 실패도 기록 없음과 구분합니다.

가상 503 장애에서 제출/체크가 없음을 확인했습니다. 재시도 후 기존 결석 사유·메모·TTS 월요일 체크와 5점이 복원됐습니다. 이전 주로 이동한 뒤의 조회 실패도 같은 방식으로 차단됐습니다.

관련 코드: `AttendancePage.jsx`, `TTSPage.jsx`, `QueryNotice.jsx`, `queryReadState.js`, `WeekNavigator.jsx`.

## 2. 행사 오류와 완료 표시 — 완료

- 행사 목록 조회 실패를 행사 없음으로 표시하지 않습니다.
- 학생·교사 출석 조회가 끝나기 전에는 행사 카드에 제출 완료를 표시하지 않습니다. 학생 명단 일부만 제출된 경우도 전체 완료로 표시하지 않습니다.
- 개별 행사 출석은 필요한 조회가 실패하면 입력을 잠그고 재시도를 제공합니다.
- 관리자 학생/교사 집계 조회 실패는 0명이나 미제출로 대체하지 않습니다.
- 행사 목록을 다시 읽다가 실패하더라도 이미 작성 중이던 패널 상태를 보존합니다.

가상 목록 오류 → 재시도, 학생/교사 기록 오류 → 복원, 관리자 두 집계 탭의 오류 → 복원을 확인했습니다. 기존 결석 사유·교사 부분참석 날짜와 메모가 유지됐습니다. 행사 수정 중 목록을 실패시켰다가 재시도했을 때 미저장 입력도 그대로 남았습니다.

관련 코드: `EventAttendanceListPage.jsx`, `EventAttendancePage.jsx`, `EventAttendanceAdminPage.jsx`.

## 3. 마감 안내 — 완료 및 앞선 분석 정정

앞선 보고서는 저장 요청을 구성하는 코드의 종료일 자동 대입을 빠뜨렸습니다. 실제 규칙은 다음과 같습니다.

- 개별 일정 폼: 마감일을 비우고 저장하면 일정 종료일을 마감일로 자동 대입합니다.
- 일괄 일정 폼: 출석이 필요한 행사는 종료일을 마감일로 저장합니다.
- 이미 저장된 행사: 명시적 마감일이 있으면 그날까지 제출 가능하고, 없는 기존 행사는 기한을 제한하지 않습니다.

업무 규칙을 바꾸지 않고 개별 일정 폼에 **저장할 때 종료일로 자동 설정됨**을 명시했습니다. 마감일이 없는 행사 출석 화면에는 **제출 기한 제한 없음**을 표시했습니다. 기존 행사에 새 마감일을 일괄 부여하지 않았습니다.

마감 당일/다음 날, 월말·연말, 마감일 없음, 화면을 열어 둔 뒤 날짜 변경의 기존 자동 검사를 통과했습니다.

## 4. 앱 업데이트 — 완료

- 자동 강제 갱신 대신 새 버전 안내와 사용자의 저장 확인 후 갱신을 제공합니다.
- 앱을 보고 있을 때 1분 간격, 앱으로 돌아올 때, 연결이 복구될 때 새 버전을 확인합니다.
- React Query로 기록을 저장 중이면 갱신 버튼을 잠급니다. 갱신 전에는 미저장 내용이 사라짐을 안내합니다.
- 다른 탭에서 업데이트를 적용해도 이 탭을 강제로 새로고침하지 않습니다.
- 처음 설치한 직후에도 새 서비스 워커가 활성화된 뒤 화면을 갱신합니다. 활성화가 지연되면 현재 화면을 유지하고 재시도 오류를 표시합니다.
- 내 정보의 고정 `v0.1.0`을 실제 빌드 식별자로 바꿨습니다. Vercel에서는 커밋 앞 7자리, 해당 값이 없는 로컬 빌드에서는 빌드 시각을 표시합니다.

로컬 완성 빌드 두 개를 실제로 교체해 검증했습니다. 첫 설치 탭은 `index-DR3b7ZG8.js`에서 `index-D9gbr4TB.js`로 확인 후 전환됐습니다. 다른 탭은 미저장 입력과 이전 코드를 유지하다가 그 탭에서 확인한 뒤 새 코드로 전환됐습니다. 자동 강제 갱신이 없었고 콘솔 오류도 없었습니다.

참고한 [Vite PWA의 업데이트 안내 방식](https://vite-pwa-org.netlify.app/guide/prompt-for-update.html)에 맞춰 대기 중인 서비스 워커를 사용자 확인 후 활성화합니다. 첫 설치 및 여러 탭에서의 입력 보호를 위해 앱이 등록·활성화 확인을 직접 관리합니다.

## 5. 실행 가이드 — 완료

`getting-started.md`를 PostgreSQL 운영, H2 로컬 개발, 명시적 실행 프로필, 기본 계정 생성 비활성, 가상 검수 데이터 원칙에 맞게 교체했습니다. 현재 유효하지 않은 공용 예시 계정·비밀번호를 제거했습니다.
