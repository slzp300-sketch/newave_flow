# 학년부장 ‘우리 학년’ 구현 — 2026-11-06

승인된 시안을 실제 화면과 서버에 연결했다. 로컬 개발·가상 자료 검증이며 **운영 DB 적용, 배포, 스토어 업로드, 커밋·푸시는 하지 않았다.** 기존 미배포 예배운영팀 및 공통 UI 변경을 유지한다.

## 화면 및 기존 자료 연결

- `/grade-care`: ‘체크 현황 / 학생 돌봄’. 현 연도 임원 조직도의 학년부장 직책에서 담당 학년을 자동 선택한다. 담당 학년이 여럿이면 전환한다. 공통 현황 권한을 가진 다른 임원은 학년을 선택해 기본 현황을 볼 수 있다.
- 홈 담당 업무와 임원 담당 업무 바로가기에 연결했다. 담당 교사는 기존 학생 상세의 ‘근황·기도제목 보기’에서 같은 공동 기록에 접근한다.
- 반 출석: 기존 주간보고서 제출 자료를 사용한다. 제출 완료 / 원본 변경 후 재제출 필요 / 미제출을 구분하며 새가족 인계 조정도 기존 집계 규칙을 사용한다.
- 교사 예배: 별도의 청소년부 예배 체크 원본. 교사회의: 해당 주 토요일의 기존 투표, 불참 사유, 공개 회의록 확인 여부. 새 확인 체크를 중복 입력하지 않는다.
- 행사 응답: 기존 행사 대상·등록 시점 명단과 응답을 사용하며 교사/학생을 구분한다. 행사 당시 학년을 사용하여 반 이동으로 과거 집계가 바뀌지 않게 한다.
- 학생: 현재 반에 배정된 활성 명단, 반·이름·학교 검색, 선택 주일까지 최근 4주 출석. 미기록·지각·배정 전을 결석으로 합산하지 않는다. 기존 학생 상세의 지각 표기도 수정했다.
- 근황·기도제목·연락 기록: 종류와 내용을 작성·수정하고 작성자·날짜를 확인한다. 후속 요청에 따라 안부 확인 숫자·필터·표시·체크 항목·버튼과 연속 결석에 따른 자동 제안을 제거했다. 기존 내용과 출결은 유지한다.
- 기도제목: 학생별로 작성·수정하여 함께 본다. 현재/지난 구분과 상태 전환 없이 기존 기록을 모두 보존하며, 이전 상태와 관계없이 명단의 기도제목 집계·검색에 포함한다.

### 기준일

- 선택 날짜는 이번 주 또는 과거 주일이며 화면은 최근 16주를 제공한다.
- 교사회의는 기존 앱의 주차에 맞춰 선택 주일 이후 토요일(주일 + 6일)을 사용하며 실제 회의 날짜를 화면에 표시한다.
- 반 제출 자료는 선택 날짜의 제출 스냅샷/변경 여부, 학생 돌봄 명단과 열람 권한은 현재 배정 기준이다. 학생 출석 요약 옆에 ‘현재 명단 기준’을 표시한다.
- 돌봄 기록은 현재 담당자가 이어서 관리한다. 새가족 과정 중 미배정 학생이나 배정 적용 전 학생은 이 기능의 대상이 아니다.

## 기록과 권한

- 열람·추가: 현재 담당 학년부장, 현재 담임/부담임, 목사, 관리자만 허용한다. 일반 임원이라는 이유만으로 상세 기록을 열 수 없다.
- 내용 수정: 작성자 또는 목사/관리자. 다른 담당자는 원문을 덮어쓰지 않고 새 기록을 남긴다.
- 조회·저장마다 현재 계정, 정지/비활성, 직책과 반 배정을 다시 확인한다. 학생의 반 이동이나 직책 해제 후 이전 담당자의 접근을 차단한다.
- 기존 교사 개인 `StudentMemo`를 가져오거나 공개하지 않는다. 공동 기록을 전체 기도제목, 주간보고서, 알림 본문에 자동 공개하지 않는다.
- 기록 종류: 근황(UPDATE), 기도제목(PRAYER), 연락·만남(CONTACT). 내용 1~4,000자, 작성자/시각, 변경 이력을 저장한다. 기존 안부/기도 상태 필드와 이력은 보존하되 표시·목록·집계의 구분 기준으로 사용하지 않는다. 내용 편집 시 이전 상태 정보를 덮어쓰지 않는다. 새 기록은 확인 상태나 완료 시각을 만들지 않는다.
- 변경 이력은 처리자·동작·시각만 저장한다. 수정 전의 민감한 내용을 별도 복제하지 않는다.
- 같은 기록을 동시에 고칠 경우 revision과 행 잠금으로 오래된 덮어쓰기를 거절한다. 입력 내용은 보존하고 최신 기록을 다시 열도록 안내한다.
- 응답은 `Cache-Control: no-store`. 로그인 계정별 조회 키, 상세 창을 닫으면 캐시 제거, 재접속·주기적 권한 재확인, 오류 시 기존 내용 숨김을 적용했다.
- 기존 개인정보 검토 범위와 계정 삭제 참조 처리를 확장했다. 탈퇴 시 공동 기록의 작성자/이력 참조를 해제하며 내용은 기존 검토 결정에 따라 처리한다.

## 디자인

- 기존 담당 업무 제목 색, 학년 색상, 공통 선택 목록, 작은 통계 카드, 검색·분할 버튼, 펼치기 디자인과 애니메이션을 사용한다.
- 학생/교사 목록은 작은 행으로 정리하고 상세에서만 기록과 사유를 연다.
- 제목·닫기와 하단 저장/취소를 고정하고 본문만 스크롤한다. 긴 문구 줄바꿈, 320px/375px 가로 넘침과 버튼 위치를 확인했다.
- 불필요한 반복 안내는 줄이고 기록 공유 범위만 입력 화면에 짧게 표시한다.

## 코드와 DB 변경

- 화면: `frontend/src/pages/GradeCarePage.*`, `components/grade-care/StudentCareDialog.jsx`, `api/gradeCare.js`, `utils/gradeCare.js`.
- 서버: `GradeCareController`, `GradeCareService`, `StudentCareRecord/StudentCareChange` 및 저장소.
- API: `/api/grade-care/access`, `/api/grade-care?grade=&date=`, `/events/{id}?grade=`, `/students/{id}/access`, `/students/{id}`, `/students/{id}/records`, `/students/{id}/records/{recordId}`. 상태를 변경하는 `/state` 경로는 후속 간소화에서 제거했다.
- 새 SQL: `backend/db/migrations/V027__grade_student_care.sql`. V026 이후 적용한다. 운영에는 V026과 V027 모두 미적용 상태다.
- 두 새 표만 추가하고 기존 출석/보고서 구조를 변경하지 않는다. 트랜잭션·중복 적용 차단·학년 기록 색인을 포함한다.

## 검증

- 프런트 검사 274개 통과, 웹 빌드 성공. 기존 큰 청크 경고는 남아 있으나 빌드 실패는 없다.
- 서버 전체 build 성공: 319개 중 300개 통과, 별도 환경용 19개 제외, 실패 0.
- 새 HTTP 검사 8개: 권한 행렬, 비공개/개인 메모 비노출, 담당 변경·이동·정지, 내용 수정 권한, 동시 수정 충돌, 제출/변경 상태, 예배·회의·회의록 연결, 행사 대상·등록 명단, 입력 검증.
- 새 PostgreSQL 검사 1개: 전환 실패 롤백, 기존 표 지문 보존, 중복 적용 차단, 내용 검토 범위, 작성자 참조 해제, 개인정보 삭제용 빈 내용 허용, 실제 JPA 스키마 검증.
- PostgreSQL 18.6의 **새 가상 DB**만 사용했다. 검사 완료 후 이 전용 서버를 종료했다. 운영 복원본 리허설이나 PostgreSQL 17 검사를 실행한 것은 아니다.
- 최초 로컬 API와 UI 검증: 기록 생성→수정→안부 확인→새로고침 유지→담당 교사 동일 내용 조회. 관계없는 임원의 상세 진입 차단, 교사회의 불참 상세, 행사 응답 연결 확인. 후속 변경에서는 이전에 ‘지난 기도’로 표시한 기록도 상세와 기도제목 명단에 계속 포함됨을 확인한다.
- 375×812·320×600에서 명단, 기록 상세/입력, 선택 목록, 하단 버튼과 가로 넘침을 확인했다. 실제 iPhone 키보드나 네이티브 빌드는 이번에 검수하지 않았다.

## 후속: 기도제목 구분 제거

- 현재/지난 탭·표시·전환 버튼을 제거했다. 상세는 모든 기록을 보이고, 기도제목 학생 집계는 이전 상태와 무관하게 모든 PRAYER 기록을 포함한다.
- 기존 상태 필드와 이력은 데이터 보존을 위해 남겼다. 새 화면에서는 상태 전환을 호출하지 않는다. 근황·연락 기록의 안부 확인과 공유 권한은 유지한다.
- 최종 프런트 274개 및 웹 빌드 성공. 서버 319개 중 299개 성공·환경 전용 20개 제외·실패 0. DB 구조 변경이 없어 PostgreSQL 전환 검사는 이 후속 작업에서 반복하지 않았다.
- 갱신 전 가상 상세 13개를 보존하고 최신 가상 서버에서 기록 3개의 내용·작성자·시각·수정 순번과 변경 이력 수가 동일함을 확인했다. 이때만 사용하는 `.verification/grade-care-preview-records.json`은 실제 자료가 아니며 저장소에 포함하지 않는다. 다음 재시작 전에도 최신 가상 입력을 보존해야 한다.
- 375px에서 기존 기도 내용 유지, 구분 탭·전환 버튼 없음, 가로 넘침 없음과 브라우저 오류 없음을 확인했다. 미배포 상태를 유지한다.

## 후속: 안부 확인 제거, 기록만 유지

이 후속 결과가 앞선 안부 확인 유지 설명보다 우선한다.

- 사용자 요청에 따라 안부 확인 버튼·체크박스·표시·명단 필터·요약 수와 연속 결석에 따른 자동 제안을 제거했다. 상태 변경 API도 제거했다.
- 근황·기도제목·연락/만남을 작성·수정하고 최근 출석을 볼 수 있다. 불필요한 ‘기록 관리’ 펼치기는 없애고 작성자의 기록에 ‘내용 수정’을 바로 표시한다. 학생 상세 진입은 ‘학생 기록 보기’다.
- 원래 내용·작성자·시각·수정 순번과 이전 상태/변경 이력을 그대로 보존했다. 내용 수정은 이전 상태를 덮어쓰지 않으며 새 연락 기록도 자동 확인 처리하지 않는다. 화면의 변경 이력에는 작성·수정만 표시한다. 공유 범위는 그대로다.
- 가상 서버 갱신 전후 학생 상세 13개와 원래 기록 3개의 내용·작성자·시각·상태·전체 변경 이력이 동일함을 확인했다. UI에서 새 연락 기록을 저장·수정한 뒤 총 4개 기록을 다음 미리보기용으로 보존했다. 실제 자료 변경은 없다.
- 프런트 검사 274개와 웹 빌드 성공. 서버 전체 build 성공: 총 319개 중 299개 성공, 환경 전용 20개 제외, 실패 0. HTTP 검사에서 이전 상태 보존·작성자 권한·동시 수정 충돌·자동 기록 미생성을 확인했다. DB 구조 변경이 없으므로 PostgreSQL 전환 검사는 재실행하지 않았다.
- 375×812에서 입력/저장/수정·고정 하단 버튼, 학년부장 현황/명단의 안부 항목 제거, 가로 넘침 없음과 브라우저 오류 없음을 확인했다. 실제 iPhone 검수는 하지 않았다.
- 커밋·푸시·배포·운영 DB 변경 없이 로컬 미리보기만 갱신했다.

## 후속: 변경 이력 화면 제거

- 학생 기록 상세의 ‘변경 이력’ 펼치기와 목록을 제거했다. 근황·기도제목·연락/만남의 내용·작성자·작성 시각·내용 수정은 유지한다.
- 서버의 기록과 과거 변경 이력은 삭제하지 않았다. 화면 표현만 변경했으며 API·DB·공유 범위는 그대로다.
- 375px 미리보기에서 기존 내용 유지, 변경 이력 없음과 가로 넘침 없음을 확인했다. 배포하지 않았다.
