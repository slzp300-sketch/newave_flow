## 단계 1 — 계정·권한

- 개인정보만으로 비밀번호를 발급하던 공개 API를 차단했습니다. 최종 관리자에게 본인 확인 후 발급 기능을 제공하며 비밀번호 찾기 화면도 안내 방식으로 맞췄습니다.
- 토큰 용도(access/refresh), 계정 활성 상태, 현재 역할, 세션 버전을 검사합니다. 비밀번호 변경·권한 변경·로그아웃 시 기존 세션은 무효화합니다.
- 일반 교사의 직접 제적·복적을 차단하고 학생 수정·메모·제적 신청·출석·보고서 저장에 담당 반 검사를 추가했습니다.
- 운영 프로필에서 명단 초기화·고정 계정 관리자 재승격을 제거했습니다. 초기 비밀번호 하드코딩을 제거하고 개발 시딩도 명시적으로 켜야 실행되도록 했습니다.
- 기존 실제 명단 출력 테스트를 가상 데이터 저장 검사로 교체했습니다. 백엔드 전체 빌드와 검사 11개(보안 8, 주차 2, 가상 반 저장 1), 프런트 빌드가 통과했습니다.
- 충돌 점검: 비밀번호 변경 후 재로그인 화면 이동, 일반 교사의 복적 버튼 비활성화를 함께 반영했습니다. 만료 응답은 다음 단계의 갱신 흐름과 맞도록 401로 통일했습니다.
- 배포 영향: 기존 형식의 토큰은 거절되므로 전원 한 번 재로그인이 필요합니다. users.auth_version 기본값 0 열이 추가됩니다. 운영의 명시적 prod 프로필·DB 환경변수·JWT_SECRET 확인이 필요합니다. 현재 운영 설정은 변경하지 않았습니다.
- 화면 브라우저 검수와 전체 회귀 검사는 마지막 단계에서 수행했습니다. 상세 범위는 아래 최종 검증 기록을 참고하세요.

## 단계 2 — 저장·로그인 안정성

- 통신 오류 자동 재시도는 GET/HEAD에만 적용합니다. POST 저장은 응답이 끊겨도 자동 반복하지 않습니다.
- 로그인 갱신을 공통 Promise로 합쳐 동시 요청의 성공·실패가 모두 종료되도록 했습니다. 갱신 중 통신 장애는 로그인 정보를 지우지 않으며, 로그아웃 후 늦게 온 갱신 응답도 세션을 복원하지 못합니다.
- 일정 생성·일괄 등록·학년 진급은 작업 번호와 결과를 같은 DB 트랜잭션에 기록합니다. 같은 번호·내용을 다시 보내면 기존 결과를 반환하고, 다른 내용을 같은 번호로 보내면 거절합니다.
- 전도조 이동은 한 API·한 트랜잭션으로 처리합니다. 조 변경을 직렬화하고 오래된 출발 조 정보를 거절합니다. 삭제한 조는 개인 소속 조회에서 제외합니다.
- 일정 생성/수정의 날짜 규칙, 행사 출결 상태·부분 참석일·불참 사유, 일반 출석과 회의 상태를 서버에서도 검증합니다.
- 검증: 백엔드 전체 빌드 및 15개 검사, 프런트 11개 검사와 빌드 통과. 이전 단계 보안 검사도 함께 통과했습니다.
- 배포 영향: completed_operations 테이블 추가. 일정 생성·진급은 새 프런트가 보내는 Idempotency-Key가 필요하므로 구형 화면은 새로고침해야 합니다. 수동으로 새 작업 번호를 발급해 다시 제출하는 별도 작업까지 같은 요청으로 간주하지는 않습니다.

## 단계 3 — 공동 출석·과거 기록 보존

- 보고서의 고유 기준을 반+날짜로 통일했습니다. 담임·부담임이 같은 보고서를 수정하고 제출하며, 작성 교사는 최종 수정자로 기록합니다. 홈의 주간 완료와 교사별 미제출 집계도 담당 반의 제출 상태를 공유합니다.
- 출석 저장·보고서 집계는 같은 원본 출석을 사용하고, 반 잠금으로 동시 최초 저장을 보호합니다. 보고 메모가 출석 수정으로 지워지던 부분도 보존하도록 했습니다.
- 출석 행사 등록 시 학생·교사의 이름·반·학년 명단을 별도 저장합니다. 이후 학생 제적·반 이동·신규 등록이 과거 행사 인원과 소속을 바꾸지 않습니다.
- TTS 항목·배점·자동 연동 규칙에 적용 주차별 버전을 추가했습니다. 관리자 변경은 다음 주부터 적용되며 이전 주 기록은 당시 규칙으로 계산합니다. 주차를 이동하면 화면의 질문·배점도 해당 주 기준으로 불러옵니다.
- 구형 일괄 TTS 저장은 거절하고 새 저장 경로를 안내합니다. 잘못된 요일 키는 거절하며 GET 조회가 빈 기록을 생성하지 않도록 했습니다.
- 검증: 담임·부담임 저장 후 보고서 1개·인원 1회 집계, 학생 이동/제적 후 행사 명단 유지, 직접 체크와 회의 자동 연동 점수의 과거 배점 유지, 구형 API/잘못된 요일 거절을 가상 DB에서 확인했습니다. 백엔드 19개 검사와 양쪽 빌드가 통과했습니다.
- 전환 한계: 기존 데이터에 과거 명단·배점 이력이 없으므로 변경 이전의 정확한 과거값을 새로 만들어낼 수 없습니다. 전환 시점 값을 기준선으로 보존하고, 기존 행사에 실제 출석 기록이 있는 비활성 인원도 포함하는 SQL 전환 절차를 준비합니다.
- 배포 전 반별 중복 보고서 원본을 보관한 뒤 통합하고 새 고유 제약을 적용해야 합니다. 이 작업은 운영에서 아직 실행하지 않았습니다.

## 단계 4 — 캐시·성능·자동 검사·운영 절차

- 홈과 달력의 일정 조회 키를 실제 시작일·종료일로 구분했습니다. 화면 방문 순서 때문에 조회 범위가 뒤섞이던 문제를 검사로 재현하고 차단했습니다.
- 반·학생·교사·행사·전도조·모임 저장 후 관련 화면 캐시를 함께 갱신합니다. 개별 TTS 체크 저장은 낙관적 표시와 충돌하지 않도록 이 일괄 갱신 규칙에서 제외했습니다.
- 35개 페이지를 필요한 시점에 불러오도록 분리했습니다. 주요 JavaScript 파일은 약 973KB에서 432.47KB(압축 143.11KB)로 감소했습니다. 실제 사용자 체감 시간·PWA 전체 다운로드량을 측정한 결과는 아닙니다.
- 주간 출석의 담임 조회와 회의록 목록의 확인/참석 조회를 반복 호출 대신 일괄 조회로 바꿨습니다. 모든 조회의 성능 검증이나 대량 데이터 부하 검사를 완료했다는 뜻은 아닙니다.
- `npm test`, `npm run check`와 GitHub 검사 workflow를 추가했습니다. 운영용 DB 설정은 자동 변경 대신 구조 검증(`validate`)으로 전환했습니다.
- SQL 전환 파일에 보고서 원본 보관, 반별 통합, 행사 명단·TTS 규칙의 최초 기준선, 스키마 버전 기록을 포함했습니다. 운영 반영·실패 시 복원 절차를 별도 문서로 정리했습니다.

## 최종 교차 점검에서 보완한 사항

- 헤더의 로그아웃도 서버 세션 종료 API를 호출하도록 맞췄습니다. 만료된 접속 토큰은 갱신 후 로그아웃할 수 있으며, 잘못된 로그인 비밀번호는 갱신 대상으로 처리하지 않습니다. 서버 통신이 실패하면 로컬 로그아웃만 됐음을 알립니다.
- 비밀번호 재설정·변경·로그아웃·역할 변경은 사용자 행 잠금으로 세션 버전 변경을 직렬화했습니다.
- 일정 종류·참석 대상의 허용값을 요청 경계에서 검증합니다.
- 375px 관리자 화면에서 발견한 카드 애니메이션의 React ref 경고를 수정하고 재확인했습니다. TTS 항목 관리에 다음 주 적용 안내를 저장 전에도 표시했습니다.

브라우저의 로그인 필요 화면은 실제 페이지 컴포넌트에 가상 API 응답을 연결한 로컬 검수 화면으로 확인했습니다. 실제 API 저장·관리자 비밀번호 발급을 브라우저에서 실행한 종단 간 검사는 아닙니다. 해당 저장 규칙은 백엔드 검사로 확인했습니다. 실제 계정, 운영 DB, 학생 명단 파일은 사용하지 않았습니다.

검수 중 확인한 React 경고는 수정 후 재확인에서 사라졌고, 관리자·반 관리·TTS 화면의 가로 폭은 375px로 넘침이 없었습니다. 서버 전체 기동 검사에서도 명단 초기화 컴포넌트가 생성되지 않고 계정이 자동 생성되지 않는 것을 확인했습니다.

빌드의 비차단 안내로 Browserslist 데이터 갱신과 Gradle 9 호환성 안내가 남아 있습니다. 이번에는 의존성의 대규모 버전 변경을 섞지 않았습니다.

## 운영 반영 후 안내

1. 보안키와 토큰 형식이 바뀌었으므로 기존 사용자는 다시 로그인해야 합니다. 설치형/PWA에서 이전 화면이 남으면 앱을 완전히 닫고 다시 열어 새 버전을 받습니다.
2. 기존 데이터에 없는 과거 명단·배점은 전환 시점 기준선으로 보존합니다. 전환 이후부터 행사 등록 당시 명단과 적용 주차별 배점 이력을 유지합니다.
3. 이번 운영 확인은 상태·접근 차단·공개 화면 확인 범위입니다. 실제 학생·교사의 저장·제출·삭제를 시험하지 않았으며 업무 저장 규칙은 합성 회귀 검사와 복원본에서 확인했습니다.

디자인 작업은 계속 보류하며, 자료 수신 후 재개합니다.

## 후속 — PostgreSQL 전환 검증 (2026-10-10)

- Windows 서비스나 전역 프로그램 설치 없이 Git에서 제외한 검증 폴더에 로컬 PostgreSQL 17.10을 준비했습니다. 접속은 루프백 전용입니다.
- 변경 전 커밋의 엔티티 소스만 추출해 기존 스키마를 재현했습니다. 실제 명단 파일과 구버전 초기화는 실행하지 않았습니다.

## 출석·행사 체크 화면 유지 개선 (2026-10-12)

- 주일 출석과 행사 목록/상세의 학생·교사 체크를 점검했습니다. 브라우저 자체의 새로고침이 아니라, 저장 후 재조회(`isFetching`)를 최초 로딩과 동일하게 처리해 입력 화면이 사라졌다가 다시 나타나는 문제가 있었습니다. 관리자 출석 화면은 조회용이며 이번 수정 대상 저장 기능이 없습니다.
- 이미 읽은 기록은 재조회 중에도 화면에 유지하고 작은 확인 안내를 표시합니다. 최초 조회 실패는 입력 화면을 열지 않으며, 재조회 실패·연결 중단 시에는 기존 내용과 오류/재시도를 함께 보여 주고 저장을 막습니다. 공통 `queryReadState`의 엄격한 저장 보호 규칙은 유지했습니다.
- 행사 폼에서 조회 결과 변경마다 입력을 초기화하던 효과를 제거했습니다. 행사·계정별 초안으로 사유, 부분참석 날짜·메모와 수정 상태를 보존합니다. 명단이 변경되면 제외된 학생은 제출 대상에서 제거하고 새 학생은 서버 기록으로 초기화합니다.

- 대상: 운영 버전 `778bb3b`. Chrome의 375px·320px 화면에서 관리자 메뉴에 연결된 13개 관리 페이지를 조회했습니다. 좁은 화면은 실제 `window.innerWidth=320`과 본문 폭 305px(스크롤바 제외)을 확인했습니다. 가로 넘침·조회 오류·운영 콘솔 오류는 없었습니다. 이 결과는 실제 iPhone/Android 기기 검수를 대신하지 않습니다.
- 운영 출석 화면과 공동 기록 안내, 행사 목록/상세의 교사·학생 영역, TTS 내 체크·주간 상세·분기 순위·내 추이를 확인했습니다. 41주차는 시트 총점과 항목별 내역 미제공 안내가 표시됩니다. 운영 저장·제출·승인·삭제는 실행하지 않았습니다.
- 프런트 자동 검사 **53개 통과**. 가상 자료의 `test` 프로필로 출석/행사 이력·저장·권한·TTS 주간/상세/분기 서버 검사 **33개 통과**(6개 검사 클래스, 실패·생략 0). 이번에는 DB 전환 검사를 재실행하지 않았으며 앱 코드/DB/배포 설정은 변경하지 않았습니다.
- 실제 화면과 가상 API 검수: 출석 저장 이후 제출 실패 시 완료 처리하지 않고 불참 사유를 유지했으며, 연결 복구 후 출석 3명·불참 1명으로 반 4명 공동 제출이 완료됐습니다. 검색 중에도 반 전체 제출 안내를 확인했습니다.
- 행사: 느린 교사 불참 저장 중 학생 폼·사유 유지, 교사 불참 제출과 학생 4명 제출 완료, 재조회 실패 시 기존 완료 기록·오류/재시도 표시와 수정 잠금을 확인했습니다. 부분참석 날짜 미입력 시 제출 차단도 확인했습니다. 네이티브 날짜 선택기 입력 완료와 부분참석 제출 전체 흐름은 이번 브라우저 검수에서 확인하지 못했으므로 실제 휴대폰 점검에 포함합니다. 부분참석 날짜 유효성·이력 보존은 서버 자동 검사 범위에 포함됩니다.
- TTS: 느린 연속 체크 즉시 반영→자동 저장 완료까지 본문 유지, 저장 실패한 체크만 복구·기존 체크 보존, 오류 안내와 연결 복구 후 재체크 성공을 확인했습니다. 관리자 점수 목록 2페이지에서 이름 검색 시 결과 1명으로 줄면서 전체 12명·미달 7명 집계는 유지됐습니다.
- 남은 개선 1 — 반 배정 팝업: 저장 버튼에서 Tab을 누르면 뒤쪽 하단 ‘홈’ 메뉴로 초점이 이동하고 Escape로 닫히지 않습니다. 열 때/닫을 때 초점 이동, 팝업 내부 Tab 순환, 배경 접근 제한을 함께 보완할 필요가 있습니다. 근거: `frontend/src/pages/AdminClassManagePage.jsx:255~278` 및 가상 팝업 키보드 재현.
- 남은 개선 2 — 작은 보조 버튼: 반 배정 ‘배정 해제’는 큰 글씨에서도 약 35×35px입니다. 앱의 주요 버튼과 동일한 최소 44×44px 터치 영역으로 맞추는 것이 좋습니다. 320px 큰 글씨에서는 팝업 제목도 여러 줄로 나뉘어 제목·닫기 버튼 배치를 다듬을 여지가 있습니다. 근거: 같은 파일 317행의 `p-2` 버튼과 실제 요소 크기 측정.
- 남은 개선 3 — 행사 날짜 입력 이름: ‘참석 시작일’ 글자는 보이지만 날짜 입력과 연결되지 않아 접근성 트리에서 이름 없는 입력으로 나타납니다. 교사/학생별 고유 id와 label 연결 또는 명확한 aria-label을 추가해야 합니다. 근거: `frontend/src/pages/EventAttendancePage.jsx:248~250,471~478`.
- 권장 순서: 팝업·터치 영역·입력 이름 보완 → 실제 iPhone Safari/Android Chrome 및 홈 화면 설치 앱에서 키보드·날짜 선택기·복귀/업데이트 확인. 이번 점검 범위에서 출석·행사·TTS의 사용을 막는 회귀 오류는 발견하지 못했습니다.

## 팝업·터치 영역·행사 입력 접근성 개선 (2026-10-12)

- 1단계 완료: 반 배정 팝업을 네이티브 모달로 전환했습니다. 열 때 닫기 버튼으로 초점 이동, Tab/Shift+Tab 순환, Escape·닫기·취소, 닫은 뒤 원래 반 카드로 초점 복귀를 확인했습니다. 배경 접근·스크롤 및 팝업에서 시작한 페이지 당겨서 새로고침을 차단합니다. 교사 추가·승격·해제로 집중된 버튼이 사라져도 초점이 팝업 안에 남습니다.
- 배정 저장 중에는 입력·중복 저장·닫기·Escape를 잠급니다. 느린 가상 저장 성공 후 반 카드의 새 담임 표시, 저장 실패 시 팝업·배정 초안 유지와 재시도 가능 상태를 확인했습니다. 배정 후보 제외 및 담임/부담임 규칙은 그대로입니다.
- 2단계 완료: 배정 승격·해제·추가 취소 및 행사 학생 상태/제출 후 수정 버튼을 최소 44×44px로 확대했습니다. 대상 이름과 선택 상태를 접근성 이름/aria-pressed로 제공합니다. 좁은 화면에서는 버튼과 교사·학생 정보를 줄바꿈하며 팝업 제목과 닫기 버튼이 겹치지 않게 조정했습니다. 320px 큰 글씨에서 배정 버튼 약 53×53px, 가로 넘침 없음, 추가·승격·해제·행사 상태 전환 정상 동작을 확인했습니다.
- 3단계 완료: 행사 날짜·메모·사유 입력을 교사/학생별로 구분했습니다. 고유 id와 label을 연결하고 필수값을 명시했습니다. 내 날짜 10/17, 학생 A 10/18, 학생 B 10/17을 실제 날짜 선택기 키보드 입력으로 기록해 교사·학생 부분참석 제출 후 다시 수정해도 서로 다른 날짜와 메모가 유지됨을 확인했습니다. 이전 검수에서 남았던 부분참석 날짜 입력·제출 브라우저 확인을 완료했습니다. 행사 날짜 범위·마감·점수·명단 보존 규칙은 변경하지 않았습니다.
- 회귀 검수: 출석 한 명만 검색한 상태에서 숨겨진 불참 사유를 포함한 반 4명(출석 3명/불참 1명) 공동 제출 완료, TTS 느린 연속 체크의 즉시 반영·자동 저장 완료 및 본문 유지 확인. 운영 기록은 수정하지 않았습니다.
- 자동 검사: 프런트 53개 통과 및 운영 빌드/PWA 생성, 서버 전체 빌드 성공(35개 통과, 별도 PostgreSQL 환경이 필요한 전환 검사 1개 생략). DB·서버 코드·권한 정책 변경은 없습니다. main 운영 배포와 배포 후 조회 점검은 사용자의 이번 요청에 따라 이어서 진행합니다.
- 실제 iPhone/Android 및 설치형 앱에서의 터치·키보드·복귀 점검은 별도입니다. 이번 변경은 앞선 모바일 감사의 개선 1~3을 해결합니다.
