# 심사용 가상 환경

2026-10-13. 로컬 구현·HTTP 격리 검사·375px 화면 검수를 완료했다. 온라인 심사 서버는 추가 사용량 과금 승인 후 배포한다. 이 문서는 온라인 배포나 Google 심사 접근 제출 완료를 뜻하지 않는다.

## 격리 방식

- 운영과 같은 화면·업무 서비스 코드를 별도 `review` 서버에서 실행한다. 심사 서버는 전용 H2 파일 DB를 사용하고 운영 PostgreSQL 접속값을 갖지 않는다.
- `review` 프로필만 단독으로 사용한다. DB/H2 콘솔 초기화 전에 실행되는 `ReviewEnvironmentGuard`가 혼합 프로필, PostgreSQL 접속값·운영 JWT/OAuth 키, 실제 명단 초기화와 H2 콘솔 활성화를 거부한다.
- `bootReviewJar`와 별도 Dockerfile은 실제 `roster_data.json`을 포함하지 않는다. `prepare-deployment.ps1`도 Java 소스와 필요한 설정만 복사한다. 실제 명단·DB 사본·암호 파일은 심사 호스팅에 올리지 않는다.
- 심사 JWT는 별도 난수 키와 `newave-flow-review` 발급자를 사용한다. 운영은 `newave-flow` 발급자만 수용하되 기존 발급자 없는 운영 토큰은 만료 시까지 호환한다. 양쪽의 사용자 ID가 같거나 서명 키를 실수로 같게 설정해도 다른 발급자 토큰은 거부한다.
- 심사 계정 이메일은 `@review.newaveflow.invalid` 예약 영역이다. 일반 이메일 로그인은 운영 API를 사용하고, 심사 영역 로그인은 운영 서버가 안내한 HTTPS 심사 API를 사용한다. 운영 서버는 심사 영역의 일반 가입·로그인을 거부한다.
- 선택한 환경은 안전한 세션 저장소에 보존한다. 읽기·쓰기·로그인 갱신·로그아웃에 같은 환경을 사용하며 심사 서버 오류 시 운영 API로 대체하지 않는다. 환경·사용자 변경 후 늦게 도착한 응답과 재시도는 거부한다. 로그아웃 시 일반 환경으로 돌아간다.
- 화면 상단에 ‘가상 심사 환경 · 실제 회원·학생 자료와 분리됨’을 표시한다. 심사 서버에는 카카오 비밀키를 두지 않으며 제공된 이메일 계정으로 검수한다.

## 계정과 가상 자료

| 구분 | 로그인 ID | 권한·자료 |
| --- | --- | --- |
| 교사 | `play.teacher@review.newaveflow.invalid` | 승인된 교사, 가상 1반 담임, TTS·출석·보고·행사·일정 |
| 관리자 | `play.admin@review.newaveflow.invalid` | 승인된 최종 관리자, 가상 자료의 모든 관리 기능 |

실제 인물·사진·연락처를 복사하지 않는다. 가상 학생 8명·반 2개, 가상 동료 교사와 승인 대기 교사, 이전 주 출석·공동 보고서, 예시 회의록, 직접 체크 TTS 7항목, 접수 중인 예시 행사를 생성한다. 예시 일정은 시작/매일 한국 시간 자정 이후 갱신해 검수 기간이 지나도 확인할 수 있게 한다. 일반 저장 기록은 재시작 후 유지한다.

실제 심사용 암호는 OneDrive 밖 사용자/SYSTEM 접근 제한 폴더의 `review-access.txt`와 DPAPI 암호화 `review-secrets.dpapi`에 보관한다. 노션·Git·공개 등록정보에는 암호를 적지 않는다. 로컬 UI 검수는 `-SyntheticTestCredentials`의 별도 시험 암호만 사용하며 배포용 암호 파일을 바꾸지 않는다.

## 서버 배포 설정

| 설정 | 값/용도 |
| --- | --- |
| `SPRING_PROFILES_ACTIVE` | `review` |
| `REVIEW_DATA_DIR` | 전용 볼륨의 `/data` |
| `REVIEW_DATABASE_PASSWORD` | 별도 난수, 비밀 변수 |
| `REVIEW_JWT_SECRET` | 운영과 다른 난수, 비밀 변수 |
| `REVIEW_TEACHER_PASSWORD` | 가상 교사 로그인 암호, 비밀 변수 |
| `REVIEW_ADMIN_PASSWORD` | 가상 관리자 로그인 암호, 비밀 변수 |
| 인스턴스 | 1개, H2 파일 볼륨을 여러 프로세스가 공유하지 않음 |
| 운영 서비스 `REVIEW_API_URL` | 심사 서버를 검증한 뒤 `https://<심사서비스>.up.railway.app/api`만 설정 |

운영의 `PG*`, `JWT_SECRET`, 카카오 키, 실제 초기화 비밀번호는 전달하지 않는다. 계정/프로젝트 공통 변수도 이름과 전달 범위를 확인한다. 플랫폼 과금은 실제 RAM·CPU·저장공간·통신량에 따른다. 로컬 메모리 약 300~350MB는 참고치이며 온라인 청구액이나 고정 비용을 보장하지 않는다. 요금제 변경·추가 결제·결제수단 변경은 이 구현에 포함하지 않는다.

배포 준비 예시(암호 없이 실행):

```powershell
./tools/review/prepare-deployment.ps1 -OutputDirectory <새 임시폴더>
```

빈 새 경로만 허용한다. 기존 폴더를 삭제하거나 실제 명단을 복사하지 않는다. 이 폴더만 심사 서비스의 Docker 빌드에 전달한다. 운영 서비스와 DB 스키마를 바꾸는 SQL은 없다.

## 검증 근거

- `ReviewEnvironmentTest`: 운영 접속값/프로필 혼합/실제 초기화/H2 콘솔 차단, 발급자가 다른 access·refresh 토큰의 양방향 거부, 기존 운영 토큰 호환.
- `ReviewIsolationHttpTest`: 실제 HTTP 심사 서버와 가상 운영 경계에서 동일 ID의 교사·관리자 토큰 읽기/쓰기/갱신 차단, 심사 DB만 수정, 재시작 후 8명과 수정 내용 유지, 실제 명단 초기화 빈 없음.
- 프런트 73개 검사: 심사 API 선택, 운영 토큰을 심사 로그인에 첨부하지 않음, 갱신/로그아웃의 환경 보존, 서버 실패 시 운영으로 대체 없음, 환경 변경 후 늦은 응답 거부.
- 실제 패키지에서 혼합 프로필을 거부함을 확인했다. `verify-bundle.py`로 명단·개인 키 미포함 및 초기 설정 차단 등록을 확인했다.
- 375px 브라우저: 가상 교사 홈 TTS 0→5 저장·새로고침 유지, 가상 1반 출석 3명/불참 1명 제출·홈 완료 동기화, 로그아웃·관리자 재로그인, 관리자 가상 학생 8명/목록 보기. 가로 넘침·확인한 흐름의 새 콘솔 오류 없음. 기존 React Router 경고는 남아 있다.
- Android 버전 코드 2의 native 빌드·`bundleRelease`·`lintRelease` 성공. 실제 Note9 설치나 Play 업데이트 설치 완료를 뜻하지 않는다.
- 화면 증빙: `frontend/.verification/review-isolation/`. 배포용 암호는 화면 캡처나 콘솔 출력에 포함하지 않는다.

## Google 심사 접근 안내 준비

앱 액세스에 제공할 안내: 이메일 로그인에서 위 계정 중 하나의 전체 이메일과 비공개 암호를 사용한다. 전체 이메일 붙여넣기를 지원하며, 직접 입력 시 도메인은 `review.newaveflow.invalid`다. 관리자 승인이나 카카오 인증 없이 바로 들어갈 수 있다. 화면 상단의 가상 환경 표시를 확인한다. 가상 반·학생·예시 행사의 조회·저장·관리 기능을 검수할 수 있다.

온라인 배포 후 해당 로그인·저장·토큰 경계를 다시 검증하고 새 AAB를 내부 테스트로 게시한다. 실제 암호를 Google Play 앱 액세스에 제공하는 단계와 온라인 배포 결과는 완료 후 이 문서에 추가한다. 새 AAB는 운영 일반 계정의 서버 선택을 유지하며 기존 USB 검수폰을 삭제하거나 초기화하지 않는다.
