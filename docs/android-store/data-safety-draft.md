## 입력 기준

서버에 저장하는 개인정보와 업무 기록이 있으므로 ‘데이터를 수집하지 않음’으로 제출하면 안 된다. SDK와 서버까지 포함해 실제 동작과 일치해야 한다. 앱 권한이 인터넷 하나라는 사실은 개인정보 수집이 없다는 의미가 아니다.

| Play 분류 후보 | 이 앱의 근거 | 목적 / 필요성 초안 |
| --- | --- | --- |
| 개인정보: 이름·이메일·사용자 ID | 교사 계정과 승인·권한 | 계정 관리, 앱 기능 / 필수 |
| 개인정보: 전화번호 | 교사 선택 입력, 학생·보호자 연락처 | 연락·반 관리 / 계정 본인의 입력은 선택, 다른 사람 정보 입력 절차 확인 |
| 개인정보: 주소 | 학생 주소 | 반 관리 / 선택 여부 운영 확인 |
| 개인정보: 기타 | 생년월일·성별·학교·학년·직분 | 계정 및 반 관리 / 항목별 확인 |
| 개인정보: 종교적 신념 | 교회 소속·세례·예배·기도·말씀 실천 | 영성체크·사역 기록 / 종교 관련 정보 분류 검토 필수 |
| 사진 | 교사·학생 프로필 사진 | 프로필 표시 / 선택 |
| 앱 활동: 기타 사용자 생성 콘텐츠 | 출결 사유, 공동 보고, 회의록·전도·새친구 기록 | 앱 기능 / 사용 기능에 따라 입력 |
| 앱 활동: 상호작용·기타 활동 | 일정 확인 상태, 체크 응답·수정 시각 | 앱 기능 / 일부 자동 기록 |
| 캘린더 | 앱에서 만든 일정·참석자 | 앱 기능 / 단말 캘린더를 읽지는 않음. Play 분류 적용 여부 확인 |

학생·보호자의 정보를 교사가 입력하는 흐름도 검토 범위에 포함한다. 자유 텍스트에 건강·민감정보를 의도적으로 받는 운영 방식이 있는지 확인한다. 수집 항목을 확인하지 않은 채 ‘건강 정보 없음’ 등으로 확정하지 않는다.

## 공통 답변 준비

- 전송 중 암호화: 코드의 API는 HTTPS. 외부 사진 주소·서버/백업 경로·모든 SDK까지 최종 확인한 뒤 ‘예’로 확정한다.
- 삭제 요청: 앱과 외부 웹에 이메일 접수 안내를 준비했다. 실제 계정·관련 정보 삭제 및 백업 처리 검증, 공개 URL 배포가 남아 있다. 안내 화면만으로 전체 삭제 완료를 주장하지 않는다.
- 광고·결제·광고 식별자: 현 앱 코드에 광고·결제 SDK나 광고 ID 권한은 없다.
- 위치·주소록·통화·SMS: 해당 Android 권한 또는 단말 데이터 읽기 코드는 없다. 사용자가 직접 입력하는 주소·연락처와 구분한다.
- 서버 접속 로그·IP·기기 정보: 호스팅 설정과 로그 보관 정책 확인 전 확정 보류.
- 외부 제공/공유: Railway/Vercel 처리, 운영 PC 백업, 이메일 접수와 교회 업무 권한을 확인한다. Google의 서비스 제공자 예외와 법률상 처리 위탁을 같은 의미로 단정하지 않는다.
- 데이터 판매 없음 등 운영 정책은 교회 운영자가 최종 확인해야 한다.

## 제출 전 조건

개인정보 처리방침 공개, 민감정보·미성년자 처리 근거와 필요한 동의 안내, 보관·삭제 기간 및 실제 삭제 절차, 가상 심사 환경, 실제 SDK/호스팅 최종 점검을 완료한다. 이 표를 자동으로 콘솔의 확정 답변으로 옮기지 않는다.

근거: `backend/.../entity/User.java`, `Student.java`, 관련 TTS·출석·행사 엔티티, `frontend/src/pages/Signup.jsx`, `ProfilePage.jsx`, `StudentDetailPage.jsx`, `frontend/android/app/src/main/AndroidManifest.xml`. 실명 명단 파일이나 실제 개인정보는 읽거나 복사하지 않았다.

공식 기준: [데이터 유형·목적·공유 정의](https://support.google.com/googleplay/android-developer/answer/10787469), [계정 삭제 요구사항](https://support.google.com/googleplay/android-developer/answer/13327111).
