## DB 변경의 정확한 범위

`V015__notifications_push.sql` → `V016__tts_calendar_quarters.sql` 순서다. 각 SQL은 트랜잭션·스키마 잠금·선행 버전 확인·재실행 거부를 포함한다. 두 파일 전체가 하나의 트랜잭션인 것은 아니다.

- V015: notifications에 중복 방지 키/이동 경로와 유일 인덱스 추가, 알림 종류 제약 확장, meeting_minutes에 최초 공개 알림 처리 여부 추가. **기존 공개 회의록은 이미 알린 것으로 표시**해 과거 회의록 일괄 알림을 막는다.
- V015: notification_preferences, push_devices, push_deliveries 3개 테이블 추가. 기존 이용자의 푸시 동의를 자동 생성하거나 true로 만들지 않는다.
- V016: 마감 분기의 연동 TTS 값을 보존하는 tts_linked_snapshots 1개 테이블/인덱스 추가.
- 기존 TTS 답변·주차 키·이관 총점을 일괄 재작성하거나 삭제하는 SQL은 없다. 달력 분기 변경은 조회/저장 규칙에 반영된다. 과거에 이미 바뀐 연동값을 역사적으로 복원하는 기능은 아니다.
- V015 적용 시 DDL 잠금과 서버 배포 중 재시작 가능성이 있으므로 짧은 점검 시간을 정한다. 잠금 대기를 무제한 허용하지 않고 실패 시 중단한다.

## 적용 전에 남은 필수 확인

1. 사용자에게 위 공용 서버·기존 iOS/웹·가상 심사 서버 영향을 설명하고 적용 범위를 결정받는다. 현재는 준비만 승인됐다.
2. 새 승인 범위에 따라 최신 운영 DB를 기존 정책대로 암호화 백업하고 별도 보호된 로컬 PostgreSQL에 복원한다. 원본/복원본 행 수·내용 해시를 비교하고 V015/V016 실패 원복·정상 적용·스키마 검증을 수행한다. 이번에 새 운영 백업이나 운영 DB 조회/변경을 실행하지 않았다.
3. 현재 배포 커밋, V014까지의 실제 이력, 환경변수는 비밀값 출력 없이 확인한다. NOTIFICATIONS_ENABLED의 실제 운영 값도 확인 전 추정하지 않는다.
4. 구버전 iOS/Android/웹 요청과 새 Android 요청으로 로그인/갱신, 같은 분기 저장, 지난 분기 거부, 분기 경계 부분 주, 기존 통계/새 통계, 출석·회의록 조회, 신고·탈퇴 경로를 복원본 또는 가상 자료에서 대조한다. 기존 합성 회귀 성공과 이 운영 복원본 검수는 다르다.
5. Play 타겟 연령·이용수칙·개인정보 신고·스크린샷을 후보와 대조한다. 이전 Play 기록은 18+이며 이후 앱 가입 정책은 14세 이상 승인 교사로 바뀌었으므로 현재 콘솔 상태 확인 및 필요한 수정 범위를 확정한다. App Store 16+와 Play 선택지를 같은 값으로 가정하지 않는다.

2. 승인된 유지보수 시간에 V015, V016을 순서대로 적용하고 이력·기존 업무 기록 보존을 확인한다.
3. 지정 커밋의 서버를 먼저 배포한다. main 병합은 웹 자동 배포도 유발하므로 실제 배포 범위에 웹이 포함되는지 별도로 명확히 한다. 이번 준비 커밋은 개선 브랜치에만 보관한다.
4. 알림 생성과 PUSH_ENABLED/PUSH_ANDROID_ENABLED/PUSH_IOS_ENABLED는 명시된 결정 없이 켜지 않는다. 새 서버 배포 자체가 푸시 활성화 승인은 아니다.
5. 승인된 가상 심사 환경을 준비하고 Google 심사 계정의 전체 기능을 검수한다. Apple의 기존 심사 환경 영향도 결정 내용과 대조한다.
6. 서명된 Android 1.0.1(6)을 기존 Alpha에 업로드하고 변경 요약·스토어 내용·오류/경고를 검토해 Google에 제출한다. 업로드 완료와 Google 승인/테스터 제공은 구분한다.
7. Google 제공 확인 후 실제 Play 업데이트에서 로그인 유지·새 홈·TTS·뒤로가기·재시작을 검수한다. 실제 명단으로 시험 저장하지 않고 교사들은 정상 업무만 입력한다.
8. 등록한 Google 계정으로 참여 링크 수락→Play 설치/업데이트→각자 앱 교사 계정 로그인 안내를 전달한다. 자동으로 이메일이나 카카오톡을 보내지 않는다.

## 실패 시 복구

- V015 실패: 해당 트랜잭션 원복 확인 후 중단. V016 실패: V015는 이미 커밋됐을 수 있으므로 이력부터 확인한다. 완료된 V015를 무조건 재실행하지 않는다.
- 서버 기동 실패: 새 앱 제공을 중단한 상태에서 검증한 이전 서버로 복귀한다. 새 테이블/열을 즉시 DROP하지 않는다. 구버전 서버의 추가 스키마 허용 여부는 복원본에서 먼저 검증한다.
- 코드 복귀는 기능 정책 복귀이기도 하다. 과거 분기 수정 잠금이 풀리거나 달력 통계가 사라질 수 있어 복구 완료를 단정하지 않는다. 새 알림 종류가 이미 생성됐다면 구버전 enum과 호환되는지도 확인한다.
- 새 업무 입력이 생긴 뒤 전체 DB를 옛 백업으로 덮어쓰지 않는다. 후속 입력을 보존·대조하는 별도 복구가 필요하다.
- Play 제공 이후 앱을 낮은 versionCode로 되돌릴 수 없다. 문제가 있으면 더 높은 코드의 수정 버전을 준비한다. 이미 설치된 새 앱이 새 API를 계속 쓰므로 공용 서버만 무조건 구버전으로 되돌릴 수 없다.
