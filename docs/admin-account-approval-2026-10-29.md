# 가입·이용 정지 관리 수정 — 2026-10-29

## 반영한 동작

- 가입 승인 대기와 이용 정지 화면은 목록형만 표시한다. 이전 보기 방식 저장값은 사용하지 않는다.
- 별도 ‘승인 후 반 배정하기’ 이동 버튼을 없앴다.
- 승인 성공 직후 해당 교사 이름과 함께 ‘선생님의 반을 배정하시겠어요?’를 묻는다. 학년·반·담임/부담임을 선택해 바로 배정하거나 나중으로 미룰 수 있다.
- 여러 교사를 선택해 한 번에 승인할 수 있다. 일괄 승인 뒤에는 승인된 교사별로 반 배정을 순서대로 안내한다. 나머지 배정을 모두 나중으로 미루는 것도 가능하다.
- 검색어 변경 시 선택을 초기화하고, 명단 갱신 시 사라진 교사 선택을 해제한다. 요청 중 중복 실행을 막고 계정·세션·환경 변경 시 이전 승인 결과를 새 화면에 적용하지 않는다.
- 승인 실패는 대기 명단을 유지하고 갱신한다. 반 배정 실패는 승인 상태와 선택 내용을 유지해 재시도할 수 있게 한다. 반 배정 안내를 닫아도 승인은 취소되지 않는다.
- 기존 담임이 있는 반은 부담임을 기본 선택한다. 담임으로 명시적으로 변경하면 기존 담임이 부담임으로 바뀐다는 문구를 표시한다. 다른 교사 배정은 유지한다.
- 이용 정지 목록의 사유·이력·해제 검토는 상세를 펼쳐 확인한다. 최종 관리자만 해제 가능하며, 사유 입력·상태 버전 검증·확인 절차를 유지했다.

## API와 검증

- 신규 `PATCH /api/admin/users/approve`, 본문 `{ "userIds": [1, 2] }`.
- 기존 가입 승인 권한(관리자·목사님·임원)을 유지한다. 중복 없이 1~100명까지 허용한다.
- 한 명이라도 승인 불가능하면 전체 승인을 반영하지 않는다. 이용 정지·기승인·비교사·계정 삭제 요청 중·삭제된 계정을 검증한다.
- 기존 단일 승인 API도 유지한다. 승인은 역할을 변경하거나 반을 자동 배정하지 않는다.
- 반 배정 API는 미승인·정지 계정을 거절한다. 기존 배정을 전부 교체하지 않고 해당 교사만 추가·변경한다.
- 향후 실제 반영 시 새 일괄 승인 API와 프런트엔드를 함께 업데이트해야 한다. DB 스키마 변경은 없다.

## 확인 결과

- 프런트엔드 테스트: 189개 통과.
- 백엔드 전체 빌드: 성공. 테스트 178개 중 166개 통과, PostgreSQL 조건부 12개 제외, 실패 0개. 새 승인 HTTP 테스트 5개 포함.
- 프런트엔드 native 모드 빌드: 성공. 출력은 `frontend/.verification/account-approval-build`에만 생성했다.
- 가상 자료로 단일·복수 승인, 교사별 배정/건너뛰기, 검색 선택 초기화, 승인 오류, 배정 오류 후 재시도, 기존 담임 유지, 임원의 복구 제한을 브라우저에서 확인했다.
- 375px 및 320px/글씨 120%에서 목록·긴 이름·이메일·버튼의 가로 넘침이 없음을 DOM 치수로 확인했다. 현재 IAB의 스크린샷 캡처가 실패해 이번 화면의 이미지 증거는 생성하지 못했다.
- 미리보기: `http://127.0.0.1:5194/.verification/account-approval-app.html`. 실제 페이지 컴포넌트를 사용하며 모든 API는 메모리 내 가상 자료로만 동작한다. 페이지를 다시 열면 초기화된다.

## 반영 범위

로컬 작업 브랜치에만 수정했다. 운영 계정 승인·반 배정, 배포, 스토어 업로드, 검토 요청, push는 하지 않았다. 이전 교사 교적부·관리자 권한 변경 작업은 그대로 보존했다.
