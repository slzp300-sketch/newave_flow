# 운영 주요 기능 점검 — 2026-10-11

## 결론

로그인을 막던 운영 API 경로 문제를 발견해 수정·배포했고, 사용자가 실제 계정으로 로그인에 성공했습니다. 이후 같은 계정에서 출석, 행사, TTS와 관리자 집계의 조회·화면 이동을 확인했습니다. **저장·제출까지 전부 정상이라는 판정은 아닙니다.** 검수용 계정/데이터가 지정되지 않아 실제 출석·행사·TTS 기록은 변경하지 않았습니다.

검수 범위는 운영 앱의 임원 권한 계정, 실제 조회 화면, 공개 API 상태 확인, 코드 대조, 가상 데이터로 조회 장애 재현입니다. 개인 이름·연락처·명단·비밀번호·토큰은 보고서에 기록하지 않습니다. 구글 시트 원본은 아직 받거나 읽지 않았으므로 기존 시트와 앱의 값이 같은지는 별도 검증 대상입니다.

## 수정 완료: 로그인 요청의 `/api` 누락

- 증상: 올바른 로그인 시도에도 `로그인이 만료되었습니다. 다시 로그인해주세요.`가 표시됐습니다.
- 원인: 10월 10일 반영한 클라이언트가 `VITE_API_URL`을 사용하도록 바뀌었지만, 기존 운영 환경값은 서버 도메인만 포함했습니다. 배포 번들의 실제 기본 주소가 `/api` 없는 도메인으로 확인됐고, 요청이 `/api/auth/login` 대신 `/auth/login`으로 전송됐습니다.
- 재현: 동일한 가상 계정 요청에 `/auth/login`은 만료 안내 401을, `/api/auth/login`은 올바른 계정 오류 안내 401을 반환했습니다. 실제 비밀번호를 수집하거나 계정을 재설정하지 않았습니다.
- 수정: 서버 도메인 또는 `/api` 포함 주소를 모두 받아 `/api`가 정확히 한 번 붙도록 공통 주소를 보정했습니다. 로그인·토큰 갱신이 같은 주소를 사용합니다.
- 검사: 주소 설정 조합과 로그인·갱신 URL 회귀 검사 추가, 프런트 18개 검사 통과, 실제 운영과 같은 도메인만 있는 환경값으로 빌드 통과. [GitHub Actions](https://github.com/slzp300-sketch/newave_flow/actions/runs/38111297677)도 성공했습니다.
- 배포: 코드 커밋 `3d45138649ce975c259c9cbf6e4fee89bcb0c329`, [Vercel 운영 배포](https://vercel.com/slzp300-sketchs-projects/newave-flow/9xypH44K4hP5qCdPe3Ursy3K8Js1), Railway 배포 `f33ea168-c882-487c-8aa7-eb7a74a86413` 성공. 운영 주 번들은 `index-C8FrPTbW.js`입니다.
- 최종 확인: 운영 브라우저에서 가상 계정 오류 안내가 정상으로 바뀌었고, 사용자가 기존 계정으로 로그인 성공을 확인했습니다. 로그인 후 기능 조회도 진행했습니다.
- 이전 검증의 빈틈: 빌드·백엔드 상태·공개 화면 확인만으로는 프런트 운영 환경값과 API의 연결을 검증하지 못했습니다. 앞으로 배포된 번들의 API 주소와 실제 브라우저 로그인 경로를 배포 점검에 포함해야 합니다.

근거: [주소 보정 함수](../frontend/src/api/createApiClient.js), [공통 클라이언트](../frontend/src/api/client.js), [회귀 검사](../frontend/tests/apiClient.test.js).

## 운영에서 확인한 기능

| 기능 | 직접 확인한 내용 | 판정과 한계 |
|---|---|---|
| 로그인 | 새 버전 적용, 잘못된 계정 안내, 사용자 실제 로그인, 이후 화면 이동 | 복구 확인. 비밀번호 변경·로그아웃·장시간 만료 후 갱신은 운영에서 별도 실행하지 않음 |
| 학생 출석 | 담당 반 학생 표시, 이번 주와 이전 주 이동, 미래 주 이동 차단 | 조회 확인. 실제 출석 체크·제출·담임/부담임 공동 제출은 운영에서 실행하지 않음 |
| 출석 관리 | 현재 주와 이전 주 선택, 해당 기간의 제출 데이터 없음 표시 | 화면 확인. 해당 기간 집계값을 시트와 대조하지 않음 |
| 달력 | 월 이동, 달력/목록 전환, 기존 8월 행사의 날짜와 목록 표시 | 조회 확인. 행사 생성·수정·삭제는 실행하지 않음 |
| 행사 출석 | 기존 행사 펼치기, 담당 학생·교사 출석과 제출 완료 표시 | 기존 기록 조회 확인. 부분참석·불참 사유 저장은 실행하지 않음 |
| 행사 출석 관리 | 학생/교사 집계 탭, 인원 표시, 명단 보존 기준 안내 | 조회 확인. 원본 시트와 인원·출결 전수 대조는 미실시 |
| TTS 내 체크 | 이번 주/이전 주 전환, 항목과 점수 표시, 미래 요일 비활성, 지난 요일 활성 | 조회 확인. 체크 버튼은 즉시 저장하므로 누르지 않음 |
| TTS 통계 | 누적 순위, 내 주차별 추이 | 실제 기록 표시 확인. 시트의 과거 배점과 값 대조는 미실시 |
| TTS 관리 | 주간 현황과 이전 주 이동, 점수 현황, 항목 조회, 다음 주 적용 안내 | 조회 확인. 항목·배점 변경은 실행하지 않음 |

주요 화면 조회 동안 브라우저 오류·경고는 발견되지 않았습니다. 현재 브라우저 폭에서는 가로 넘침이 없었습니다. 이번 점검을 375px 기기 실측이나 모든 권한·모든 데이터 조합 검수로 해석하지 않습니다.

운영 상태 확인은 API health 200/정상, 비로그인 학생 API 401, 프런트 도메인 CORS 정상, 로그인 페이지 200을 통과했습니다. 백엔드 로그의 기동 실패·스키마 오류는 없었습니다.

## 남은 문제 — 우선순위 순

### 1. 높음: 조회 실패 후 출석·TTS 입력을 허용함

**출석:** 학생 목록은 성공하고 출석 기록 조회만 503으로 실패하도록 가상 화면에서 재현했습니다. 실패 안내 없이 학생이 기본 `출석`으로 표시되고 `제출하기`가 활성화됐습니다. 이 상태에서 실제 저장을 하면 기존 결석·메모가 기본값으로 덮일 수 있습니다. 운영에서 덮어쓰기가 발생했다는 증거는 없으며, 재현 화면에서는 저장을 차단했습니다.

- 근거: `AttendancePage.jsx` 45~67행의 조회 결과에서 오류 상태를 사용하지 않음, 94~114행의 기본 출석값과 일괄 저장, 198~203행의 제출 버튼.
- 개선: 반·학생·출석·제출 상태가 모두 정상 로딩된 뒤에만 입력/제출 허용. 조회 실패는 명확한 오류·재시도 화면으로 표시. 주차 이동 중에도 이전 주 입력과 새 주 저장이 섞이지 않도록 잠금.

**TTS:** 질문 조회는 성공하고 주간 기록 조회만 503으로 실패하도록 재현했습니다. `0점`과 비어 있는 체크로 보이며, 지난 주 체크 버튼은 활성화됐습니다. 사용자가 한 칸을 누르면 읽지 못한 나머지 요일을 빠뜨린 답변으로 기존 주간 답변을 대체할 수 있습니다.

- 근거: `TTSPage.jsx` 88~96행과 179행은 로딩만 처리하고 오류를 표시하지 않음. 147~150행은 빈 객체에서 새 답변을 생성. `TtsService.java` 129~136행은 해당 항목의 전체 답변을 교체.
- 개선: 질문과 기록 조회 성공 전 체크 잠금, 조회 실패와 실제 0점을 구분, 재시도 제공. 회귀 검사에 부분 조회 실패를 포함.

가상 재현 파일은 Git 제외 폴더 `frontend/.verification/failure-review.html`과 `failure-review.jsx`에 있습니다. 모든 요청은 가상 응답이며 저장은 차단했습니다.

### 2. 보통: 행사 조회 실패를 ‘행사 없음’으로 표시함

가상 행사 목록 API를 503으로 만들면 오류 대신 `출석 체크가 필요한 행사가 없습니다`가 표시됩니다. 또한 행사 카드의 학생 조회 실패/로딩은 기본 빈 배열이므로 조건에 따라 `제출 완료`로 오인할 수 있습니다.

- 근거: `EventAttendanceListPage.jsx` 501~525행의 기본 배열·로딩/빈 목록 분기, 439~448행의 `students.length === 0` 완료 판정.
- 개선: 조회 성공 시에만 빈 목록·완료 여부를 판정하고 실패에는 오류와 재시도를 표시.

### 3. 보통: 행사 마감일 미입력 안내와 실제 규칙이 다름

일정 화면은 마감일을 비우면 `일정 마지막 날까지 제출 가능`하다고 안내합니다. 실제 공통 함수와 서버는 명시적 마감일이 없으면 계속 입력을 허용합니다. 운영에서도 8월 행사에 마감 안내 없이 기존 출석 조회가 열리는 것을 확인했습니다. 입력 제한 자체는 저장하지 않아 검증하지 않았습니다.

- 근거: `CalendarPage.jsx` 730~736행, `utils/eventAttendance.js` 3~5행, `EventService.java` 147~148행 및 206~207행.
- 개선: 현재 규칙을 유지한다면 문구를 `비워두면 제출 기한을 제한하지 않습니다`로 통일. 기한을 자동 지정하려면 별도의 업무 규칙 결정이 필요.

### 4. 보통: 새 버전이 배포돼도 열린 앱은 이전 코드를 사용할 수 있음

수정 배포 후 서버는 새 번들을 제공했지만, 처음 연 검수 탭은 서비스 워커 캐시의 이전 번들을 사용해 같은 로그인 오류가 났습니다. 다시 새로고침하자 새 번들을 받고 문제가 해결됐습니다.

- 근거: 같은 브라우저에서 배포 후 처음 확인한 스크립트 `index-BQ7twCGk.js`, 새로고침 후 `index-C8FrPTbW.js`.
- 개선: 새 버전 감지와 `새 버전으로 다시 열기` 안내, 화면의 실제 빌드 버전 표시. 입력 중인 내용이 있으면 먼저 보존하거나 안내하고 갱신. 무조건 강제 새로고침은 피함.

### 5. 낮음: 실행 가이드가 현재 운영 구조와 맞지 않음

`docs/getting-started.md`는 여전히 MySQL 초기화, 프로필 없는 실행, 자동 생성되지 않는 예전 테스트 계정을 안내합니다. 현재 PostgreSQL 운영·명시적 프로필·기본 시딩 비활성 규칙과 맞지 않습니다.

- 개선: 현재 실행법과 가상 검수 계정 준비 절차로 교체하고, 운영 계정으로 예전 예시 비밀번호를 시도하지 않도록 정리.

## 다음 검증 순서

1. 조회 실패 시 출석·TTS 입력 차단과 행사 오류 표시를 먼저 개선하고 가상 장애 검사를 반복합니다.
2. 행사 마감 안내와 앱 업데이트 안내를 정리합니다.
3. 별도 검수용 계정·반·행사가 준비되면 저장 → 새로고침 → 조회, 공동 출석 완료, 행사 부분참석·불참 사유, TTS 체크 복원·점수 반영을 운영과 분리한 데이터로 검증합니다.
4. 구글 시트 링크가 제공되면 읽기 전용으로 주차 기준·교사 매칭·항목별 배점과 합계를 먼저 대조합니다. 시트 제공만으로 운영 DB 덮어쓰기나 가져오기를 실행하지 않습니다.

실제 학생/교사의 저장·제출·삭제·승인, 비밀번호 변경, TTS 배점 변경, 데이터 가져오기는 이번 점검에서 실행하지 않았습니다. 디자인 변경도 포함하지 않았습니다.
