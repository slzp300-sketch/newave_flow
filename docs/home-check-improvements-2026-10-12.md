# 홈 체크와 모바일 터치 개선

2026-10-12 사용자 요청: 모바일의 남는 초록 hover 제거, 홈 주간 요일 체크 허용, 체크하지 않은 모임의 완료 표시 수정.

## 변경

- Tailwind hover와 group-hover를 마우스 입력 조건에서만 생성한다. 기존 직접 작성한 hover도 같은 조건을 유지한다.
- 터치 시 정적인 부모 카드의 active 색상 변경을 제거한다. 실제 버튼은 짧은 눌림/테두리 효과를 사용하며 키보드 초록 포커스 테두리는 유지한다.
- HomeTtsSummary의 월~토 말씀·기도를 최소 높이 44px 버튼으로 바꾸고 CheckTab의 동일 저장 큐를 사용한다. 미래 날짜, 오프라인, 조회 오류 및 합계만 이관한 주차의 잘못된 수정을 차단한다. 아래 버튼에는 빨간 점을 추가하지 않는다.
- 모임 상태 문구를 실제 의미에 맞춰 ‘참석 체크 반영’, ‘참석 투표 반영’, ‘참석 미반영’으로 구분한다. 수동 예배 체크는 ‘체크됨’으로 표시한다. 참석 응답을 실제 모임 개최/출석 확인으로 표현하지 않는다.

## 모임 완료 문제와 운영 설정

기존 운영의 교사회의·온라인 줌 기도모임 질문은 link_type이 비어 있어 별도 TTS 수동 응답을 읽었다. 따라서 모임 화면의 미응답과 홈 TTS의 완료 표시가 동시에 가능했다. 저장된 수동 응답을 임의로 삭제하거나 다른 예배 체크를 초기화하지 않는다.

V005는 정확히 일치하는 두 표준 질문만 이번 주(한국 시간 2026-10-11 시작)부터 SAT_MEETING/PRAYER_MEETING에 연결한다. 이전 질문 버전과 원본 답변은 보존한다. 이름이 중복되거나 미래 규칙이 예약되어 있으면 중단한다. 이번 주 점수는 실제 참석 응답에 따라 정정되며 이전 주의 계산 기준은 유지된다.

최신 암호화 백업 복원본에서 정상 적용, 실패 롤백, 중복 적용 거절, 이전 규칙 및 기타 질문 속성 보존을 검증했다. 운영 적용 전후 질문 설정/변경 이력 외 31개 업무 테이블의 전체 행 해시가 일치했다.

## 터치 색상 의도 정정 (2026-10-13)

사용자는 모바일에 연두색이 남는 문제는 해결됐지만 클릭할 때의 녹색은 유지하길 원한다고 정정했다. 앞서 적용한 파란 눌림 효과를 녹색으로 바꾸고, 마우스를 올리기만 했을 때의 배경색 전환은 제거했다. 누르는 동안 즉시 녹색, 손을 떼면 기존 파란색/선택 상태로 돌아간다. 정적인 부모 카드·키보드 포커스에는 녹색 채움을 적용하지 않는다. 비활성화 버튼 및 종료 행사 회색은 기존 규칙을 유지한다.

가상 홈 375px에서 실제 누름 상태를 유지해 진한 녹색 rgb(33,100,63)/흰 글씨를 확인했다. 해제 후 마우스 hover가 남아 있어도 원래 파란 배경 rgb(238,243,255)으로 복귀했다. 요일 버튼과 오늘 체크·점수의 동기화 및 콘솔 오류 없음 확인. 프런트 65개 검사와 웹 빌드 통과. 이 보완은 CSS만 변경하며 저장·연동 규칙을 수정하지 않는다.

## 선택·활성 상태에 초록색 유지 (2026-10-13)

최신 사용자 요청은 ‘클릭 시’ 대신 ‘활성화된 상태’를 초록색으로 표시하는 것이다. 위의 누르는 동안만 녹색을 적용하던 기준을 이 요청으로 대체한다.

- 공통 `:active` 녹색 스타일을 제거하고 `aria-pressed`, `aria-checked`, `aria-selected`, 현재 메뉴와 체크 완료 상태에 녹색을 적용한다. 선택을 해제하면 기본 파랑 계열로 돌아간다.
- 채움형 선택 버튼은 진한 녹색/흰 글씨, 일반 선택 버튼과 현재 메뉴는 연한 녹색/진한 녹색 글씨를 사용한다. 일반 실행 버튼은 파랑을 유지한다.
- 날짜·기간 선택, 켜진 스위치, TTS 체크 표시와 완료된 모임 상태를 맞췄다. 기존 색상 선택 견본과 접수 종료 행사 회색은 보존한다.
- 상태 색상을 결정할 수 있도록 바로가기 편집과 태그 배정 버튼에 선택 상태를 명시했다. 저장·점수·출석 집계 로직은 변경하지 않았다.
- 로컬 H2 가상 자료에서 출석 선택 후 손을 뗀 상태의 녹색 `rgb(33,100,63)`/흰 글씨를 확인했다. 다른 상태 선택 시 이전 버튼은 기본 `rgb(238,243,255)`로 복귀하고 새 선택은 녹색을 유지한다. 현재 메뉴와 편집 토글도 녹색 유지 확인.
- 프런트 기존 65개 검사, 웹/PWA 빌드, native 동기화와 Android `assembleDebug lintDebug` 통과. 기존 lint 경고/baseline은 별도이며 경고 0개라는 뜻은 아니다.
- 검수 이미지: `frontend/.verification/active-state-attendance.jpg`. 로그: active-state-tests.log, active-state-build.log, active-state-android.log.

1. 홈 ‘이번 주 기록 수정’은 페이지 이동 대신 펼치기로 변경하고, 펼쳐진 영역으로 자동 스크롤한다. 위의 기록 수정 이동 요구를 이 요청으로 대체한다.
2. 교사회의·행사 참석 등 모든 관리자 확인 화면에 보기 형식 전환이 있는지 확인하고, 없는 곳에 추가한다.
3. Android 시작 화면은 배경이 화면 전체를 채우고 가운데 로고가 잘리지 않게 표시한다. 현재 약 1초 보이는 파란 시작 화면의 로고가 잘려 오류처럼 보인다는 사용자 피드백이며, 원하는 구성은 유튜브 배너처럼 전체 배경과 중앙 로고다.

## 후속 UI 개선 구현과 검증 (2026-10-13)

- 홈 ‘이번 주 기록 수정’은 같은 화면에서 펼치고 해당 영역으로 자동 스크롤한다. 키보드 포커스와 접기 동작, 움직임 줄이기 설정을 지원한다. 기존 체크 저장 큐와 점수 계산을 재사용한다.
- 관리자 확인 화면 13곳에 큰 카드·작은 카드·목록·자세히 전환을 제공한다. 기존 교사·학생·명단 보기와 같은 방식이며 화면별 선택을 기억한다. 교사회의, 온라인 기도모임, 회의록과 확인 현황, TTS, 행사 학생·교사 참석, 전도, 학생 출결, 일정, 가입 승인, 담당 반, 비활성화 요청을 확인했다. 필터·기록·부분 참석 날짜·사유·수정 시각·기존 작업 버튼을 유지한다.
- 관리자 전체 메뉴는 ‘나의 활동 / 관리’ 두 선택만 제공하고 ‘나의 활동’으로 시작한다. 일반 교사는 관리 항목과 이 필터가 없다.
- 로그인 화면의 회원가입·아이디 찾기·비밀번호 찾기를 카카오 로그인 아래에 묶었다. 고객지원·계정삭제 요청은 배경 없는 작은 글씨로 표시하되 44px 터치 영역을 유지한다.
- 이번 주 일정은 한국 날짜 기준 3~2일 전 연한 노랑, 하루 전·당일 연한 빨강, 더 먼 일정은 기존 파랑으로 표시한다. 종료 일정의 회색이 우선한다. ‘이번 주 일정’ 제목을 눌러 달력으로 이동하며 별도 달력 보기 버튼은 제거했다.
- 하단 메뉴는 선택 상태 녹색과 기존 이동 애니메이션을 유지하고 아이콘에 겹치던 별도 배경을 제거했다.
- Android 시작 화면은 전체 파란 배경과 중앙 흰색 원본 로고를 분리했다. Android 12 이상은 시스템 원형 마스크의 안전 영역 안에 전체 로고가 들어가도록 여백을 둔다. 벡터 생성은 `tools/android/create-splash.mjs`로 재현한다.
- 프런트 67개 검사, 웹/PWA 빌드, 백엔드 전체 build, Android native 동기화·assembleDebug·lintDebug 통과. Android lint의 기존 경고가 없다는 뜻은 아니다.
- localhost 가상 자료로 375px 홈 펼침·체크와 점수 동기화·미래 날짜 제한, 관리자 보기 전환·검색 유지·선택 복원·기록 보존, 교사 권한의 메뉴, 일정 색상·제목 이동, 로그인 링크와 하단 메뉴 배경을 검증했다. 확인한 화면에 가로 넘침과 콘솔 오류가 없었다. 운영 학생·교사의 업무 기록을 시험 수정하지 않았다.
- 근거: `frontend/.verification/ux-followup/`의 빌드 로그, `admin-view-checks.json`, `home-expanded.png`. 운영 배포와 기존 서명 실기기 설치 결과는 완료 후 별도로 기록한다.
