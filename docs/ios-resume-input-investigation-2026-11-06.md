# iOS 복귀 후 버튼 무응답 조사 — 2026-11-06

## 사용자 확인

- 업데이트 안내를 확인한 시점에는 1.0.3이 설치돼 있었고, 1.0.4 출시 후 아직 업데이트하기 전이었다. 이를 이미 1.0.4를 설치한 상태의 시험으로 해석하면 안 된다.
- 앱 안내가 없었으며 App Store도 처음에는 ‘열기’였다. App Store를 완전히 닫고 다시 열자 ‘업데이트’가 나타났다.
- 별도 증상: 앱을 완전히 종료하지 않고 다시 들어오면 스크롤은 되지만 버튼은 반응하지 않았다.
- 버튼 문제는 1.0.3에서 확인했다. 사용자는 현재 1.0.4에서는 아직 시험하지 않았다고 답했다.

## 확인한 사실과 한계

1. 업데이트 조회 지연은 `ios-store-update-cache-fix-2026-11-06.md`의 Apple 고정 조회 주소 캐시 재현 및 로컬 수정 `91389a1`을 따른다. App Store 앱 자체의 버튼 갱신과 앱 내부 안내는 별도 경로다.
2. 공통 `usePullToRefresh`의 기존 실제 이벤트 처리기를 가상 이벤트로 실행했다. 화면 맨 위에서 버튼 터치가 아래로 1px 움직여도 `touchmove.preventDefault()`를 호출했다. `blur`로 앱을 떠나고 `touchend`가 없는 경우에도 다음 이동 이벤트를 계속 취소했다.
3. 해당 훅·버튼 피드백·NativeRuntime 코드는 출시 소스 1.0.3 `dbcea8c5b31583ba7d6f08fc5dbaadc263a7617b`와 1.0.4 `bd073af551fdeb762eb117ab6914cbd6fa30ead8` 사이에 변경이 없다. 따라서 확인된 코드상의 약점은 두 버전에 모두 존재한다. **1.0.4 실기기에서 동일 증상을 재현했다는 뜻은 아니다.**
4. 네이티브 복귀, 로그인 확인, 업데이트 알림, 통신 재시도와 화면을 가리는 요소를 함께 읽었다. 현재 자료만으로 기기의 모든 버튼이 멈춘 직접 원인은 확정하지 못했다. 아래 수정은 재현 가능한 입력 결함을 보완한 것으로, iOS 복귀 오류 전체가 해결됐다고 단정하지 않는다.

## 로컬 수정

- 버튼·링크·입력칸·선택 컨트롤·대화상자에서 시작한 터치를 당겨서 새로고침이 가로채지 않는다. 자식 아이콘/텍스트를 누른 경우도 포함한다.
- 일반 영역에서는 10px를 넘는 아래 방향 드래그일 때만 새로고침 제스처를 시작한다. 미세한 움직임, 가로/위 방향 이동, 내부 스크롤, 여러 손가락 입력은 원래 동작을 유지한다.
- 앱을 나가거나 복귀할 때 `blur`, `pagehide`, `visibilitychange`, Capacitor의 문서 `pause`/`resume` 이벤트에서 남은 제스처와 화면 이동량을 정리한다. 버튼 눌림 효과도 같은 복귀 신호에서 해제한다.
- 터치 뒤 발생하는 호환 마우스 이벤트가 새 제스처를 만들지 않게 했다. 실제 마우스 드래그는 유지한다.
- 이미 진행 중인 조회는 중복 시작하지 않는다. 실패 또는 화면 해제 시 상태가 남지 않게 한다. 화면 강제 재시작, 로그인 초기화, 입력 초안 삭제, 쓰기 요청 재전송을 추가하지 않았다.

## 검증

- 신규/보완 입력 검사 15개 통과: 클릭 보존, 실제 당기기, 성공/실패, 복귀 중단, 중복 조회 방지, 내부 스크롤, 다중 터치, 마우스 호환 이벤트, 해제 후 늦은 응답.
- 출시 1.0.4의 실제 훅과 수정된 실제 훅을 같은 가상 이벤트로 비교: 미세 탭 취소 및 앱을 떠난 후 남은 제스처 취소가 기존 `true/true`에서 수정 후 `false/false`로 바뀜.
- 전체 프런트 검사 **264개 성공**, 실패 0.
- native 모드 Vite 빌드 성공: `frontend/.verification/resume-build-20261106`. 기존 500kB 청크 크기 경고는 유지.
- `npm run ios:verify` 성공. iOS 구성/연결의 정적 검사이며 가상 기기 실행 검사가 아니다.
- 서버 `gradlew.bat build` 성공, 기존 결과 UP-TO-DATE. 서버 코드는 수정하지 않았다.
- 빌드 로그: `frontend/.verification/resume-build-20261106.log`, `backend/.verification/resume-backend-20261106.log`.

## 남은 확인 / 출시 범위

- 실제 iPhone에서 앱 전환·잠금·짧은/긴 대기 후 복귀, 홈 및 하단 메뉴 이동, 입력칸/선택 목록, 저장 버튼의 동작을 확인해야 한다. 기존 1.0.4에서의 재현 여부와 수정본에서의 결과를 구분해 기록한다.
- 계속 발생하면 당시 화면, iOS 버전, 대기 시간, 하단 메뉴까지 반응하지 않는지 확인하고 기기 실행 기록으로 화면 처리/터치/통신 중 정지 위치를 좁힌다.
- 이번 수정과 `91389a1`은 로컬 다음 출시 후보다. 새로운 iOS 빌드 업로드·심사 제출·운영 서버 배포·main 푸시·웹/Android 배포를 진행하지 않았다. 배포된 1.0.4에 소급 반영되지 않는다.
