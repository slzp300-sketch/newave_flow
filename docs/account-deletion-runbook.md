# 계정 삭제 요청 처리 준비

2026-10-12 사용자가 승인한 범위: 개인 계정·연락처·프로필·TTS는 삭제하고, 공동 반 보고서는 개인을 식별할 수 없게 처리해 보존한다. 공개 접수 주소는 slzp300@gmail.com이다.

현재는 이메일 접수 경로를 마련한 단계다. 운영 DB에서 실제 삭제를 시험하지 않는다. 아래 검증과 보관 정책 확정이 끝나기 전 삭제를 완료했다고 안내하거나 스토어에 완성된 처리 기능으로 신고하지 않는다.

## 접수와 본인 확인

1. 가입 이메일에서 요청했는지 확인한다. 비밀번호·신분증 사진을 받지 않는다.
2. 다른 주소에서 온 경우 계정 소유자임을 별도 확인한다. 확인 전에는 계정 존재 여부나 개인정보를 답변에 포함하지 않는다.
3. 대상 계정의 내부 ID와 요청 범위를 확인하고 개인 정보를 포함하지 않는 접수 번호로 처리 이력을 남긴다.
4. 담당 반 이전과 마지막 관리자 계정 여부를 확인한다. 서비스 관리자가 사라지는 경우 담당자 이전을 먼저 조정한다.

## 삭제·익명화 대상 조사

- `users`: 이름·이메일·전화번호·생일·프로필 사진·직분·학년·비밀번호 및 세션 무효화. 비활성화만으로 삭제를 완료하지 않는다.
- `tts_data_entry`, `tts_answers`: 개인 영성 기록 제거. `tts_legacy_score`는 이름 기준이므로 동일 이름의 다른 사람 자료를 지우지 않도록 별도 식별·대조한다.
- `teacher_classes`, `user_tags`, `event_reads`, `notifications`, `meeting_minute_confirms`, `checklist_records`, `prayer_votes`, `meeting_attendances`, 전도 조/일정 배정: 개인 연결과 활동 자료 처리.
- `event_participants`: 과거 교사 명단 스냅샷의 이름·학년·반 정보. 현재 사용자 이름만 바꿔서는 이 자료가 지워지지 않는다.
- `event_attendances`: 교사 개인 참석 자료. `event_student_attendances`의 학생 참석 결과는 공동 기록이므로 제출자 식별 정보와 구분한다.
- `attendances`, `daily_reports`, `student_memos`, `deactivation_requests`: 교사 외래키와 공동 내용의 보존 범위를 분리한다. 외래키를 임의 삭제해 학생 기록을 잃지 않도록 한다.
- `daily_reports_before_class_merge`: 운영 전환 당시 보존한 원본에도 제출자 ID·자유기술 이름 등이 남을 수 있다.
- 회의록·공동 보고서·메모 등 자유기술 문서: 이름·전화번호 등을 사람이 확인한다. 같은 이름을 일괄 치환해 다른 사람의 내용을 바꾸지 않는다.
- 완료 작업 기록 및 별도 과거 원본·스프레드시트·암호화 백업도 보관 책임자와 처리 범위를 확인한다.

## 처리와 검증

1. 접근 제한된 최신 복원본에 가상 삭제 대상과 공동 기록을 만들고 트랜잭션 삭제 절차를 검증한다.
2. 개인 정보·TTS 제거, 과거 명단 익명화, 다른 교사·학생·공동 집계 보존, 기존 토큰 차단, 재승인으로 되살릴 수 없는 상태를 확인한다.
3. 실패 시 전체 롤백되는지 확인한 뒤에만 확인된 실제 요청을 처리한다.
4. 백업을 복구할 때 이미 처리한 삭제 대상이 되살아나지 않도록 삭제 완료 이력을 적용한다.
5. 신청자에게 결과와 별도 보관이 있다면 근거·항목·기한을 안내한다. 발송은 요청을 처리하는 운영자가 진행한다.

## 출시 전 남은 결정

현재 PC 백업은 완료본을 자동 삭제하지 않는다. 따라서 ‘탈퇴 즉시 모든 사본에서 영구 삭제’ 또는 임의의 30일 소멸을 약속할 수 없다. 백업 보관 기한·만료 처리·복원 후 삭제 재적용을 확정해야 한다. 이 문서는 자동 삭제 스크립트나 완료 증명이 아니며, 삭제 실행 기능의 구현·가상 자료 검수가 별도로 필요하다.
