# 예배운영팀 개발·검증 — 2026-11-06

사용자가 승인한 시안을 실제 React 화면과 서버 API로 구현했다. 추가 요청에 따라 기존 앱의 공통 제목·파트 색상·선택 목록·체크·버튼·대화상자·애니메이션을 사용했다.

## 구현

- 경로: `/worship`, API: `/api/worship`. 홈 담당 업무 및 임원 업무 메뉴와 연결.
- 이번 주 / 예배위원·공지 / 팀원 화면. 서울 시간 기준 다음 또는 당일 주일을 기본으로 표시하며 주차·연월 선택 가능.
- 미리 정한 중보기도 학년, 헌금기도 교사, 대표기도 학생, 헌금위원 학생을 기존 명단에서 선택해 주차별 저장. 자동 편성하지 않음.
- 토요일 공지 확인, 예배 전·중·후 준비 체크. 현수막과 강대상 준비는 팀원 준비와 팀장 확인을 분리. 담당자·처리자·시각 및 이전 주 기록 보존.
- 팀원 지정 및 준비 항목별 담당 지정. 담당자 변경·체크 해제 시 확인 초기화. 예배위원 변경 시 해당 안내 체크와 공지 완료 표시 초기화.
- 이름·학년·공지 문구로 PNG 생성. 긴 명단은 높이를 늘려 모두 포함. 다운로드와 카카오톡 게시 완료 체크는 별개. 카카오톡 자동 전송 없음.
- 전체 임원 조회, 일반 교사는 소속 팀만 진입. 관리자·목사·현 연도 예배운영팀장이 명단·팀원·담당·공지를 관리. 팀원은 배정 항목과 공동 준비만 체크. 서버가 권한 변경·계정 상태 및 수정 충돌을 다시 검사.
- 학생 화면·계정은 추가하지 않음. 조회·선택 응답은 이름·학년·역할 등 필요한 정보만 포함.

## 저장 구조와 개인정보

- 미적용 SQL: `backend/db/migrations/V026__worship_team.sql` (V025 이후).
- 새 표: worship_registry, worship_members, worship_weeks, worship_offerings, worship_tasks.
- 주차와 작업 항목별 revision을 분리해 서로 다른 준비 항목의 체크가 충돌하지 않도록 함. 저장은 계정/직책 변경과 같은 순서로 잠그며 오래된 revision은 409.
- 공지 문구는 기존 공유 내용 개인정보 검토 범위에 포함. 날짜 기반 주차에 epoch-day 숫자 id를 추가해 기존 검토·수정 도구와 연결.
- 사용자 삭제 시 회원 연결 및 담당/확인/공지 참조 처리, 수정 revision 갱신. 생성 이미지는 서버에 보관하지 않음.
- iOS 기존 파일 저장 플러그인에 엄격한 공지 파일명과 PNG 헤더 검사를 추가. 저장 취소는 완료로 표시하지 않음.

## 검증

- 프런트 전체 270개 성공.
- 일반 웹 빌드 및 native 모드 빌드 성공. 기존 큰 번들 경고는 남아 있음.
- 서버 최종 build 성공: 310개 중 291개 성공, 별도 환경 검사 19개 제외, 실패/오류 0.
- 신규 HTTP 검사 7개: 진입/쓰기 권한, 개인정보 응답 최소화, 주차별 저장, 준비·검토·해제, 담당 재지정/팀원 제외, 명단 변경 초기화, 충돌/날짜/제적 학생/직책 해제.
- 별도 가상 PostgreSQL에서 V026 적용 실패 롤백, 기존 표 보존, 중복 적용 차단, 주일/중복 제약, 학생 순서 교환, 계정 FK, 개인정보 문구 검토 범위, JPA validate 성공.
- 개인정보 도구 4개 성공, 별도 환경용 1개 제외. iOS 구성 정적 검사 성공.
- 375px 실제 화면에서 학년 선택, 학생 검색·추가·저장, 담당 지정, 팀장 확인, 팀원 체크→팀장 재조회, 공지 완료 체크 확인. 가로 넘침 및 브라우저 오류 없음.
- 공지 PNG를 실제 다운로드해 가상 학생 3명·학년·공지 문구와 잘림 여부 확인. 저장 뒤 공지 상태가 자동으로 바뀌지 않음을 확인.
- 실제 iPhone 파일 저장 창 및 새 Swift 검사 실행은 이 Windows PC에서 하지 않음. 다음 출시 전 macOS/iOS 검수 필요.
