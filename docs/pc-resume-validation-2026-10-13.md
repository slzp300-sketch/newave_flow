## 개선 우선순위

1. **연간 TTS 통계 집계 비용:** `TtsRecordRepository.findAllByYearWithAnswers`는 요청마다 해당 연도 전체 기록·답변·질문을 읽는다. `TtsService.computeAppScores`는 조회 후 관리 대상 주를 걸러낸다. 관리 기간/필요 범위를 DB 질의에 반영하고, 집계 반복과 재계산 비용을 줄일 수 있다. 점수 변경 후 갱신과 과거 배점 보존 검사가 필요하다.
2. **DB 연결 대기:** 혼합 부하에서 연결 풀 10개가 사용 중이고 최대 90개 요청이 대기했다. 먼저 통계 처리 시간과 트랜잭션 점유를 줄이고 재측정한다. 연결 풀만 늘려 해결됐다고 판단하지 않는다.
3. **행사 단위 저장 잠금:** `EventService`의 교사/학생 저장은 같은 행사 행을 잠근다. 중복 방지에는 도움이 되지만 행사에 사람이 몰리면 순서대로 기다린다. 병목이 계속되면 반/참가자 단위 잠금을 검토하되 중복·접수 종료 검사를 함께 보존해야 한다.
4. **실제 서비스 메모리:** 힙 1,024MiB 실행은 전체 프로세스가 1GiB를 초과했다. 힙 제한과 서비스 전체 메모리 제한은 다르다. 이 결과만으로 Railway 1GB/2GB에서의 수용 인원을 확정하지 않는다. 실제 제한 아래에서 CPU·전체 메모리·장시간 부하를 검수해야 한다.

## 한계와 다음 작업

- localhost HTTP API 검수이며 모바일 렌더링, 외부 통신 지연, 카카오 외부 로그인, 실서비스 장시간 지속 부하 검수는 아니다. 실제 DB와 마이그레이션 파일을 부하 검수에 적용하지 않았다.
- 검수용 서버와 이번에 만든 PostgreSQL만 종료했다. DB/로그는 Git 제외 검수 폴더에 남겼다. 기존 운영/백업 DB는 변경하지 않았다.
- 다른 PC의 기존 Play 업로드 키와 암호 파일을 이 PC의 비공개 폴더로 옮긴 후 기존 업로드 인증서와 대조하고 AAB 서명 검증을 수행해야 한다. 새 키를 만들지 않는다.

- 공개 개인정보 처리방침·데이터 보안 제출, 안전한 심사 접근, 내부/비공개 테스트 등 출시 작업은 별도로 남아 있다.
