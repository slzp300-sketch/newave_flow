# 찬양팀 개발 기록 — 2026-11-03

확정된 시안 범위의 앱·서버 구현 및 로컬 검증을 완료했다. 운영 DB 적용, 배포, 커밋·푸시, 앱스토어 제출은 하지 않았다. 기존 미출시 변경을 보존한 현재 작업 폴더에서 진행했다.

## 구현

- `/praise`에 홈, 학기 명단, 월별 로테이션, 다음 달 불가 일정, 콘티 자료실, 목요 기도회, 학기 운영 화면을 연결했다. 기존 앱의 담당 업무 메뉴와 임원 내 업무에도 연결한다.
- 홈에서 이번 주 연습·배정·PDF·기도회 정보를 바로 표시한다. 50명 규모 명단은 교사/학년/파트별 2열 이름 목록과 검색·접기·상세를 사용한다.
- 기존 교사 계정/학생 명단을 참조해 학기별 팀원을 지정한다. 여러 명 일괄 지정, 복수 파트, 활동 종료/재개를 지원한다. 활동을 종료해도 과거 배정과 파일 기록은 보존한다. 학생 로그인/직접 제출은 만들지 않았다.
- 연습 월의 토요일을 기준으로 주차를 생성하고 다음 주일을 연결한다. 토요일 17:00–19:00을 기본으로 하며 토요일/해당 주일의 시간 변경이 가능하다. 월·연도 경계에도 토요일 소속 학기를 유지한다.
- 배정 초안과 공개본을 분리했다. 팀원에게 미공개 배정은 보내지 않고, 이미 공개한 뒤 초안을 수정해도 기존 공개본은 유지한다. 각 주 인도자를 지정한 뒤 월 단위로 공개한다.
- 불가 일정은 본인만 제출하며 토요일 날짜/명시적 불가 없음/미제출을 구분한다. 팀장은 날짜별 이름·수를 확인한다. 시간 변경 시 재확인 상태를 표시하고, 지난 일정 버전으로 제출하면 다시 확인하도록 차단한다. 불가자 배정은 확인 체크를 요구한다.
- PDF는 실제 업로드·교체·버전 보관·권한 검사·페이지 미리보기·다운로드를 구현했다. 파일당 5MB, 200쪽 이하이며 암호/실행 동작/첨부를 제한한다. 페이지는 서버에서 제한된 해상도로 렌더링해 모바일 내장 PDF 뷰어에 의존하지 않는다. 개인별 읽음 기록은 없다.
- 목요 기도회는 학기 안 목요일별 교사 진행자와 Zoom 링크를 저장한다. 22:30–23:00을 표시하고, 팀장 또는 해당 진행자가 링크를 수정한다. 앱에서 Zoom 회의를 자동 개설하지 않는다.
- 화면 이동·선택·목록 펼침·상세창·실제 저장 완료에 승인된 애니메이션을 유지했다. 저장 대기 중 중복 동작을 막고 오류는 편집창 안에도 표시한다. 동작 줄이기 설정을 따른다.

## 권한과 저장

- 활성 조직도의 `PRAISE` 직책, ADMIN/PASTOR는 관리 권한을 갖는다. 일반 임원이라는 이유로 찬양팀 관리 권한을 추가하지 않는다.
- 활동 팀원 교사는 해당 학기의 공개 배정·명단·콘티를 조회한다. 본인이 공개 인도자로 배정된 주의 PDF만 올릴 수 있다. 학생 인도 주는 팀장이 대행한다.
- 정지/활동 종료/탈퇴 처리 계정은 접근을 차단한다. 이름이나 프로필 직분으로 권한을 추정하지 않는다.
- `praise_terms`, `praise_members`, `praise_weeks`, `praise_responses`, `praise_prayers`, `praise_pdfs`에 저장한다. 쓰기는 학기 잠금과 버전 검사로 오래된 화면의 덮어쓰기를 차단한다. 파일 응답은 인증 후에만 반환하며 `no-store`를 사용한다.
- 계정 삭제 절차는 개인 불가 응답을 삭제하고 명단의 계정 참조를 비운다. 공유 배정은 이름 없는 기록으로 보존한다. PDF는 업로더만으로 개인정보 포함 여부를 판단할 수 없으므로 모든 저장 PDF의 내용·해시 검토를 요구한다. `privacy_praise_pdf_review`의 검토가 빠졌거나 파일이 바뀌면 전체 삭제를 중단한다.

## 확인 결과

- 프론트 자동 검사 239개 통과, 최종 Vite 빌드 통과. 기존 큰 번들/동적 import 관련 경고는 남아 있다.
- 백엔드 전체 빌드 통과: 277개 중 261개 실행 통과, 환경 조건부 검사 16개 제외. 찬양팀 전용 8개와 실제 PostgreSQL 계정 삭제 검사 포함.
- V021 PostgreSQL 변경은 별도 실행에서 적용·실패 시 롤백·고유 제약·계정 참조·JPA validate 통과. 운영 DB는 연결하지 않았다.
- 가상 자료 로컬 브라우저에서 교사 제출 → 다른 팀장 화면 날짜별 집계, 새로고침 후 저장 유지, 기존 계정 팀원 등록, PDF 업로드 후 v1→v2 및 이전 버전 표시, 실제 PDF 다운로드, PDF 페이지 이미지 표시를 확인했다.
- 375px 모바일 폭에서 입력·완료 체크·알림 표시와 가로 넘침 없음을 확인했다. 애니메이션은 승인된 시안과 공통 구성요소를 사용한다.
- `ios:verify` 통과. iOS 파일 전달 브리지는 `찬양팀 콘티 (YYYY-MM-DD) vN.pdf` 이름을 명시적으로 허용한다. Windows 환경이므로 Xcode 서명 빌드와 실제 iPhone 파일 공유는 아직 실행하지 않았다.

## 출시 전 순서 / 남겨 둔 범위

1. 사용자가 출시를 별도로 요청하면 V020 이후 V021을 백업·검증 절차에 따라 운영에 적용한다.
2. iOS 실기기에서 PDF 페이지 보기와 파일 공유를 확인하고 새 네이티브 빌드를 준비한다. 기존 설치본에 웹 코드만 전달하면 새 파일명 허용 코드가 포함되지 않는다.
3. 실제 조직도의 찬양팀장과 학기 명단·일정을 지정한다. 가상 계정·자료는 제품에 포함하지 않는다.

학생 본인 기능, 모집/재결단의 구체적 제출 양식, 훈련 항목·수료 판단, 1월·8월 운영, 자동 알림·출석 통계는 아직 확정되지 않은 별도 범위다. 학기 운영 화면은 확정된 2월/9월 훈련과 3–7월/10–12월 활동 흐름을 표시한다.

로컬 기능 미리보기: `http://127.0.0.1:5200/.verification/praise-live-app.html?role=CHAIR` (교사: `role=TEACHER`). 가상 자료 전용 서버 8093/H2 메모리 DB이며 운영 환경과 분리된다. 브라우저 새로고침 시에는 저장이 유지되지만 검증 서버를 다시 실행하면 가상 자료가 초기화된다. 기존 시안 5199는 그대로 보존했다.
