# TTS 체크 안정화·상세 통계 개선

## 요청과 참고 화면

- 체크할 때 페이지가 새로고침되는 듯한 현상을 수정하고 TTS 통계를 세분화한다.
- 사용자가 제공한 [찬양팀 영성체크](https://script.google.com/macros/s/AKfycbw_fOxdhvIRjW_w4PDwYAkmbrLYGTTrTI6Zg0IzdlzIstwZLkfmBZ2x5cov3RLV5zkV/exec)를 브라우저에서 읽기 전용으로 확인했다.
- 참고한 구조: 요약 수치, 소속 필터, 점수·이름 정렬, 이름 클릭 시 요일별 말씀·기도와 예배·모임 내역 펼침, 1분 주기 통계 갱신. 참고 사이트의 체크 기록은 변경하지 않았다.

## 원인과 저장 동작 수정

기존 `queryReadState`는 배경 조회 중인 상태도 로딩으로 취급했다. TTS는 체크 저장 후 주간 자료를 다시 조회하면서 점수 카드와 체크 목록 전체를 없앴다가 다시 생성했다. 문서 자체의 새로고침이 아니어도 화면 높이가 바뀌고 스크롤·등장 애니메이션이 초기화됐다.

- TTS에만 캐시 표시 정책을 적용했다. 유효한 현재 주 자료가 있으면 배경 조회 중에도 화면을 유지한다. 최초 조회·다른 주의 대체 자료는 입력 화면으로 쓰지 않는다. 조회 실패·연결 끊김에는 기존 화면을 보존하면서 입력을 잠근다. 다른 입력 화면의 엄격한 공통 조회 규칙은 유지한다.
- 저장 성공 응답에 들어 있는 확정 주간 자료를 사용하므로 매 체크마다 추가 조회하지 않는다.
- 순차 저장은 유지하고, 확정 자료와 대기 중인 개별 체크를 분리했다. 앞선 응답이 나중에 누른 체크를 덮어쓰거나 실패한 요일이 다음 저장에 섞이지 않도록 한다.
- 저장 실패는 해당 변경을 복구하고 화면에 안내한다. 마지막 저장이 불확실하게 실패하면 배경에서 다시 대조한다. 인터넷 연결 대기와 실제 저장 완료를 구분한다.
- 홈의 TTS 점수 요약도 배경 조회 중 그대로 유지한다. 체크 저장 도중 홈으로 이동해도 대기 중인 값을 조회 결과로 덮어쓰지 않는다.

## 통계

- `TTS → 통계 · 상세`: 주간 상세 / 분기 순위 / 내 추이.
- 주간 상세: 현재·지난 주 선택, 평균·점수 있는 인원·최고점, 이름 검색, 소속 필터, 점수순·이름순, 동점 공동 순위.
- 이름을 펼치면 말씀·기도 월~토 체크, 항목별 획득점/배점, 예배·모임 여부, 자동 반영 구분, 직접 체크 수정 시각을 확인한다.
- 분기 순위의 개인별 주간 점수 및 주차별 요약, 내 추이에서 해당 주의 개인 상세로 이동한다.
- 2026년 4분기부터 관리하며 연도·분기를 넘나들어도 점수를 합치지 않는다. 아직 시작하지 않은 분기에는 미래 기록을 요청하지 않는다.
- 평균은 **저장된 0점을 포함**하고 미기록은 제외한다. 참여 인원은 종전 기준대로 양수 점수가 있는 사람이다. 평균·인원은 현재 검색/소속 필터 기준, 순위 번호는 전체 명단 기준이다.
- 앱에서 모두 체크 해제한 주도 저장된 0점으로 보존한다. 점수 합계와 양수 참여 주 수는 달라지지 않는다.
- 40·41주차 시트 확정 기록은 총점만 표시한다. 빈칸과 0점을 구분하고 요일별 답변·과거 배점을 만들어 넣지 않는다.

## 서버와 데이터 보호

- 로그인된 사용자의 기존 TTS 통계 접근 범위 안에서 `GET /api/tts/stats/week?year=…&weekNum=…` 읽기 전용 경로를 추가했다.
- 해당 주의 배점 이력을 적용하고 직접 체크와 자동 연동을 함께 계산한다. 주간 세부 점수 합계와 기존 통계 점수가 같아야 한다.
- 응답 전용 자료 구조로 이름·소속·점수·체크 내역만 제공한다. 계정 이메일·비밀번호·연락처·User 객체를 직렬화하지 않는다.
- DB 구조 변경·자료 이관·운영 체크 변경은 없다. 운영에서는 표시·조회만 검사한다.

## 검증

- 프런트 자동 검사 36개 통과: 배경 조회 표시, 연속 저장 순서, 중간 실패 시 다른 체크 보존, 실패한 요일의 후속 요청 혼입 방지, 마지막 실패 복구, 빈칸/0점, 공동 순위, 필터, 미래/53주차 경계 등을 포함한다.
- 프런트 운영 빌드 성공. 결과는 `.verification/build`에만 출력한다.
- 서버 전체 빌드와 가상 데이터 검사 35개 통과: 직접·연동 내역 합계, 과거 배점 유지, 0점/미기록, 시트 우선/빈칸, 범위 검사, 비로그인 접근 차단. PostgreSQL 전환 전용 1개 검사는 일반 test 프로필에서 제외된다.
- 실제 컴포넌트를 사용하는 별도 가상 브라우저에서 375px 폭 검수. 모든 요청은 가상 어댑터로 처리하며 운영 API로 저장하지 않는다.
- 느린 저장 중/완료 후 버튼 위치와 문서 높이가 동일하고 로딩 화면으로 바뀌지 않음을 확인했다. 저장 실패 시 20점 미리 표시 → 15점 확정값 복구와 해당 체크 해제를 확인했다.
- 상세 펼침이 통계 새로고침 후 유지됨, 소속/이름 필터, 시트 주차, 분기→개인 상세 이동, 내 추이, 2027년 미래 분기 안내를 확인했다. 가로 넘침과 브라우저 콘솔 오류 없음.
- 로컬 검수 이미지: `frontend/.verification/tts-stats-overview.jpg`, `tts-stats-detail.jpg` (가상 자료).

## 배포

사용자가 앞서 승인한 main 직접 반영 → 자동 배포 → 운영 읽기 전용 점검 순서를 따른다. 배포된 커밋과 운영 점검 결과는 같은 날의 로컬 배포 기록 `docs/design-deployment-2026-10-12.md`에 추가한다.
