# iOS 업데이트 점검 · 2026-10-30

현재 누적 수정본은 UI만 바뀌는 업데이트가 아니다. V015~V017 스키마와 새 서버 API가 필요한 기능 업데이트다. 10월 28일의 프런트엔드 단독 업데이트 계획 대신 이 문서를 따른다.

사용자는 로컬 점검 후 문제가 없으면 App Store 심사 요청까지 진행하도록 승인했다. 운영 서버·DB에는 아직 이번 변경을 적용하지 않았고, App Store 제출도 아직 하지 않았다. 이 문서의 로컬 통과 결과를 서명된 iPhone 앱 검증이나 운영 데이터 전환 완료로 해석하지 않는다.

### 제출 경로 확인 결과

- App Store Connect의 기존 앱은 **1.0.1 / 배포 준비됨**으로 표시됐다. 다음 후보는 1.0.2로 준비하되, 빌드 번호는 TestFlight 최신 목록 확인 후 정한다.
- 새 Apple Developer Program License Agreement 동의가 필요하다는 실제 계정 안내를 확인했다. 계약 검토 화면을 열어두었으며 사용자가 직접 검토·동의하도록 요청했다. 동의나 App Store 버전 생성은 실행하지 않았다.
- GitHub iOS 후보 브랜치 `codex/ios-first-update`의 웹 자동 배포는 비활성이다. 기존 원격 커밋은 현재 로컬 변경의 조상이므로 강제 푸시는 필요하지 않다.
- 원격 코드 업로드는 자동 승인 검토에서 별도 명시적 승인이 필요하다는 이유로 차단됐다. 사용자에게 해당 브랜치 업로드 승인과 기존 배포 금지 범위 중 서버·DB 반영 여부를 질문했다. 로컬 후보 커밋 `5d1bb4a`는 생성했지만 원격 푸시·신규 CI 실행·서명·업로드·심사 요청은 하지 않았다.
- GitHub `ios-testflight` 보호 환경은 현재 main만 허용한다. 후보 브랜치의 서명은 환경 보호 정책 확인과 정식 승인을 거쳐야 하며 검사를 우회하지 않는다.

## 이번 점검에서 보완한 결함

1. iOS의 보고서 다운로드가 웹용 Blob 링크만 사용했다. 인증된 다운로드 후 파일 데이터만 네이티브 저장 창으로 전달하도록 `NewaveReportExport`를 추가했다. HWPX/PDF와 파일명·용량·파일 헤더를 제한하고, 취소와 저장 완료를 구분한다. 임시 파일은 저장·취소 후 정리한다. iPhone에서 실제 파일 앱 저장은 다음 네이티브 검증 단계에서 확인한다.
2. 새 상세창의 `dialog`, `Array.at`, `crypto.randomUUID`와 iOS 15.0 설치 조건이 맞지 않았다. 최소 iOS를 **15.4**로 맞추고 웹 빌드 및 최종 앱 검사에 반영했다. iOS 15.0~15.3 사용자는 OS 업데이트가 필요하다. [WebKit 15.4 변경점](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/)
3. 새가족 테이블이 기존 계정 삭제 도구의 데이터 목록에 빠져 삭제가 중단되는 문제를 가상 PostgreSQL에서 재현했다. 목록과 공동 자료 검토 범위를 추가했다. 날짜가 기본 키인 팀 제출 표에는 기존 검토 도구의 행 식별을 위한 고유 ID를 추가했으며, 학생 출석과 과정은 보존하고 확인된 교사 정보만 교정하는 회귀 검사를 통과했다. V017은 미배포이므로 별도 운영 변경 없이 해당 예정 마이그레이션에 포함했다.
4. V015~V017의 PostgreSQL 검사가 자동 CI에서 빠져 있었다. PostgreSQL 17·18 검사에 새 보고서·프로필·새가족 전환 단계를 추가했다.

## 로컬 검증 결과

- 프런트엔드: **218/218 통과**.
- 서버 전체: **194 통과, 11 건너뜀, 실패 0**. PostgreSQL 18 가상 DB의 V015/V016, V017, 계정 삭제 검사를 이번 실행에 포함했다. 나머지 11개 과거 전환 검사는 별도 환경 변수가 필요한 검사이며 이번 로컬 실행에서는 미실행이다.
- 서버 일반/가상 환경 JAR 생성 완료. 가상 환경 JAR의 실제 명단·개인 키 제외 검사 통과.
- iOS 릴리스 도구: **77/77 통과**. 이 수치는 Python 도구의 단위 검사이며 Xcode·실기기 검사 수치가 아니다.
- 백업·삭제 도구: 7 통과, PostgreSQL 모듈 환경을 요구하는 기존 별도 검사 1개 건너뜀. 실제 삭제 SQL 회귀는 위 Java/PostgreSQL 검사에서 통과했다.
- `npm run ios:sync`, `npm run ios:verify` 성공. 현재 원본을 iOS 프로젝트의 로컬 웹 리소스에 반영했다. 기존 주 번들 500kB 초과 경고는 남아 있다.
- 375px 브라우저에서 두 보고서 다운로드, 화면 가로 넘침 없음, 콘솔 오류 0건 확인. 다운로드 파일은 가상 원본과 SHA-256이 같고 HWPX ZIP 구조와 PDF 헤더가 정상이다. 브라우저 검증을 실제 iOS 검증으로 대체하지 않는다.
- 원본 한글 양식과 실제 한글 출력의 이전 대조 결과는 `weekly-report-implementation-2026-10-29.md`에 있다.

## 출시 전 순서

1. 이 변경 전체가 들어간 정확한 커밋으로 GitHub 회귀 검사와 Xcode 네이티브 검사를 통과한다. 네이티브 Swift 파일의 실제 컴파일과 저장 창 표시는 Windows에서 확인하지 못했다. 보호 환경과 릴리스 검사를 우회하지 않는다.
2. 운영의 적용된 DB 버전과 서버 버전을 확인한다. 최신 암호화 백업의 분리 복원 검증 후 **V015 → V016 → V017 → 대응 서버** 순으로 반영한다. `ddl-auto=validate`를 유지한다. 운영 반영 범위는 사용자와 확정한다.
3. 가상 심사용 서버도 동일한 API와 스키마로 갱신한다. 심사자가 역할별 새 기능을 실제로 볼 수 있어야 한다. 본문·첨부에는 실제 학생 자료를 쓰지 않는다.
4. App Store Connect의 기존 버전·처리 중 빌드를 확인해 미사용 빌드 번호를 선택한다. 기존 1.0.1 후보 이력이 있으므로 프로젝트 기본 번호만 보고 업로드하지 않는다. 앱 ID·이름·Apple 로그인 구성은 유지한다.
5. 서명·검증·업로드 후 Apple 처리 결과를 확인한다. 현재 제출 SDK 기준은 Xcode 26 이상/iOS 26 SDK 이상이다. [Apple 제출 기준](https://developer.apple.com/news/upcoming-requirements/?id=04282026a)
6. iPhone 설치/업데이트, 로그인·재로그인, 권한별 메뉴, 교사 제출→팀 집계→반 배정, 보고서 HWPX/PDF 파일 앱 저장·열기·취소·재시도, 큰 글씨·키보드·오프라인 복귀를 확인한다.
7. 새 빌드와 최신 변경 설명을 연결해 App Store 심사를 요청한다. 심사 요청과 공개 출시는 구분한다. 공개 방식은 기존 수동 공개 설정을 유지한다.

새가족 생성 후에는 반 미배정 학생을 처리하지 못하는 구 서버로 단순 롤백하지 않는다. 스키마와 기록을 삭제하거나 예전 백업으로 최신 데이터를 덮어쓰지 않고, V017 호환 버전으로 복구한다.

## App Store 변경 내용 초안

- 교사 출석과 주간보고서 작성 흐름을 개선했습니다.
- 제출 자료 자동 집계와 한글·PDF 보고서 저장을 지원합니다.
- 새가족 등록부터 과정 관리, 등반과 반 배정까지 연결했습니다.
- 기도모임·교사회의 통계와 관리자 화면을 보기 쉽게 정리했습니다.
- TTS 항목 선택과 전도 조 편성·일정 등록을 개선했습니다.

심사 메모에는 로그인 화면의 가상 자료 환경, 교사·관리자·새가족팀 접근 방법, 보고서의 개인정보 없는 가상 자료 사용, 파일 저장 창 진입 경로를 설명한다. 기존 심사 계정 정보는 공개 저장소에 넣지 않는다.
