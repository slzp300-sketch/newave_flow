# iOS 업데이트 점검 · 2026-10-30

현재 누적 수정본은 UI만 바뀌는 업데이트가 아니다. V017~V019 스키마와 새 서버 API가 필요한 기능 업데이트다. 10월 28일의 프런트엔드 단독 업데이트 계획 대신 이 문서를 따른다.

사용자는 점검 후 운영 서버·DB 및 가상 심사 서버 업데이트와 App Store 심사 요청까지 승인했다. 검증된 `ff3b0474aecdd67be9aee5d98937ec6b8e43ab65`의 운영 서버·DB 전환과 **App Store 1.0.2 (빌드 9) 심사 제출을 완료했다.** 2026-10-30 22:26 KST에 Apple의 '1개의 항목 제출됨'과 **심사 대기 중** 상태를 확인했다. main과 공개 웹앱은 변경하지 않았고 App Store 수동 출시 설정을 유지했다. 공개 출시는 실행하지 않았다.

- TestFlight 최신 빌드 8을 재확인한 뒤 같은 `ff3b047`로 1.0.2 / 빌드 9의 [서명·업로드 실행 41061579242](https://github.com/slzp300-sketch/newave_flow/actions/runs/41061579242)가 성공했다. `apple_login=true`, `push_notifications=false`이며 임시 키·프로파일·IPA 정리도 성공했다. IPA SHA-256은 `da6a9306e66e7c0d12555b163cba18fc08ed6ef3bac73af499c2a070f5311adc`이다.
- Apple 처리 완료와 TestFlight '제출 준비 완료'를 확인한 빌드 `bb842bdb-35da-4162-a9c0-6554469eb74a`를 1.0.2에 연결했다. 제출 초안의 단일 항목 **1.0.2 (9)**를 확인한 뒤 최종 제출했고 [App Store Connect](https://appstoreconnect.apple.com/apps/6823391707/distribution/ios/version/inflight)의 **심사 대기 중** 상태까지 확인했다.
- 공개 출시는 수동이다. Apple의 심사 결과는 아직 나오지 않았으며 승인·공개 완료로 표현하지 않는다. 별도의 반복 확인 자동화는 만들지 않았다.
- 제출 증거는 `app-store-1.0.2-review-submitted.png`, 비밀값 없는 서명 영수증과 제출 기록은 로컬 `frontend/.verification/ios-1.0.2-build9/`에 보관했다.

- 심사용 Docker 배포에 보고서 양식·글꼴을 명시적으로 포함하고 패키지 검사에 필수 리소스 검증을 추가했다.
- 가상 심사 서버 배포 `00cb50d8-4d57-401c-9085-b342a75fbfed`는 SUCCESS이다. 기존 H2의 반 필수 제약을 review 프로필에서만 갱신하고 기존 행·외래키 보존 검사를 추가했다. 가상 첫 방문·재방문·과정·팀 판단·등반·10월 30일 반 배정, 교사 명단 반영, 10월 25일 중복 없는 집계와 HWPX/PDF 출력을 실제 가상 서버 API로 확인했다.

## 이번 점검에서 보완한 결함

1. iOS의 보고서 다운로드가 웹용 Blob 링크만 사용했다. 인증된 다운로드 후 파일 데이터만 네이티브 저장 창으로 전달하도록 `NewaveReportExport`를 추가했다. HWPX/PDF와 파일명·용량·파일 헤더를 제한하고, 취소와 저장 완료를 구분한다. 임시 파일은 저장·취소 후 정리한다. 시뮬레이터의 저장 창·취소·재시도 검사는 통과했으며 실제 iPhone 파일 앱 저장·열기 확인은 별도이다.
2. 새 상세창의 `dialog`, `Array.at`, `crypto.randomUUID`와 iOS 15.0 설치 조건이 맞지 않았다. 최소 iOS를 **15.4**로 맞추고 웹 빌드 및 최종 앱 검사에 반영했다. iOS 15.0~15.3 사용자는 OS 업데이트가 필요하다. [WebKit 15.4 변경점](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/)
3. 새가족 테이블이 기존 계정 삭제 도구의 데이터 목록에 빠져 삭제가 중단되는 문제를 가상 PostgreSQL에서 재현했다. 목록과 공동 자료 검토 범위를 추가했다. 날짜가 기본 키인 팀 제출 표에는 기존 검토 도구의 행 식별을 위한 고유 ID를 추가했으며, 학생 출석과 과정은 보존하고 확인된 교사 정보만 교정하는 회귀 검사를 통과했다. 이 보완은 운영 반영 전에 새가족 마이그레이션 V019에 포함했다.
4. V017~V019의 PostgreSQL 검사가 자동 CI에서 빠져 있었다. PostgreSQL 17·18 검사에 새 보고서·프로필·새가족 전환 단계를 추가했다.

## 전환 순서와 검증 범위

1. 정확한 후보 커밋으로 GitHub 회귀 검사와 Xcode 네이티브 검사 통과를 확인했다. Swift 컴파일과 PDF/HWPX 저장 창 표시·취소·재시도는 Mac의 iPhone 시뮬레이터에서 통과했다. 보호 환경과 릴리스 검사를 우회하지 않는다.
2. 최신 암호화 백업의 분리 복원 검증 후 **기존 V015·V016 확인 → V017 → V018 → V019 → 대응 서버** 순으로 운영에 반영했다. `ddl-auto=validate`를 유지했고 전환 후 백업 복원도 통과했다.
3. 가상 심사용 서버도 갱신하고 역할별 API 흐름과 실제 HWPX/PDF 출력을 확인했다. 본문·첨부에는 실제 학생 자료를 쓰지 않는다.
4. App Store Connect의 기존 버전·처리 중 빌드를 확인해 미사용 빌드 번호를 선택한다. 기존 1.0.1 후보 이력이 있으므로 프로젝트 기본 번호만 보고 업로드하지 않는다. 앱 ID·이름·Apple 로그인 구성은 유지한다.
5. 서명·검증·업로드 후 Apple 처리 결과를 확인한다. 현재 제출 SDK 기준은 Xcode 26 이상/iOS 26 SDK 이상이다. [Apple 제출 기준](https://developer.apple.com/news/upcoming-requirements/?id=04282026a)
6. 실제 iPhone의 서명 빌드 설치/업데이트와 파일 앱 저장·열기는 아직 확인하지 않았다. 서버의 교사 제출→팀 집계→반 배정·출력, 모바일 브라우저 화면, 네이티브 저장 창과 세션 검사의 통과를 실기기 검수 완료로 표현하지 않는다.
7. 새 빌드와 최신 변경 설명을 연결해 App Store 심사를 요청했고 접수를 확인했다. 공개 방식은 기존 수동 공개 설정을 유지했다.

새가족 생성 후에는 반 미배정 학생을 처리하지 못하는 구 서버로 단순 롤백하지 않는다. 스키마와 기록을 삭제하거나 예전 백업으로 최신 데이터를 덮어쓰지 않고, V019 호환 버전으로 복구한다.

## App Store 변경 내용 초안

- 교사 출석과 주간보고서 작성 흐름을 개선했습니다.
- 제출 자료 자동 집계와 한글·PDF 보고서 저장을 지원합니다.
- 새가족 등록부터 과정 관리, 등반과 반 배정까지 연결했습니다.
- 기도모임·교사회의 통계와 관리자 화면을 보기 쉽게 정리했습니다.
- TTS 항목 선택과 전도 조 편성·일정 등록을 개선했습니다.

심사 메모에는 로그인 화면의 가상 자료 환경, 교사·관리자·새가족팀 접근 방법, 보고서의 개인정보 없는 가상 자료 사용, 파일 저장 창 진입 경로를 설명한다. 기존 심사 계정 정보는 공개 저장소에 넣지 않는다.
